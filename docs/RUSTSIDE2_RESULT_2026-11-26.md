# RUSTSIDE2 결과 — 창 간 파일 전달, 종료·설치 안전 (2026-11-26)

브랜치 `feature/RUSTSIDE2` (`feature/RUSTSIDE1` fast-forward 병합 후 작업). 커밋만 했고 푸시하지 않았다. 설치본의 기본 실행 방식은 바꾸지 않았다.

## 기존 앱에서 달라지는 것 (먼저 확인)

| 달라진 동작 | 이유 |
|---|---|
| 저장 안 한 PDF 편집, 다이어그램·마인드맵·붙임사진 편집, 가상 폴더 메모 초안이 있으면 **보통 앱도** 닫을 때 묻는다 | 닫기 보호. 전에는 묻지 않고 닫혔다 |
| 변환 창(`convert_win`)은 변환 중에 닫으면 "중단하고 닫을까요?"를 묻는다 | 전에는 묻지 않고 중단했다 |
| 변환 창이 끌어 놓은·넘겨받은 파일 이름을 목록에 보인다. 처음 뜰 때 명령줄의 파일도 받는다 | 기존 결함(개수만 늘고 이름이 안 보임, 첫 실행은 인자를 버림) |
| 설치·업데이트·제거가 먼저 열린 창에 닫기를 요청하고, 남으면 멈추거나 묻는다 | 강제 종료로 편집을 잃지 않게 |

## 한 일

### 1. 창끼리 파일 넘기기
- 문서뷰·사진뷰(Rust 창) 오른쪽 클릭(메뉴 키·Shift+F10 포함)에 보내기 메뉴를 만들었다. 문서뷰 5곳(문서편집·PDF 편집·파일 변환·가상 폴더·업무자료함), 사진뷰 2곳(파일 변환·가상 폴더, CTXMENU1 표와 같음). 못 보내는 항목은 흐리게 두고 이유를 적는다.
- 전용 앱 화면 창(`--screen`)의 기존 연결 메뉴는 "막고 안내" 대신 그 창으로 보낸다.
- 보내는 곳은 `sidebar.exe --send` 하나다. 대상 창이 있으면 앞으로, 없으면 연다. 파일 변환은 Rust 변환 창이 있으면 그 창에 준다.
- 통로: `%LOCALAPPDATA%\HWP_AutoDocFit\open_requests\screen-N\` 수신함. **인증은 Windows 계정 권한**이다(상속을 끊고 현재 사용자·SYSTEM 만 접근, 시험이 `icacls` 로 확인). 같은 계정의 다른 프로그램은 요청을 넣을 수 있다. 받는 창은 파일을 목록에 더하기만 하고 작업을 시작하지 않는다.
- 검사: 형식·개수는 CTXMENU1 표(Dart·Rust·Python 세 표를 시험이 대조). 절대 경로의 일반 파일만. 받는 쪽이 다시 검사한다.
- 요청 상태: 대기 → 가져감(한 번만) → 삭제. 10분 지난 것은 버린다. 받는 창이 작업 중·닫는 중이면 가져가지 않는다.

### 2. 닫기 보호와 전체 종료
- 사이드바 머리줄의 전원 단추(와 오른쪽 클릭 메뉴) '전체 종료'. 창마다 닫기를 **한 번** 보내 각 창의 저장 확인을 거친다. 모두 닫히면 사이드바도 끝난다. 2분 안에 안 닫히거나 메뉴를 누르면 평소로 돌아간다. 몽땅검색(상주 단축키 앱)은 닫지 않는다.
- 상태: 평소 → 닫는 중(머리글 "닫는 중…", 상태 파일 `quitting`) → 종료 | 취소.

### 3. 설치·업데이트·제거
- `installer/close_windows.iss` → `sidebar.exe --close-all --install-dir <설치 폴더>`. 설치 폴더 아래 프로그램의 창만 닫고, 창 없이 작업 중인 앱 프로세스는 끝날 때까지 기다린다. 강제 종료하지 않는다.
- 도우미는 설치 파일에 담아 임시 폴더에서 실행하므로 이전 버전에서 올라올 때도 쓴다.
- 대화 설치: 20초 뒤에도 남으면 [다시 확인]/[강제로 닫고 계속]/[취소]. 조용한 설치(앱의 자동 업데이트): 300초 기다린 뒤 **설치를 중단**하고 안내한다.
- 도우미를 실행하지 못하면 기록만 하고 예전 방식으로 진행한다.
- 기존의 색인 서비스 잠금 파일 이름 바꾸기, 창 없는 도우미 `taskkill` 은 그대로다.

### 4. 로그온 때 사이드바 시작 (기본 꺼짐)
- 사이드바 오른쪽 클릭 메뉴에서만 켠다. `HKCU\...\Run` 값 하나가 상태의 원본이고 제거 때 지운다. `sidebar.exe --autostart on|off|status`.

### 5. 상주 작업의 주인
`docfit_app/resident.py`. 보통 앱과 `HWP_AutoDocFit.exe --resident` 가 같은 함수를 쓴다. 사이드바가 설치본에서 `--resident` 를 띄우고, 사이드바가 끝나면 함께 끝난다.

| 작업 | 사이드바만 쓸 때 |
|---|---|
| 몽땅클립보드 앱 파이프 | `--resident` ('붙임사진 편집 열기'는 5번 창으로 전달) |
| kagent·kvf·ktm 갱신, 우클릭 메뉴 갱신 | `--resident` (보통 앱이 떠 있으면 건너뜀) |
| 업데이트 확인 | `--resident` 가 `update_notice.json` 을 쓰고 사이드바에 '새 버전' 단추. 누르면 보통 앱이 떠서 묻고 설치 |
| 변환 파이프 | 맡지 않음(`mdm-ctx` 가 파이프가 없으면 앱을 직접 실행) |
| 검색 색인 사전 준비, 하단 Dock | 맡지 않음 |

## 작업 중 찾아 고친 결함
- **보내기가 받는 창이 닫힐 때까지 멈춤**: 띄운 창이 부른 쪽의 출력 파이프를 물려받았다. 실제 창 확인에서 발견. 시험 추가.
- **RUSTSIDE1**: 전용 창이 `MaterialApp` 에 `home` 과 `onGenerateInitialRoutes` 를 함께 줘 디버그 단언에 걸렸다(배포 빌드는 단언이 꺼져 있어 드러나지 않음).
- 가상 폴더·업무자료함 전용 창은 열린 뒤에 온 파일을 못 받는 구조였다(처음 만들 때만 가져감).
- 변환 창의 두 결함(위 표).

## 앱 화면 창을 미리 띄워 두는 비용

실제 창, 프로세스 트리 합계, 각 1회. 작업 집합은 공유 쪽이 겹쳐 세어진다.

| 대상 | 프로세스 | 작업 집합 | 전용 메모리 |
|---|---|---|---|
| 앱 화면 창: PDF 편집 | 8 | 656MB | 410MB |
| 같은 창을 최소화하고 30초 | 8 | 670MB | 412MB |
| 앱 화면 창: 문서편집 | 7 | 643MB | 397MB |
| 사이드바 | 1 | 19MB | 2MB |
| `--resident` (도우미 갱신은 빈 함수로 대신) | 1 | 30MB | 20MB |
| Rust 창: 문서뷰·사진뷰(합성 목록) | 2 | 30MB | 4MB |
| Rust 창: 설정 / 파일변환 | 1 | 15MB | 3MB / 2MB |

- 앱 화면 창 하나를 미리 띄워 두면 **전용 메모리 약 400MB** 가 늘고, 최소화해도 줄지 않는다.
- 지금은 창의 화면 번호를 시작할 때 정하므로 메뉴마다 따로 띄워야 한다(앱 화면 메뉴 8개면 3GB 이상으로 추정, 재지 않음).
- 권고: 미리 띄우지 않는다. 필요하면 "화면을 나중에 정하는 예비 창 1개"를 만들고 선택 설정으로 둔다. 근본 해결은 화면의 Rust 전환이다.
- 참고 시간(1회, 소스 실행, 다른 작업 부하 있음, 판정에 쓰지 말 것): 창 표시 2.6~3.1초, 화면이 수신함을 가져간 시각(내용 준비) 6.3~8.4초.

## 남은 문제·확인하지 않은 것
1. **실제 `setup.iss` 설치·업데이트·제거는 하지 않았다**(사용자 설치본을 덮고 도우미를 끝내므로). Restart Manager 와의 순서, 앱 자동 업데이트 전체 흐름, 설치본의 `--resident`(시작 그림 억제 포함)는 미확인.
2. 제거는 Inno 의 "제거할까요?" 확인보다 **앞에서** 창을 닫는다. 거기서 취소해도 창은 이미 닫혀 있다(각 창의 저장 확인은 거친다).
3. 앱 화면 창은 화면이 5초 안에 닫기 요청에 답하지 않으면 기존 규칙대로 강제 종료한다. 화면이 멈춘 상태에서는 저장 안 한 내용을 잃을 수 있다.
4. 닫기 보호를 넣지 않은 곳: 표그림판(자동 임시저장, 마지막 0.6초는 잃을 수 있음), Flutter 아웃라이너·설정 화면 등은 점검하지 않았다. 색인·일괄 이름 변경 같은 배경 작업은 묻지 않고 취소한다.
5. 받는 창이 10분 넘게 작업 중이면 보낸 요청은 **알림 없이** 버려진다.
6. Rust 문서뷰·사진뷰는 한 번에 1개만 보낸다(다중 선택 없음).
7. 보통 앱에서 연 Rust 문서뷰에서 보내면, 떠 있는 보통 앱이 아니라 전용 창이 새로 뜬다.
8. 사이드바를 닫으면 `--resident` 도 끝나, 열린 전용 창이 있어도 클립보드 파이프가 없어진다.
9. 화면에서 확인하지 않은 것: 사이드바 오른쪽 클릭 메뉴, '새 버전' 단추, 실제 로그온 시작, 변환 창·아웃라이너·설정의 닫기 확인 대화상자, 파일 변환 앱 화면(Rust 창이 없을 때)과 업무자료함으로의 실제 전달(위젯 시험·단위 시험까지), 다중 모니터·배율.
10. 작업 관리자에서 시작 프로그램을 꺼도 사이드바 메뉴의 체크는 켜진 것으로 보인다. 설정 화면에는 항목이 없다.
11. PDF 미리보기는 작업 폴더에 `pdf-edit` 를 빌드하지 않아 확인하지 않았다(파일이 올라오는 것까지).
12. 변환 창의 제목 표시줄이 비어 있다(기존 동작, 고치지 않음).
13. 한/글 COM 시험은 하지 않았다.
