## 7-다

커밋: `fe1c1291`.
`klib/src/search.rs`에서 같은 경로의 후보가 같은 문서 번호를 사용하도록 바꿨다.
최고 점수 후보를 대표 문단으로 유지해 이름·제목·대표 페이지·스니펫·강조를 제공하고,
선택된 문서의 모든 후보 페이지를 `hit_pages`에 담는다. 문서 집계 후 결과 limit을 적용한다.

호출부는 git grep으로 확인했다.

- `klib/src/pipe.rs`의 `search`: JSON 필드와 타입은 그대로다. 같은 파일의 여러 결과가
  한 행으로 합쳐지고 `hits`가 후보 문단 수, `pages`가 그 문단들의 페이지 목록이 된다.
  같은 페이지가 여러 번 들어가거나 페이지 미상의 null이 들어갈 수 있다.
- `item_search`: 집계된 파일마다 DB 항목을 찾아 첫 스니펫을 반환하므로 중복 항목이 사라진다.
- `docfit_app/library_bridge.py`: 명령 허용 및 응답 전달 구조를 유지할 수 있어 수정하지 않았다.
- `flutter_ui/lib/features/library/library_api.dart`: `LibrarySearchResult`는 경로·이름·스니펫을
  사용한다. 화면의 결과 이동도 경로를 사용하므로 스키마 변경이 필요하지 않다.

다중 문단 파일과 다른 파일을 함께 색인하여 중복 제거·언급 수·페이지 목록·스니펫·
대표 메타데이터·집계 후 limit을 검사하는 회귀 시험을 추가했다.

## 7-라

`hierarchy/src/search.rs`의 후보별 선형 탐색을 문서 ID → 결과 배열 위치 HashMap으로 바꿨다.
최초 등장 순서와 집계 계산은 유지한다. `aggregate`의 정렬 비교 구간은 바이트 비교로
기존과 같음을 확인했다. 실제 시작 코드의 정렬은 점수 → 위계 → 언급 수 → 최신 → 문서 ID이며,
요청문에 적힌 순서와 차이가 있지만 다른 브랜치의 작업을 존중해 변경하지 않았다.

저장소 전체 검색에서 실제 호출이 없는 `rank_documents`와 전용 `RankedDocument`를 제거했다.
삭제한 함수만 검사하던 시험도 함께 제거하고, 실제 `aggregate`의 비연속·희소 문서 ID,
최상위 usize ID, 언급 수, 위계·최신·최고 점수 병합, 빈 입력 및 limit 0 시험을 추가했다.
