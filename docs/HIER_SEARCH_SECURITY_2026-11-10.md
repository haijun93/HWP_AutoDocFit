# 위계검색 보안 점검 — HSA1

점검일: 2026-11-10. 대상: `docfit_core/hierarchy_nodes.py`, `docfit_core/hierarchy_search.py`, `tools/hier_search_eval.py`, 위계검색 회귀 fixture와 관련 단위시험. 저장소 전체의 보안 인증이나 외부 추출 엔진·설치본 감사가 아니다.

## 점검 결과

| 항목 | 확인 내용 | 판정·한계 |
|---|---|---|
| 외부 클라우드 검색 API 기본 경로 | 정규화·검색·평가 코드에 클라우드 클라이언트, HTTP 요청, API 키 읽기 없음. 검색은 전달된 메모리 인덱스만 사용 | 검토 대상 코드의 기본 경로에 없음. 시스템 전체 네트워크 차단 시험은 별도 |
| 개인정보 처리 | 본문·제목·경로·위치·일치어를 그대로 인덱스와 결과에 보존 | 개인정보 탐지·마스킹·암호화 기능 없음. 인덱스와 결과를 원문과 같은 민감도로 취급해야 함 |
| 원본 문서 보존 | 정규화는 입력을 깊은 복사하며, 검색·평가에서 원본 HWP/HWPX/PDF 등을 열거나 저장하지 않음 | 추출 데이터 계층에서 보존. 기존 등록·변환 코드의 원본 보존 전 구간을 이번 점검으로 보장하지 않음 |

| 잘못된 그래프 | 중복 ID, 존재하지 않는 부모, 순환 참조를 `ValueError`로 거부. 검색 문맥 확장도 순환·누락 부모 확인 | 무한 부모 순회 방지. 큰 입력의 크기·깊이·메모리 상한은 별도 미구현 |

| 결과 파일 보존 | 평가 CLI는 입력 코퍼스와 같은 경로 또는 `samefile()`인 결과 경로를 거부 | 다른 기존 결과 파일은 지정된 출력 경로에 덮어씀. 쓰기 중 중단에 대한 원자 저장·경로 교체 경쟁 방지는 미검증 |
| 로그·자격 증명 | 신규 코드가 자격 증명·환경변수 전체를 출력하지 않음. CLI 콘솔 출력은 결과 경로·건수·집계 지표 | 결과 경로 자체가 사용자명을 포함할 수 있음. 예외·호출자 로그의 민감 정보 취급은 호출 계층 책임 |

## 저장·공유·임시 파일 취급

- 인덱스에는 본문 토큰뿐 아니라 원문 텍스트, 상위 제목, 문서명, 위치가 있다. `build_index_from_content_db()` 결과의 `source.document_path`는 전체 경로를 포함할 수 있다. 결과를 외부 이슈·공개 저장소에 첨부할 때는 합성 자료 또는 별도 익명화 사본을 사용한다.
- 평가 JSON은 질의, 정답 ID, `expected_context`, 문서명을 기록한다. 자동 개인정보 삭제 기능은 없다. 문서 제목이나 질의에 개인정보가 있으면 보고서에도 남는다. 코퍼스 SHA-256은 재현성 식별자이며 익명화·암호화가 아니다.
- 기본 회귀군 `tests/fixtures/hier_search/regressions.json`은 공개 가능한 합성 추출 노드로 설명되어 있으며 개인 이름·연락처·자격 증명을 넣지 않았다. 실제 원본 문서는 fixture에 포함하지 않는다.
- 이번 작업의 임시 데이터·시험용 SQLite는 사용자 지정 `E:/docfit-tmp`를 사용한다. 메모리 검색 자체는 임시 파일을 만들지 않는다. 평가 보고서는 명시한 `--output`에 저장하므로 민감 문서로 실행할 때 출력 경로 접근 권한과 보존 기간을 별도로 관리해야 한다.
- 이 기능은 인덱스 암호화, 파일 ACL 설정, 보존 기간 자동 삭제, 다중 사용자 권한 분리를 제공하지 않는다. 문맥 확장은 본문보다 더 넓은 상위·하위 내용을 반환하므로, 향후 권한이 다른 문서를 합쳐 서비스할 경우 후보·문맥 양쪽에 접근 제어가 필요하다.

## 시험 근거와 범위

관련 시험: `tests/test_hierarchy_nodes.py`, `tests/test_hierarchy_search.py`, `tests/test_hier_search_eval.py`.

- 정규화 입력 불변성, 검색 결과를 바꿔도 인덱스가 바뀌지 않는지 확인한다.
- `builtins.open`과 `socket.socket`을 실패하도록 대체한 상태에서 검색을 수행한다. 이는 해당 단위 경로가 원본 파일·소켓을 사용하지 않음을 확인하며, 운영체제 수준 트래픽 캡처나 모든 파일 API 차단을 뜻하지 않는다.
- 존재하지 않는 원본 경로를 가진 작은 SQLite fixture에서 읽기 전용 어댑터로 색인하고, DB 파일 바이트가 실행 전후 동일한지 확인한다. 시험 DB는 실제 Rust 바이너리 실행 결과가 아닌 공용 컬럼을 흉내 낸 작은 테이블이다.
- 중복·순환·없는 부모를 거부하고, 미확인 표 식별자를 진단에 남기는지 확인한다.
- 평가 결과에 `unsupported`·`unverified`가 있고 잘못된 정답 주석을 조용히 제외하지 않는지 확인한다. 회귀 기준값은 완화하지 않는다.

위 시험의 실행 결과·건수는 HSA1 최종 보고서에 기록한다. 이 문서는 코드에서 확인한 보장과 시험의 의미를 기술하며, 아직 실행되지 않은 전체 검사나 실제 COM 검사를 통과했다고 주장하지 않는다.

## 미지원·미검증 항목

원본 HWP/HWPX/PDF/DOCX/XLSX 직접 파싱·OCR·변환은 새 평가 도구에서 지원하지 않는다. 기존 색인의 추출 문단과 확정 level·위치를 정규화하는 경계다. 위치가 없으면 페이지·표를 추정하지 않으며, 문장 경계는 구두점 기반 근사다. 실제 kordoc XML 변환, 한/글 COM, 이미지 PDF, 암호·DRM 문서, 대규모 악성 입력, 실제 Rust/Tantivy 통합 처리·native 메모리, 실행파일 배포본은 이 점검과 작은 fixture만으로 검증되지 않는다.

외부 클라우드 검색·모델 API는 기본 구현에 추가하지 않았다. 사례 조사를 위한 공식 공개 웹 열람은 사용자 문서 업로드가 아니다. 의미 검색은 비교 설계만 수행하며 신규 임베딩 모델·벡터 DB 등 무거운 의존성을 추가하지 않는다.
