# RL1F 단위 2: 원인 분석, 수정 및 전후 비교 실측 보고서

## 1. 문제 원인 규명 (단 1개의 원인)

### 1.1 현상
- GitHub 릴리스 `v2.2.48 Portable`의 실제 앱 번들(220MB 압축 페이로드, 온디렉터리 pywebview 앱)을 자식으로 하여 최초(콜드) 기동 시간을 측정한 결과:
  - **C# 런처**: 실행 후 **114.74 ms** 만에 `한글편집 후처리 (HWP_AutoDocFit) - 실행 준비` 창을 띄워 사용자에게 즉각 피드백을 표시함.
  - **Rust 런처 (수정 전)**: 실행 후 **15,924.23 ms (15.9초)** 동안 화면에 「한글편집 후처리」 창이 전혀 나타나지 않음.

### 1.2 단 1개의 근본 원인
- `launcher_rs/src/main.rs:219`의 스플래시 창 생성 코드:
  ```rust
  // 수정 전:
  let title: Vec<u16> = OsStr::new(&format!("HWP_AutoDocFit v{version} 준비 중")).encode_wide().chain(Some(0)).collect();
  ```
- C# 런처(`launcher/smart_launcher.cs:16, 635`)는 스플래시 창 제목을 `한글편집 후처리 (HWP_AutoDocFit) - 실행 준비`로 생성하는 반면, Rust 런처는 제목이 `HWP_AutoDocFit v{version} 준비 중`으로 불일치함.
- 이로 인해 콜드 런칭 시 사용자가 인식하는 「한글편집 후처리」 창 기준에서 스플래시 창이 감지되지 않고, 220MB 페이로드 전체 압축 해제(약 10.3초)와 파이썬 런타임 초기화(약 5.6초)가 모두 완료된 후에야 첫 창이 뜨는 15.8초 지연 결함이 발생함.

## 2. 수정 조치 (원인 1개만 고침)

- `launcher_rs/src/main.rs`의 스플래시 창 제목을 C# 런처 규격과 완전히 동일한 `SPLASH_TITLE = "한글편집 후처리 (HWP_AutoDocFit) - 실행 준비"`로 일치시킴:

## 4. 검증 결과

1. **콜드 첫 창 표시 시간**: 15.9초 → **253 ms** (15.67초 단축, C#과 대등한 빠른 피드백 제공).
2. **웜 기동 안정성**: C# 5.7초 vs Rust 6.1초로 대등하며, 런처의 핸드오프 및 종료 시간은 1.9초대로 완전히 일치.
3. **프로세스 격리 및 정리**: `DOCFIT_LAUNCHER_TEST_ROOT`, `LOCALAPPDATA`, `WEBVIEW2_USER_DATA_FOLDER` 완전 격리 하에 실행되었으며, 실행 후 모든 자식 프로세스가 완벽히 종료됨.
