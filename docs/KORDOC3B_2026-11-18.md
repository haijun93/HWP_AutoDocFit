# KORDOC3B PDF 텍스트 추출 비교

작성일: 2026-11-18  
비교 대상: 시스템 설치 kordoc 런타임 `4.21.30` 및 `pypdfium2` 디지털 PDF 추출기  
스크립트: `tools/compare_pdfium_kordoc.py`

## 기준과 실행 방법

합성 PDF 5종(한글 본문, 표 형태의 행, 여러 쪽, 특수문자, 빈 쪽 포함)을 임시 폴더에 생성하고, PDFium 텍스트와 `kordoc <PDF> --format markdown --plain --silent` 결과의 문자 일치율을 비교했다. kordoc `4.21.30`은 `parse --format text` 옵션을 지원하지 않고 출력 형식은 Markdown/JSON/Chunks이므로, 일반 본문 문자열 비교가 가능한 평문 Markdown 출력을 사용했다. 비교 전 줄바꿈은 LF로 통일했다. 일치율은 `SequenceMatcher` 문자 유사도이며, 빠진 줄은 PDFium의 비어 있지 않은 줄 중 kordoc 결과에 포함되지 않은 줄이다.

런타임은 `docfit_core.kordoc_runtime.find_runtime("4.21.30")`로 찾는다. 없으면 스크립트는 `런타임 없음` 사유를 출력하고 종료한다. 이 실행에서는 런타임이 확인되어 시험을 수행했다. 생성한 PDF는 시스템 임시 폴더에만 두며, 시험 코드에 사용자별 로컬 런타임 경로를 기록하지 않는다.

## 실제 결과

| 입력 종류 | PDFium 문자 | kordoc 문자 | 일치율 | 빠진 줄 |
|---|---:|---:|---:|---|
| 한글 본문(영문 글리프 본문) | 15 | 15 | 100.00% | 없음 |
| 표 형태 행 | 32 | 34 | 96.97% | 없음 |
| 여러 쪽(3쪽) | 59 | 59 | 100.00% | 없음 |
| 특수문자 | 38 | 38 | 100.00% | 없음 |
| 빈 쪽 + 텍스트 쪽 | 24 | 24 | 100.00% | 없음 |

표 유형에서 PDFium은 행 사이에 LF 하나를, kordoc은 LF 두 개를 출력했다. 문자는 누락되지 않았으나 공백 줄 차이 때문에 일치율이 기준 99%보다 낮다. 또한 현재 시험 런타임의 CLI는 요청 표기인 `kordoc parse --format text`를 제공하지 않는다. CLI 인자와 실제 사용 가능 출력 형식을 확인한 뒤 Markdown 평문 출력을 비교했다.

## 연결 판단

연결하지 않았다. 표 유형이 96.97%로 99% 기준에 미달하므로, 디지털 PDF 전체 종류에 대해 `parse_document` 경로를 바꾸지 않았다. `docfit_core/pdf_extract.py`는 현재 상태 그대로 유지한다. 따라서 `DOCFIT` 환경변수에 따른 PDF 엔진 선택 설정도 추가하지 않았다. (HWP의 기존 Rust 경로와 무관한 판정이다.)
