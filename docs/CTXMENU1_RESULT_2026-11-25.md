# CTXMENU1 — 사진뷰·문서뷰 오른쪽 클릭 메뉴와 앱 주요 기능 연결 (2026-11-25)

사용자 지시: "사진뷰, 문서뷰에서 파일을 선택하고, 마우스 오른쪽 메뉴로 삭제, 이동, 파일명변경 등 기본 기능이외에 앱의 주요기능으로 연결하는 기능 추가. … 사진뷰는 사진편집, 파일변환 등의 메뉴 선택 가능하도록 개선"

앞 카드 `feature/FILEOPS1`(95dcd58a, DBLOPEN1 포함)을 병합한 뒤 작업했다. 대상은 Flutter 두 화면이다.

## 대상 선택

- 선택 밖 항목을 오른쪽 클릭하면 그 항목만 선택하고, 선택 안이면 선택 전체가 대상이다.
- DBLOPEN1 의 "오른쪽 단추는 선택을 바꾸지 않는다" 시험(`dblclick_open_test.dart`)은 이 요구와 반대라 새 동작으로 고쳤다.
- 사진을 왼쪽 클릭한 직후 오른쪽 클릭하면 예약된 크게 보기는 버린다.

## 메뉴

| 메뉴 | 문서뷰 | 사진뷰 | 활성 조건(아니면 비활성 + 이유 표시) |
|---|---|---|---|
| 열기 | ○ | ○ | 1개 |
| 복사 · 폴더로 복사 · 이동 · 삭제 | ○ | ○ | 다른 파일 작업 중이 아님 |
| 파일명 변경 | ○ | ○ | 1개 |
| 문서편집 | ○ | — | hwp·hwpx·pdf·doc·docx·txt·md, 1000개까지 |
| 가상 폴더에 추가 | ○ | ○ | 모든 형식, 200개까지 |
| 업무자료함에 넣기 | ○ | 숨김 | hwpx·hwp·docx·pdf·xlsx·pptx·txt·md, 200개까지 |
| 파일 변환 | ○ | ○ | hwp·hwpx·pdf·docx·txt·md·png·jpg·jpeg·webp·bmp·tif·tiff·gif, 숨긴 메뉴가 아님 |
| PDF 편집 | ○ | — | pdf 만(100개까지), 숨긴 메뉴가 아님 |
| 사진 편집(사본) | — | ○ | 1장, 클라우드 전용이 아님 |
| 공문 첨부용 사본 저장 · 사진대지 만들기 | — | ○ | (기존 단추와 같은 동작) |

파일 작업은 FILEOPS1 의 확인창·휴지통·덮어쓰기 금지 규칙을 그대로 쓴다.

## 대상 기능의 진입 경로

| 대상 | 기존에 파일을 받던 경로 | 이번에 쓴 방법 |
|---|---|---|
| 문서편집(탭 0) | 파일 선택·끌어 놓기 → `add_paths` → 문서 목록 | 같은 `add_paths`. 목록에 들어갔는지 확인한 뒤 '문서 선택' 화면을 연다 |
| 파일 변환(탭 10) | 변환 화면 파일 선택·끌어 놓기 → `add_paths`(문서 목록과 공용) | 같은 `add_paths` 뒤 탭 이동(`enterConversionMode`) |
| PDF 편집(탭 11) | 파일 선택·끌어 놓기(`_addFile`, 합치기 목록) | **받는 기능 추가**(`PdfEditWorkspace.incoming`): 1개는 편집 대상, 여러 개는 합칠 목록 |
| 가상 폴더 | 화면에 끌어 놓기(`_takeDrops` → `item_add`) | **받는 기능 추가**(`LibraryScreen.incoming`): 넣을 폴더를 고르거나 새로 만든 뒤 같은 추가 코드 |
| 업무자료함 | 경로 입력·끌어 놓기(`_addPaths` → `nb_source_add`) | **받는 기능 추가**(`NotebookScreen.incoming`): 넣을 자료함을 고르거나 새로 만든 뒤 `_addPaths` |
| 사진 편집(사본) | 크게 보기 창의 '사본 편집' | 같은 편집 창을 메뉴에서 바로 연다 |
| 사본 저장·사진대지 | 선택 막대 단추 | 같은 함수 |

연결 통로는 `features/common/file_handoff.dart`(`FileHandoff`, `FileInbox`)이고 탭 이동은 `main.dart` 가 맡는다. 백엔드(Python·Rust)는 바꾸지 않았다.

## 원본 보호

- 문서편집·파일 변환은 목록에 더하기만 하고 작업은 사용자가 시작한다. 결과 저장 규칙은 기존 그대로다.
- PDF 편집은 새 결과 경로에만 저장한다(기존 규칙). 저장하지 않은 편집이 있으면 버릴지 먼저 묻는다.
- 가상 폴더·업무자료함은 기존 추가 명령을 그대로 쓴다.
- 사진 편집은 사본 저장만 한다.

## 알아 둘 제한

- **파일 변환이 '새 창(Win32)' 방식이면** 그 창에 파일을 넘길 수 없어, 넣지 않고 "앱 안에서 변환"으로 바꾸라는 안내를 낸다(메뉴는 활성).
- **xls·ppt·pptx·hml** 은 문서편집·파일 변환 메뉴가 비활성이다. 파일 변환 엔진 일부는 이 형식을 지원하지만, 파일 목록 추가 통로(`native_file_dialog_service.ADDABLE`)가 받지 않는다(기존 동작, 고치지 않음). 문서편집의 doc 은 목록에 들어가지만 파일 변환은 doc 입력을 지원하지 않는다.
- 파일 변환과 문서편집은 같은 파일 목록을 쓴다. 이미 있던 파일은 지우지 않으므로, 형식이 섞이면 변환 포맷이 꺼질 수 있다.
- `add_paths` 는 한 경로라도 거절되면(네트워크 경로·재분석 지점 등) 묶음 전체를 넣지 않는 것으로 코드상 보인다. 화면은 "넣지 못했습니다"를 보여 주고 이동하지 않는다.
- **붙임사진 편집 탭(그림판)** 으로 보내는 메뉴는 만들지 않았다. 이 탭은 끌어 놓기·클립보드로만 사진을 받고, 웹 전용 화면이라 위젯 시험으로 확인할 수 없다. '사진 편집'은 기존 사본 편집 창에 연결했다.
- 업무자료함은 그림 형식을 받지 않아 사진뷰에는 넣지 않았다.
- 몽땅검색·표템플릿 등 파일 목록을 받는 구조가 아닌 화면은 메뉴에 넣지 않았다.

## PM 추가 항목: 사진뷰 크게 보기 순번

`globalIndexCounter` 는 FILEOPS1 에서 이미 경로 기준(`_openViewerFor`)으로 고쳐져 코드에 남아 있지 않다. 그 카드에는 스크롤 시험이 없어 이번에 추가했다(`context_menu_test.dart` "스크롤·다시 그리기 뒤에도 누른 사진이 크게 열린다"). 옛 코드에서 이 시험이 실패하는지는 확인하지 않았다.

## 확인하지 못한 것

- 실제 앱(설치본·exe, WebView)에서의 오른쪽 클릭 메뉴. WebView·브라우저 기본 메뉴가 겹쳐 뜨지 않는지 포함.
- 실제 백엔드에서의 연결: `add_paths`, klib 의 `item_add`·`nb_source_add`, pdf-edit 쪽 읽기.
- 네이티브 Flutter 실행기(`application_service`)에서의 동작: `add_paths` 가 그림을 받지 않고 `notebook` 명령이 없는 것으로 코드상 보인다.
- 네트워크 드라이브·클라우드 전용 파일을 넘기는 경우.
- 네이티브 창(`docview_win`·`photoview_win`)에는 오른쪽 클릭 메뉴가 없다.
- 키보드(메뉴 키·Shift+F10)로는 메뉴를 열 수 없다.
