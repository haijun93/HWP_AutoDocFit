### 하네스가 잡은 차이 (숨기지 않음)
1. **연결 부호 탭 1쌍 실패(`k_entities_in_text`, 탭 위치 7030 대 7029).** 원인은 파이썬 3.12 이상 내장 `sum()` 이 부동소수 합에 Neumaier 보정 합산을 쓰는 점이다(`sum([0.1]*10) == 1.0`). Rust 는 단순 덧셈이라 글자 폭 합(`text_em`)이 1 ULP 달랐다. `style::PySum`/`py_sum`(CPython `sum()` 과 같은 단계: 정수 항목은 첫 실수 전까지 정수로, 이후 보정 합산)을 만들어 연결 부호 탭·표 칸 너비(비율 합·낱말 폭·표 앞 글 폭)·기본 표 서식(`_fits_one_line` 의 정수·실수 섞인 합) 모든 부동소수 합에 썼다. **같은 원인의 잠복 위험이 RSXML3 콜론 라벨 폭 합(`fmt3::sum_em`)에도 있었다**(길이 2~9 글자 무작위 20만 개 중 약 23%에서 단순 합과 `sum()` 이 다름). 같은 함수로 고쳤고 RSXML3 5종을 포함한 전체 하네스는 그대로 차이 0이다. 파이썬 3.11 이하에서는 이 보정이 없으므로 앱 파이썬은 3.14(HANDOVER 기준)여야 결과가 같다.
2. 그 밖의 실패는 없었다. 다만 첫 시험에서 한 번에 통과한 것을 믿지 않고 아래 두 가지로 하네스가 헛돌지 않는지 확인했다.

### 하네스가 진짜 차이를 가리지 않는지 확인
- **반올림 규칙을 일부러 망가뜨림**: 열 너비 `round`(짝수 쪽)를 `round`(반올림 위로)로 바꿨더니 처음 하네스 사례 225쌍에서는 **0건 실패** — 사례가 정확히 `x.5` 가 되는 열 너비를 만들지 못하고 있었다. 홀수 본문 폭에 글자 수가 같은 두 열·여섯 열 사례 10건(`w_tie_round_*`)을 추가하자 같은 망가뜨림이 4쌍 실패로 잡혔고, 복구 후 235쌍 모두 통과했다.
- **출력을 일부러 망가뜨림(`--sabotage`)**: 새 처리기마다 대표 문서 7쌍(표 칸 너비 2, 연결 부호 탭 2, 기본 표 서식 2, 정렬 재확인 1)에 16가지 변형. 글자·문단 모양 참조 번호, `itemCnt`, 새 정의 id, 글자 크기, 글 안 글자/공백, 이름공간 주소, run 삭제, **칸 너비·표 폭·탭 위치·칸 테두리 참조·테두리 정의·탭 요소 종류·머리글 새 글꼴 이름**이 모두 잡혔고(해당 변형이 적용되는 모든 경우), 의미가 같은 변형(속성 순서·접두사 이름 바꿈)만 같다고 보았다. `sabotage_bad 0`.

## 이식한 것(핵심 규칙)

코드: `tbl.rs`(676줄: 파이썬 숫자 해석·머리글 색인·본문 폭·표 칸 너비) · `conn.rs`(424줄) · `tstyle.rs`(897줄: 프로필·대상 판정·머리 표 판별·머리글 풀·적용) · `run4.rs`(243줄: 조사·처리 흐름) · `eaw.rs`(61줄: 동아시아 글자 폭 W·F·A 구간, 생성 파일). 기존 `rules.rs`·`run3b.rs` 에서 쓰던 표 판별·프로필 XML 조각 처리를 공유했다.

- **본문 폭·쪽 크기·여백**: 문서에서 처음 나오는 `pagePr` 의 (쪽 폭 − 왼쪽 − 오른쪽 여백), 가로 방향(`NARROWLY`)은 높이가 쪽 폭. 표 칸 너비는 쪽 정보가 없거나 폭이 0이면 그 구역의 표를 대상에서 뺀다. 연결 부호 탭은 쪽 정보가 없으면 42520, 칸 안 묶음은 `cellSz` 폭 − `cellMargin` 좌우(`cellMargin` 이 없으면 빼지 않음, 칸 안이 아닌 `subList` 나 `cellSz` 가 없으면 폭 0).
- **표 칸 너비**: 머리글 행(첫 행 rowSpan 으로 판별)을 뺀 본문 행마다 열별 글자 수 비율을 구해 평균, 병합 칸은 걸친 열에 똑같이 나눔. 열 최소 폭(가장 긴 낱말·글자 크기·장평·자간·굵기·칸 안 여백)을 지키고 합이 표 폭의 95%를 넘으면 큰 값부터 깎음. 빈 열은 원래 폭 비율을 지킴. **반올림은 파이썬 `round`(짝수 쪽), 합이 모자라거나 넘치는 만큼은 첫 번째 최댓값 열에 보정.** 단위 캡션 표는 비례 분배 대신 쪽 폭을 넘을 때만 열 경계를 한 번만 반올림해 줄임. 글자처럼 놓인 표 앞 글·문단 여백만큼 폭을 뺌.
- **기본 표 서식**: 대상 판정(2×2 이상 격자·사용자가 꾸민 표 제외·서식 표(제목·중제목·붙임·빈 정보 칸 제목) 제외·문서 머리 표/18pt 이상 큰 글자 표 제외 `head_block_tables`)과 적용(칸 위치별 테두리 조합·바탕 그림 보존·글자 모양 복제(글꼴 추가 포함)·배분 정렬 제한·한 줄 적합 판정(`east_asian_width` 로 W·F·A 는 한 글자 폭)·줄 간격·세로 정렬·표 테두리·안 여백)을 옮겼다. 정렬 재확인(13번)은 같은 처리기를 새 문서에서 다시 조사해 부른다(1차 선택 목록을 재사용하지 않음).
- **연결 부호 탭**: 정규식의 앞뒤 확인(lookbehind·lookahead)을 손으로 풀어 연결 부호(점·선·여러 칸 빈칸·전각 빈칸) 판별, 묶음(같은 종류 연속 2문단 이상, 표가 든 문단·다른 글이 끼면 끊김), 탭 위치(가장 긴 왼쪽 글 + 1.5글자, 본문 폭 초과 시 앞으로 당김), 새 탭 모양(`tabPr`: `hp:switch` 의 case/default 두 벌)·문단 모양 사본을 만든다.
- **서식 ID 규칙(RSXML3 과 같음)**: 새 charPr/paraPr/borderFill/font/tabPr 는 그룹 끝에 붙이고 `id = 그룹 안 숫자 id 최댓값 + 1`, `itemCnt`(글꼴은 `fontCnt`)는 자식 수. 원본 정의는 건드리지 않고 복제. 같은 (원본, 변경)은 사본 하나를 공유하며, **테두리는 이번 실행에서 만든 것끼리만 같은지 본다**(문서에 원래 있던 정의와는 비교하지 않음 — 파이썬과 같아서, 같은 문서에 기본 표 서식을 두 번 입히면 두 번째에도 테두리가 새로 생긴다). 같은 테두리인지는 꼬리 공백까지 포함한 구조 비교다.

## 설정 전달(추가 키)와 거부
`--config` JSON 에 추가: `table_style`(활성_표서식_프로필 — 파이썬 `learn_from_table`/`default_style()` 이 만든 사전; **앱은 `기본표서식()` 의 결과를 풀어서 넘긴다**), `connector_tab_enabled`(알파_연결부호_탭정렬_사용, 기본 true; 조사에서만 확인하고 선택 목록을 직접 주는 처리에서는 보지 않음 — 파이썬과 같음), `standard_margin_planned`(표준서식이 편집 여백을 바꿀 예정인지, 기본 false). 처리기 이름: `table_width`·`table_style`·`table_style_align`·`connector_tab`(파이썬 함수 이름 별칭 포함, 정렬 재확인은 `기본표서식_hwpx_처리` 와 같다). 조사 결과 JSON 은 모두 `{구역: [번호…]}`(표 칸 너비는 본문 직속 표의 순번, 기본 표 서식은 구역 안 모든 표의 순번, 연결 부호 탭은 묶음 수만큼의 번호).

거부(`미지원 입력:`, 종료 코드 4, 출력 없음): 알 수 없는 키, 형식 오류(`table_style` 이 객체 아님, 프로필의 정수·문자열 자리가 틀린 값, 불리언 아님), `title_owner_text` 가 있는 표 칸 너비·기본 표 서식(서식 표 판별에 반영 못 함), `standard_margin_planned: true` 인 연결 부호 탭, 처리 중 만난 프로필 XML 의 이름공간이 문서에 없을 때, 파이썬 `int()`/`float()` 해석이 갈릴 수 있는 속성 값(전각 숫자·밑줄·지수 표기·64비트 초과). 파이썬 `valid_style` 이 거짓인 프로필(버전 ≠ 1, 행·열 모양 불일치, 빈 사전)은 파이썬처럼 '프로필 없음'으로 보고 표를 바꾸지 않는다(복사).

## 남은 한계
- **표준서식이 편집 여백을 바꿀 예정인 경우의 본문 폭(`_최종_본문폭`)은 연결 부호 탭에서 지원하지 않는다**(`standard_margin_planned: true` 면 거부). 표 칸 너비는 쪽 정보의 본문 폭만 쓰므로 영향이 없다.
- **준말 '표' 등록표(`준말_등록표`)는 Rust 가 읽지 않는다.** 앱이 `기본표서식()` 을 풀어 `table_style` 로 넘겨야 한다. 그 연결 코드는 없다(앱 미연결).
- 시험은 합성·fixture·실제 머리 위 합성 문서 기반이며 실제 한/글 문서 코퍼스는 쓰지 않았다(사용자 문서 사용 금지). `tests/fixtures` 18건은 표가 거의 없어 새 처리기에 변경 사례가 되지 못했다.
- 동아시아 글자 폭 표(`eaw.rs`)는 파이썬 3.14 `unicodedata`(유니코드 16.0)에서 생성했다. 다른 파이썬 버전의 유니코드 표와는 다를 수 있다.
- 파이썬 `isdigit()` 가 참이지만 ASCII 가 아닌 id(위첨자 숫자 등)는 RSXML3 과 같이 다루지 않는다. 정규식 `\d`·`\w` 는 `\p{Nd}`·`\p{L}\p{Nl}\p{No}` 로 옮겼으며 결합 문자 같은 드문 글자의 분류가 다를 수 있다.
- 파이썬 `sum()` 보정은 3.12 이상 동작을 따른다. 파이썬 3.11 이하에서는 부동소수 합이 달라 결과가 갈릴 수 있다.
- 헤더 `fontface` 가 없거나 `fontRef` 가 없는 경우 등은 파이썬과 같이 처리하되(둘 다 거부 또는 둘 다 건너뜀) 하네스 사례 수가 적다.
- 속도 이득은 4.5~7.6배 규모(RSXML2 의 7~11배, RSXML3 의 3~5배 사이).
