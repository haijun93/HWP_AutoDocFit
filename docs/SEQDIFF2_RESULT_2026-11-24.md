# SEQDIFF2 결과 — 문서 간 한/글 재시작 비용과 안전장치

작성일: 2026-11-24

- 브랜치 기준: `feature/SEQDIFF2`, 시작 커밋 `340208c3`
- 수정 후 비용 측정 대상: 재시작·보안 모듈 재등록·PID 소유 연결을 포함한 문서 간 초기화 경로
- 입력: 저장소의 ALLQA 합성 fixture 사본 5개. 사용자 문서 원본은 사용하지 않았다.

## 결론

유효 짝 측정에서 기준선은 334.532초, 재시작 적용은 345.069초였다. 차이는 +10.537초(+3.15%), 입력 문서당 +2.107초다. 문서 사이 네 번의 재시작은 보안 모듈 재등록까지 포함해 합계 12.499초, 경계당 평균 3.125초(최솟값 2.900초, 최댓값 3.357초)였다. 총 시간 차이가 재시작 구간 합보다 작아 실행 간 편차가 있음을 보여 준다. 이 한 번의 짝으로 더 정밀한 인과 분해는 할 수 없다.

직접 계측한 재시작과 종단 간 관측 차이 모두 문서당 5초 미만이었다. 다만 자동 닫기 끔에서 한/글 창이 누적되는 부작용을 재현했고, 비교 보기의 실제 좌우 창 배치도 시험하지 못했다. 요청한 보수 기준에 따라 문서 간 재시작은 **기본 비활성화**했다. 명시적으로 켜려면 `DOCFIT_RESTART_BETWEEN_DOCS=1`, 끄려면 `DOCFIT_RESTART_BETWEEN_DOCS=0`을 지정한다. 문서가 한 개뿐이면 `=1`이어도 재시작하지 않는다.

자동 닫기 끔 시험에서는 이전 작업 창을 넘긴 뒤 새 한/글 프로세스를 추가해 두 개의 HWP PID가 남는 것을 확인했다. 비교 보기의 실제 좌우 배치는 GUI 프레임 핸들이 필요한데 테스트 드라이버에 실제 앱 프레임이 없어 COM 실측하지 못했다. 두 조건을 기본 동작에서 보호하기 위해서도 재시작 기본값을 보류했다. 재시작을 opt-in할 때는 새 인스턴스에 보안 모듈을 다시 등록하고, COM 계측 래퍼와 PID 소유 연결도 재설정한다.

## 비용 측정

`all` 모드로 아래 5개를 같은 순서로 처리했다. 유효 짝 측정의 기준선은 측정 당시 `github/main`의 `1284db55` 코드, 수정 후는 `340208c3`에 이번 변경을 적용하고 `DOCFIT_RESTART_BETWEEN_DOCS=1`을 지정한 코드다. 입력 파일명도 전후 동일하게 맞췄다. 두 배치는 공용 잠금 하나를 유지한 채 연속 실행했고, 짝 측정 동안 다른 빌드·시험은 실행하지 않았다.

| 항목 | 수정 전(기준 main) | 수정 후(재시작 opt-in) | 관측 차이 |
|---|---:|---:|---:|
| 5문서 pipeline 총 시간 | 334.532초 | 345.069초 | +10.537초 (+3.15%) |
| 문서 간 재시작 횟수 | 0 | 4 | +4 |
| 재시작 시간 합계 | 해당 없음 | 12.499초 | — |
| 재시작 시간(경계당 평균) | 해당 없음 | 3.125초 | 범위 2.900–3.357초 |
| 저장 성공 / 처리 오류 | 5 / 0 | 5 / 0 | 동일 |

사용한 문서: `txt_short`, `txt_long`, `hwp_reference`, `hwpx_continuation`, `hwpx_shapes`. 유효 짝 측정은 입력·결과 파일명이 모두 구분돼 다섯 결과를 각각 보존했다.

예비 실행은 기준선 결과 경로 이름 충돌, 수정 후 재시작 경로의 보안 모듈 재등록 누락, 그리고 전후 실행 사이의 별도 COM 부작용 시험이 있어 비용 표에서 제외했다. 위 표는 입력 이름을 맞추고 최종 재시작 초기화 경로를 보완한 뒤, 별도 작업 없이 연속 실행한 단일 짝 결과다.

## 부작용 및 COM 확인

| 시나리오 | 방법 | 결과 |
|---|---|---|
| 자동 닫기 켬 | 5문서 유효 측정 | 각 문서 경계에서 새 COM 프로세스와 보안 모듈 등록 성공. 다섯 문서 저장, 오류 0. |
| 자동 닫기 끔 | 2문서 COM 시험 | 재시작 경로가 이전 창을 사용자 소유로 넘겨 두 PID가 남는 것을 관찰했다. 시험 PID만 정리했다. 이 창들이 사용자 화면에 실제로 배치된 모습은 육안 확인하지 않았다. 최종 기본값에서는 이 경로의 재시작을 생략하도록 했고, 두 문서가 기존 프로세스에서 저장되는 것을 재확인했다. 명시적 `=1`은 계속 강제할 수 있다. |
| 비교 보기 켬, 좌우 배치 | 코드 경로 점검 | 실제 GUI 프레임 핸들이 없는 드라이버에서는 원본/작업 창 임베드가 시작되지 않아 좌우 배치의 COM·육안 시험을 하지 못했다. `작업창_임베드`와 재확인 경로는 새 작업 창을 다시 임베드하도록 유지했다. 비교 보기를 켠 실사용 화면의 영향은 미확인이다. |
| 중간 취소 | 첫 `saved` 이벤트 직후 취소 이벤트 설정 | 첫 문서만 저장, `stopped=true`, 문서 간 재시작 0회. 취소 플래그를 확인한 뒤 재시작을 건너뛰는 코드 경로를 확인했다. |
| 첫 문서 실패 후 다음 문서 | 없는 첫 경로 후 유효 TXT | 첫 문서 오류 1건을 기록하고 다음 문서를 저장했다. 재시작 뒤 진행 가능함을 확인했다. 이 경로 시험은 새 보안 모듈 재등록 추가 전 실행했고, 수정 후 ALLQA에서 정상 문서 경계 네 곳의 재등록은 확인했다. |
| 파일 1개 | TXT 한 건 | 저장 성공, 재시작 이벤트/로그 없음. `index < total` 조건으로 단일 입력은 경계를 만들지 않는다. |
| 이어하기 (`시작 인덱스=2`) | 2개 중 두 번째만 처리 | 두 번째 문서 저장, 앞 문서는 재처리하지 않았다. 단일 남은 문서 뒤 재시작 없음. |
| 환경변수 `=0` | 2문서 COM 배치 | 두 문서 저장, 재시작 로그 없음. 정책 단위 시험에서도 `0/false/no/off/빈 값`이 비활성으로 판정됐다. |

자동 닫기 끔과 비교 보기 사용 중 재시작은 opt-in으로 남겨 두었다. 자동 닫기 끔에서 재시작하면 보존된 창이 문서 수만큼 늘 수 있고, 비교 보기에서는 실제 좌우 임베드 경로를 확인하지 못했기 때문이다. `DOCFIT_RESTART_BETWEEN_DOCS=1`은 이 보호 조건보다 우선하는 명시적 opt-in이다.

## 메타데이터 판정과 대안

문서가 한 개면 문서 간 상태가 없으므로 재시작은 불필요하다. 여러 문서 중 기존 비교에서 `borderFillIDRef` 번호만 재배치된 결과는 참조 정의를 정규화하면 동등했지만, `hwpx_continuation`의 `endNotePr/noteLine/@length`는 단독 결과 `14692344`, 순차 실행 결과 `0`으로 실제 XML 값이 달랐다. 해당 합성 문서에는 각주·미주 참조가 없어서 시각적 영향을 확인하지는 못했지만, 런타임에서 단순 ID 재배치와 의미 있는 문서 메타데이터 차이를 미리 판별할 수 없으므로 **“메타데이터 차이만이면 재시작 생략” 규칙은 구현하지 않았다.**

한컴 개발자 포럼의 오토메이션 예제에는 `FootnoteOption`의 `EndnoteShape.LineLength`를 설정하는 방법이 있다([한컴디벨로퍼: 미주의 뒤 장식문자 바꾸기](https://forum.developer.hancom.com/t/topic/2956)). 이는 특정 문서의 각주·미주 옵션을 설정하는 API 예시다. 이 앱에서 원본별 기본 선 길이를 안전하게 읽고 복원하는 경로, 또는 영향을 주는 다른 HWP 내부 상태까지 초기화하는 방법은 확인하지 못했다. 사용자 문서별 설정을 덮어쓸 수 있어 이번 수정에는 적용하지 않았다. `FileClose`만으로 상태가 초기화되지 않았다는 SEQDIFF1 결과도 있어, 이 API로 프로세스 재시작을 대체할 수 있다고 단정하지 않는다.

## 수정 및 시험

- 기본 재시작을 비활성화하고, `DOCFIT_RESTART_BETWEEN_DOCS=1`을 명시한 경우에만 재시작한다. `=0`은 명시적 비활성화다.
- 재시작에는 이전 인스턴스 정리, 새 COM 생성, 새 창 표시, 보안 모듈 등록, COM 계측 래핑, 소유 PID 연결을 포함한다. 비교 보기 강제 opt-in 시 새 창을 다시 임베드한다.
- `tests.test_hwp_process_restart_policy`와 `tests.test_allqa_tools`: 12개 통과.
- 전체 `unittest discover -s tests`: 3,584개 통과, 28개 건너뜀. unittest는 `OK`와 종료 코드 0으로 끝났다. 종료 뒤 테스트 임시 디렉터리의 `timeline-content.sqlite` 잠금 정리에서 `PermissionError`가 무시 경고로 출력됐다. 변경된 추적 fixture 4개는 기준 상태로 복구했다.
- `hwp-auto-docfit.py`는 수정하지 않았다(CRLF 유지). 저장소에는 PC 전용 경로를 추가하지 않았다.

## PM 결정(2026-11-24)

결과 재현성이 비용(문서당 +2.1초, +3.15%)보다 중요하므로 **기본 켬**으로 바꿨다. 자동 닫기를 끈 경우와 비교 보기에서는(창 누적·좌우 배치 미검증) 기본을 끄고, `DOCFIT_RESTART_BETWEEN_DOCS=1`로 강제, `=0`으로 해제한다. 문서가 1개면 재시작하지 않는다. 정책 시험 2건을 갱신했다(`tests.test_hwp_process_restart_policy`·`test_allqa_tools` 13건 통과). 이 변경 뒤 COM 실측은 하지 않았다.
