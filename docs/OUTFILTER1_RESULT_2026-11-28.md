# OUTFILTER1 결과 — 블록 검색으로 거른 상태의 편집이 다른 블록을 바꾸던 결함 (2026-11-28)

대상: `flutter_ui/lib/features/outliner/outliner_workspace.dart`(앱 안 화면). `outliner_core` 의 키 규칙과 네이티브 창(`outliner_win`)은 바꾸지 않았다.
합성 자료와 가짜 엔진 위젯 시험만 썼다. 설치본·사용자 데이터·실행 중인 앱은 건드리지 않았고 푸시하지 않았다.

## 1. 원인 (위젯 시험으로 재현)

블록 검색을 하면 문서 블록 목록(`_blocks`) 자체를 검색 결과만 남긴 목록으로 바꿨다. 엔진에는 문서 전체 마크다운과 함께 이 목록의 순번을 보냈다.

잘못 가던 값:

- 키 명령의 대상 블록(`block`): Enter·Shift+Enter·Tab·Shift+Tab·Ctrl+Enter·Backspace·Delete·붙여넣기·예약한 키, 줄 단추(들여쓰기·내어쓰기·접기)
- 블록 선택 명령의 `selection`: 삭제·잘라내기·복사·들여쓰기·내어쓰기·TODO·접기와 일괄 단추
- 접힘 목록(`folded`): 순번이 어긋나거나, 검색에 없는 블록의 접힘이 빠짐
- '새 블록' 단추: 문서 끝이 아니라 마지막 검색 결과 뒤에 삽입

이전에 올바른 자리를 보내던 곳은 OUTKEYS3 의 '칸을 벗어날 때 저장' 하나였다.

## 2. 고친 방식

`_blocks` 는 늘 문서 전체다(목록의 자리 = 문서 순번). 검색 결과는 블록 번호 집합(`_filter`)으로만 들고 화면을 그릴 때 거른다. 경로마다 순번을 환산하지 않으므로 같은 혼동이 다시 생기기 어렵다. 문서가 새로 읽히면 검색은 이전처럼 저절로 풀린다.

## 3. 거른 상태에서의 명령별 적용 대상

'가려진 블록이 하나라도 있을 때'만 제한한다. 모든 블록이 검색되면 평소와 같다.

| 명령 | 처리 | 적용 대상·이유 |
|---|---|---|
| Enter, Shift+Enter, 붙여넣기 | 허용 | 커서가 있는 블록. 새 블록의 자리는 문서 구조 기준(그 블록의 하위 포함 뒤 등) |
| Tab·Shift+Tab, 들여/내어쓰기 단추 | 허용 | 고른 블록과 그 하위(가려진 하위 포함). 새 상위 블록이 가려져 있을 수 있음 |
| Ctrl+Enter, 접기·펼치기, 완료 단추 | 허용 | 고른 블록만(접기는 그 블록의 하위) |
| 복사 | 허용 | 선택 블록과 하위(가려진 하위 포함). 문서를 바꾸지 않음 |
| 삭제·잘라내기 | 선택 블록의 하위가 모두 보일 때만 | 가려진 하위가 있으면 **막고 알림**(보지 못한 블록이 지워짐) |
| 맨 앞 Backspace·맨 끝 Delete(블록 합치기) | **막고 알림** | 합칠 이웃이 가려져 있을 수 있음. 칸 안 글자 지우기는 그대로 |
| 블록 위/아래 옮기기(Alt+Shift+↑/↓) | **막고 알림** | 자리를 바꿀 이웃이 가려져 있을 수 있음 |
| 거른 화면에서 처리 중에 눌러 예약한 Backspace·Delete | 합치기가 되는 경우 **적용하지 않고 알림** | 누를 때 화면에 이웃이 보이지 않았음. 뒤에 예약한 키도 버리고 친 글은 칸에 남김 |
| '새 블록' 단추 | 허용 | 문서 끝(검색하지 않았을 때와 같음) |
| Ctrl+A(상위 블록 선택) | 상위가 가려졌으면 선택하지 않고 알림 | 이어지는 삭제가 보이지 않는 블록에 적용되지 않게 |
| Shift+↑/↓ 범위 선택, Ctrl+Shift+A | 허용 | 보이는 블록만 |

제한은 단순하게 잡았다. 합치기·옮기기는 대상 이웃이 보이는 경우에도 막는다(core 의 이웃 판정 규칙을 화면에 한 벌 더 두지 않기 위해).

함께 바꾼 것:

- 검색하면 앞서 한 블록 선택을 푼다(가려진 블록이 선택된 채 일괄 단추가 남지 않게).
- **검색 칸을 비우면 검색이 풀린다.** 이전에는 풀 방법이 페이지를 다시 여는 것 등뿐이었다.
- 검색을 다시 하면 문서 전체에서 새로 찾는다(이전에는 앞 결과 안에서 다시 거름).
- 검색에 없는 접힌 블록은 하위의 검색 결과를 가리지 않는다. 접힌 블록이 자기 하위가 아닌 결과를 가리던 것을 고쳤다.
- 결과가 없으면 '블록이 없습니다' 대신 '검색 결과가 없습니다'를 보인다.

끌어 옮기기: 앱 안(Flutter) 아웃라이너에는 블록 끌어 옮기기가 없어 시험 대상이 아니다(네이티브 창에만 있음).

## 4. 같은 부류 점검

- Flutter 아웃라이너: `_blocks` 에서 얻는 순번(`indexOf`·`_indicesWhere`·결과의 `selection`·`cursor`)은 이제 모두 문서 순번이다. 자동완성 후보 순번은 화면 안에서만 쓴다.
- 네이티브 창(`outliner_win`, 코드 읽기만): 화면 줄은 `Row::block`(문서 순번)이나 블록 번호로 바꿔 core 에 보낸다. 화면 순번을 문서 순번으로 보내는 곳은 보지 못했다. 검색은 별도 결과 목록이며 편집 화면을 거르지 않는다.
- 다른 기능 화면(아웃라이너 밖)은 점검하지 않았다.

## 6. 남은 문제

- 거른 상태에서 ↑↓·←→ 로 블록을 넘으면 core 가 문서의 실제 이웃(가려진 블록 포함)으로 커서를 옮기고 검색이 풀린다. 문서 글은 바뀌지 않는다(이전과 같음).
- 명령을 한 번 적용하면 검색이 풀려 전체가 보인다(이전과 같음). 검색 칸의 글은 남는다.
- 네이티브 창(코드 읽기, 미재현·미수정): 확대(zoom)한 상태의 경계에서 Backspace·Delete·옮기기가 확대 범위 밖의 보이지 않는 블록에 닿을 수 있어 보인다. 순번 혼동은 아니며 별도 확인이 필요하다.
- 설치본·실제 키보드·한글 IME 확인은 하지 않았다.
