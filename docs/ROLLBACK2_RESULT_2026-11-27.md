# ROLLBACK2 — 쪽 간격 조정의 취소·예외 원복(E07)

작성: 2026-11-27 · 브랜치: `feature/ROLLBACK2` · 로컬 커밋만, 푸시 없음.

## E07 확인

사실이었다. `_보고서_페이지수_맞춤_시도_본체`는 취소 때 바로 False를 반환해 줄인 간격·셀 여백이 남았고, `구조문단_간격_복원`·`표_셀_세로여백_복원`은 예외를 로그만 남기고 넘어갔다. 문단 간격 쓰기 함수도 예외를 삼켜, 원복 실패가 성공처럼 보였다.

## 수정

| 대상 | 수정 전 | 수정 후 |
|---|---|---|
| 선형 쪽 수 맞춤 | 취소·예외 때 원복 없음. 취소 중 '묶음 걸림 없음'을 성공으로 판정 | 성공 확정 전에는 finally에서 원복 |
| 고속 쪽 수 맞춤 | 일부 쓰기 뒤 예외면 기록값이 원래 값이라 원복에서 건너뜀 | 쓰는 동안 '값 모름', 신규 `쪽맞춤_원복`이 쓴 곳을 다시 읽어 확인 |
| 문단 간격·셀 여백 복원 | 실패 무시 | 모두 시도한 뒤 다시 읽어 확인 |
| 보고서 1쪽 맞춤 | 원복 한 단계가 실패하면 뒤 단계 생략·반환값 미확인 | 쪽 여백·줄간격·간격을 각각 시도하고 확인. 취소 때도 원복 |
| 묶음 줄간격 이동 | 일부 적용 뒤 예외면 원복 안 함 | 원복하고 문단별 확인 |
| 묶음 뒤 문단 줄간격 | 첫 실패에서 원복 중단 | 전 문단 시도·확인 |
| 문단 위 간격 당김 | 예외 때 원복 없음, 원값을 0.1pt로 반올림 | finally에서 원값 그대로 원복·확인 |
| 묶음 쪽 나눔 이동 | 예외 때 쪽 나눔 잔존, 원래 켜져 있어도 끔 | 원래 값을 보관해 finally에서 원복 |
| 중제목 정리 | 뒤 □의 쪽 나눔을 푼 채 중단·예외로 이탈 | 다시 켬 |
| 보고서 안 쪽 나눔 해제 | 중단·예외 때 해제 상태 잔존 | 중단·예외면 다시 켬 |

원복을 확인하지 못하면 ROLLBACK1의 `fail_required_edit`로 올려 결과 저장을 막는다. `보고서_페이지수_맞춤_시도`와 `…_전체_적용`은 이 오류를 잡아 기존 방식으로 다시 시도하지 않는다. 공통 도우미는 신규 `docfit_engine/layout_restore.py`다. `hwp-auto-docfit.py`는 연결 2줄만 추가했고 CRLF를 유지했다.

## 실제 확인에서 추가로 찾은 원복 오차

간격 복원이 pt 값을 `PointToHwpUnit`으로 바꾸며 소수를 버려, 문단 아래 간격 29(HWPUNIT)가 28로 돌아왔다. 수정 전 코드는 취소 없이 정상적으로 '실패 후 원복'한 경로에서도 25문단이 원본과 달랐다. 복원 뒤 값이 다르면 원시 값(pt×200)을 다시 써서 정확히 맞춘다(`confirm_margin`). 정상 간격 쓰기 함수는 바꾸지 않았다.

## 정상 경로

- 가짜 hwp: 고속 실패·성공, 줄간격 이동 실패·성공, 위 간격 당김 실패·성공, 쪽 나눔 실패·성공 8개에서 수정 전과 문단·셀 쓰기 순서, 반환값, 최종 상태가 같았다.
- 실제 한/글: 선형 방식의 성공·재적용 성공 저장본은 수정 전·후 문단 모양 차이 0. 실패 후 원복 경로(선형·고속)는 위 오차가 없어진 만큼 달라진다(수정 전 25문단 차이 → 0).
- 보관·확인용 읽기가 늘었다. 시간 비용은 측정하지 않았다.
- 기존 시험 파일은 수정하지 않았다.

## 실제 한/글 확인(합성 문서)

잠금 규칙에 따라 `.full-test.lock`이 풀린 뒤 COM 잠금을 배타 생성하고 DispatchEx 새 인스턴스만 사용했으며, 끝나면 그 인스턴스를 종료했다. 합성 문서(본문 75문단·12문단, 2×2 표)에서 시도 중간에 저장해 값이 실제로 바뀐 것을 확인한 뒤, 중단·예외를 주입하고 최종 저장 HWPX를 원본과 비교했다.

| 시나리오 | 중간(바뀐 문단/셀) | 최종 차이 |
|---|---|---|
| 선형: 중단 / 예외 / 재적용 중 중단 | 75/4, 75/4, 75/0 | 0 |
| 고속: 중단 / 예외 | 75/4 | 0 |
| 선형·고속: 목표 미달 | — | 0 |
| 묶음 줄간격 이동: 중단 / 예외 | 8/0 | 0 |
| 문단 위 간격 당김: 중단 / 예외 | 8/0 | 0 |

| 1쪽 맞춤: 중단 | 12/0 | 0 |
| 대조(열고 저장) | — | 0 |

비교 대상은 문단별 문단 모양 정의·쪽 나눔, 셀 여백, 쪽 여백이다. **단, 테두리 참조 번호는 같지 않다.** 한/글은 기존 간격 쓰기(`HParaShape` 경로)를 실행하면 문단의 테두리/배경 정의를 '투명 채우기(`faceColor=none`)를 더한 정의'로 바꾼다. 원복 전 중간 저장본에 이미 나타나며, 위 '차이 0'은 이 투명 채우기만 같은 것으로 본 결과다. 이를 같게 보지 않으면 `HParaShape`로 쓴 문단 수만큼 차이가 난다.

복원 실패는 실제 한/글에서 만들지 않았고 가짜 hwp 시험으로만 확인했다.

## 남은 문제

- `문단_줄수_원본맞춤`이 바꾼 자간은 1쪽 맞춤이 실패해도 원복되지 않는다(`자간보관`이 비어 있음). 문단 모양이 아닌 글자 모양이라 이번 범위 밖이다.
- 보고서 1쪽 맞춤이 정상적으로 '실패'한 경우, 먼저 해제한 보고서 안 쪽 나눔은 기존처럼 해제된 채 남는다. 정상 경로 결과를 바꾸지 않으려고 두었다.
- `_묶음_쪽나눔_이동`에서 바꾸기 전 쪽 나눔 값을 읽지 못하면 설정 명령의 성패만 본다.
- `쪽배치_축소쪽_줄간격_통일`·`문서_쪽나누기_전체해제`는 시도·원복 구조가 아니어서 바꾸지 않았다.
- 위의 테두리 참조 번호 변화(화면 모양은 같은 투명 채우기)는 남는다. 원복 쓰기가 아니라 기존 간격 쓰기 방식의 부수 효과다.
- 원복 실패로 저장이 막히는 것은 문서 단위다. 실패 문서의 화면 상태 표시는 확인하지 않았다.
- 실제 문서, 다른 한/글 판, 설치본·EXE는 확인하지 않았다.
