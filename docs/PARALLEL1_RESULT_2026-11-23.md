# PARALLEL1 여러 파일 한/글 2개 동시 처리(옵션, 기본 꺼짐) 1단계 결과

## 결론 (먼저)

- **기본 꺼짐 유지, 옵션 화면 노출 보류.** 오류·멈춤·잠금 충돌은 0건이었으나, **5개 문서 중 2개(`hwp_reference`, `hwpx_continuation`)의 서식 정규화 해시가 순차 처리 결과와 3회 모두 달랐다.** 카드 기준("한 번이라도 결과가 다르면 보류")에 따라 노출하지 않는다.
- 원인 추정: 병렬(= 문서마다 새 한/글 프로세스) 결과는 **같은 문서를 단독(1개만)으로 처리한 결과와 해시가 일치**했다. 순차(한/글 1개로 여러 문서를 이어 처리) 결과가 앞선 문서의 영향으로 달라지는 것으로 보인다(병렬이 틀렸다고 단정하지 않는다). 다만 이 차이의 내용(서식 ID 번호 `borderFillIDRef` 4↔3 등)이 시각적으로 동등한지는 확인하지 않았다.
- 속도 이득은 5건·3회 평균 **-9.0%**(334.7초 → 304.7초)로 PARALLEL0(-30.6%)보다 작았다. 정적 분배(파일 크기 기준)가 실제 처리 시간과 잘 맞지 않기 때문으로 보이며, 작업자별 실제 소요 시간은 이번에 기록하지 않았다.

## 구현 (코드는 설정 2일 때만 동작)

| 항목 | 내용 |
|---|---|
| 설정 키 | `all_parallel_files` 정수, 기본 1(현재 동작), 2면 병렬. `docs/settings_defaults.json` 골든·`settings_schema.py` 기본값·`configuration_service.py` 라벨에 추가. 화면 폼에는 **숨김**(`EXCLUDED`) — 노출 보류 결정에 맞춤. 노출하려면 `EXCLUDED`에서 빼면 한 줄이 고급 설정에 나타난다. |
| 계획 | `docfit_core/parallel_files.py`: 큰 파일 우선 그리디 분배, 같은 원본 중복 제거(로그), 결과 파일 이름이 같아지는 문서(`a.hwp`+`a.txt` 등)는 **같은 작업자에 묶어 차례로** 처리, 작업자별 실행(스레드)·한 작업자 실패 격리·취소 이벤트 공유 |
| 실행기 | `docfit_engine/parallel_run.py` + `parallel_worker.py`: 작업자마다 **별도 Python·한/글 프로세스**(DispatchEx)를 띄워 JSON 줄로 이벤트를 받아 진행률·문서 순번·완료를 합친다. 취소는 작업자 표준입력으로 전달(45초 안에 안 끝나면 강제 종료). |
| 자동 끄기(사유를 로그에 표시) | 파일 1개, 비교 보기(창 배치·전역 상태), 이어하기(시작 인덱스>1), 설치형 실행 파일(작업자 프로세스 미지원), 옵션을 JSON으로 전달할 수 없을 때 |
| 연결 | `runtime.py`의 `작업_실행` 호출 지점에서 `context.parallel_setting >= 2`일 때만 `parallel_run`을 불러온다. 1이면 모듈 자체를 가져오지 않아 **기존 경로 불변**. `docfit_ui/legacy.py`는 컨텍스트에 설정 값만 심는다(`Thread(target=작업_실행, args=…)` 모양은 기존 시험 때문에 유지). |
| 클립보드·창 활성화 | 엔진·코어에서 `SendKeys`·클립보드·`SetForegroundWindow`를 쓰는 단계를 찾지 못했다(`docfit_engine`, `docfit_core` 검색). 창 배치(`창_임베드`)는 비교 보기에만 쓰여 자동 끄기 조건으로 막았다. 한/글 자체·보안 모듈의 전역 클립보드 동작은 이번에도 확인하지 못했다. |

작업자 상태: `idle → running → done | failed | cancelled`(되돌아가지 않음). 취소로 못 한 파일은 '실패'가 아니라 미처리.

## 측정 조건

- 문서: ALLQA 합성·사본 5건 — `txt_short`, `txt_long`, `hwp_reference`, `hwpx_continuation`, `hwpx_shapes`(문서 ID 이름으로 사본 생성, 원본 픽스처 해시 전후 동일). `hwpx_table`은 PARALLEL0에서 순차·병렬 모두 열기 실패해 뺐다.
- 방식: 같은 `작업_실행` 호출(모드 all, 표준서식 켬, 자동 닫기 켬, 검수 끔)을 (순차) 한 프로세스·한/글 1개로 5건 전부, (병렬) `run_parallel_job`로 작업자 2개. 순차→병렬 순서로 3회 반복, 반복마다 사본 폴더 새로 생성. COM 잠금(`.com-test.lock`)을 측정 프로세스가 전체 동안 보유, 측정 중 다른 빌드·시험 없음.
- 분배(병렬): 작업자1 = `txt_short`, `txt_long`, `hwpx_continuation`, 작업자2 = `hwp_reference`, `hwpx_shapes`.
- 도구: `scripts/parallel1_probe.py`(반복·메모리/CPU 샘플링·해시), `scripts/parallel1_driver.py`(구동기). 해시는 `allqa_compare.xml_hashes`(텍스트 XML, `paraPr` ID를 풀어 정규화한 서식)를 그대로 썼다.
- PC 사양·한/글 버전은 이번에 다시 기록하지 않았다(PARALLEL0과 같은 PC의 같은 설치, 4 물리 코어/8 논리 프로세서, 약 24 GiB).

## 안정성 판단

- 3회 × 2방식 모두 오류·멈춤·잠금 충돌·한/글 열기 실패 0건. 한/글 2프로세스 동시 실행, 보안 모듈 등록, 독립 저장 모두 문제 없었다(이 PC·이 문서 5건 한정).
- 그러나 **순차와 결과가 다른 문서가 있다** → 기준 미충족. 기본 꺼짐 유지, 화면 옵션 노출 보류.
- 확인하지 못한 것: 위 서식 차이가 시각적·기능적으로 같은지(한/글에서 열어 비교하지 않음), 순차 결과가 앞선 문서 영향을 받는다는 가설의 직접 증명(단독 결과와 일치한다는 정황뿐), 문서 수 2~3건·큰 문서·다른 PC, 취소·한 작업자 실패의 **실제 COM 시험**(단위 시험은 가짜 작업자로 확인), 설치형 실행 파일(작업자 프로세스 미지원이라 자동으로 끔).

## 권고

1. 기본 1 유지, 화면 노출하지 않는다(키는 설정 파일로만 켤 수 있음).
2. 노출 전에 (가) 순차 결과가 문서 사이 영향을 받는지 별도 카드로 확인 — 사실이면 병렬이 아니라 순차 경로의 결함 후보, (나) 서식 차이가 동등한지 판정 기준(`borderFill` ID 정규화) 보강, (다) 분배를 파일 크기 대신 실제 소요 시간 추정 또는 동적 큐(끝난 작업자가 다음 파일을 가져감)로 바꿔 이득을 키우는 것을 검토.
3. 설치형 EXE 지원(작업자 진입점을 EXE에 포함)은 위 1~2가 해결된 뒤에 한다.
