# FILEOPS1 — 사진뷰·문서뷰 다중 선택과 복사·삭제·폴더 이동·파일명 변경 (2026-11-25)

사용자 지시: "사진뷰, 문서뷰에서 파일을 선택하여 복사, 삭제, 폴더 이동이 가능한 기능추가. shift키를 이용해 다중 파일들을 선택하는 기능추가."

앞 카드 `feature/DBLOPEN1`(aa64b5fd)을 병합한 뒤 작업했다. 대상은 Flutter 두 화면이다.

## 선택

| 조작 | 동작 |
|---|---|
| 클릭 | 그 파일만 선택. 사진뷰는 이전처럼 약 0.3초 뒤 크게 보기, 더블클릭은 연결 앱 |
| Ctrl+클릭 | 추가·해제만 (열기·크게 보기 없음) |
| Shift+클릭 | 마지막으로 누른 항목부터 화면 순서상 범위 (Ctrl+Shift 는 범위 추가) |
| Ctrl+A / Esc | 전체 선택 / 해제 |
| 사진뷰 '다중 선택' 모드 | 보조키 없는 클릭도 추가·해제(이전 동작 유지), Shift 는 범위 |

- 묶음 격자(날짜·폴더·카메라·위치), 검색 결과, 중복 보기에 모두 적용한다. 범위는 묶음 경계를 넘는다.
- 목록 위에 늘 같은 높이의 줄(`N개 선택`, 모두 선택, 선택 풀기, 복사, 폴더로 복사, 폴더 이동, 이름 변경, 삭제)을 둔다.
- 검색하거나 보기를 바꾸면 선택을 푼다. 파일 작업은 지금 화면에 보이는 선택만 대상으로 한다.

## 파일 작업

| 작업 | 단축키 | 규칙 |
|---|---|---|
| 복사(클립보드) | Ctrl+C | `CF_HDROP` + 복사 표시. 탐색기에 붙여넣는 형식 |
| 폴더로 복사 · 폴더 이동 | — | 덮어쓰지 않고 `이름 (2).ext`부터 붙인다 |
| 삭제 | Delete | 개수·이름 확인창(처음 초점은 취소) 뒤 휴지통. 영구 삭제 경로 없음 |
| 이름 변경(1개) | F2 | 확장자 고정. 경로 구분자·금지 문자·예약 이름·끝의 마침표/공백 거부. 같은 이름이 있으면 거부 |

- 화면의 목록 확장자인 실제 파일만 처리한다.
- 휴지통: `IFileOperation`이 "휴지통으로 보낼 수 없다"고 알리면 중단시켜 파일을 남긴다. 네트워크·이동식 드라이브는 시도하지 않는다.
- 클라우드 전용 파일은 복사(와 다른 드라이브 이동)를 거절한다(내려받기 방지).
- 다른 드라이브 이동은 복사가 끝난 뒤 원본을 지우며, 원본을 못 지우면 만든 사본을 되돌린다.
- 부분 실패는 파일별 안내창으로 보여 주고, 성공한 것만 목록·DB·썸네일 캐시·저장된 목록에 반영한다.
- 사진 DB: 이동·이름 변경은 태그·즐겨찾기·촬영일을 새 경로로 옮긴다(목록 범위 밖으로 옮겨도 보존). 복사본은 태그·즐겨찾기 없이 추가한다. **삭제하면 그 사진의 태그·즐겨찾기 기록도 지운다**(휴지통에서 되살려도 돌아오지 않는다).
- 작업은 배경 스레드에서 하고 화면은 진행 상태를 조회한다. 취소 단추는 없다.

## 구현

- 백엔드: `docfit_app/file_ops.py`(두 서비스 공용). 명령 `file_op_start`·`file_op_progress`·`pick_destination`을 `doc_grid`·`photo_album`에 추가했다. 데스크톱 브리지와 `application_service` 모두 기존 `command` 통로를 쓴다.
- 화면: `features/common/file_selection.dart`(선택 모델), `features/common/file_ops_area.dart`(작업 줄·단축키·확인창).
- 대상 폴더 선택: 네이티브 Flutter 는 `getDirectoryPath`, 웹 화면(WebView)은 백엔드 폴더 선택창.
- 함께 고친 것: 사진뷰 묶음 격자에서 스크롤·다시 그린 뒤 다른 사진이 크게 보일 수 있던 순번 계산(DBLOPEN1 기록)을 경로 기준으로 바꿨다. 클릭마다 다시 그리게 되어 필요했다.

별도 수동 확인(합성 파일):
- 실제 휴지통: C:·E: 임시 폴더의 파일이 원본에서 사라지고 휴지통에 있음을 확인. 배경 스레드를 거친 삭제 2건도 성공.
- 휴지통 표시가 없다고 가정시킨 경우 `RECYCLE_UNAVAILABLE`이고 파일이 남음을 확인.
- 클립보드 자료는 `DragQueryFileW`로 되읽어 확인(사용자 클립보드는 건드리지 않음).
- 시험에 쓴 합성 파일(`fileops1-synthetic-*.pdf`)이 휴지통에 남아 있다.

## 확인하지 못한 것

- 실제 앱(설치본·exe, WebView)에서의 Ctrl/Shift 클릭·단축키 동작. 위젯 시험만 했다.
- 실제 클립보드에 올려 탐색기에서 붙여넣기.
- 웹 화면의 폴더 선택창(시험은 대화상자를 가짜로 바꿨다).
- Windows '휴지통에 버리지 않고 바로 삭제' 설정이나 휴지통 용량 초과 상태에서의 거절(설정을 바꾸지 않았다). 거절 경로는 위의 가정 시험으로만 확인.
- 다른 드라이브로의 실제 이동(시험은 오류를 흉내 냈다), 클라우드 전용 파일, 260자를 넘는 경로, 빌드된 exe 에서의 휴지통 COM 호출.
- 처음 스캔이 도는 중에 옮기거나 지우면, 스캔이 끝난 목록에 옛 항목이 잠시 다시 보일 수 있다고 코드상 판단한다(다시 작업하면 '파일을 찾을 수 없음').

## 남은 일

- 네이티브 창(`docview_win`·`photoview_win`)에는 다중 선택·파일 작업이 없다.
- 기존 문제(고치지 않음): 데스크톱 브리지의 `PhotoAlbumService()`는 설정 저장소 없이 만들어진다(`desktop_web_ui.py` `photo_album`). 코드상 사진뷰의 제외 폴더·썸네일 크기 저장이 동작하지 않고, 제외 폴더로 옮긴 사진도 목록에 남는다.
