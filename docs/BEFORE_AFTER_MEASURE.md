# 변경 전후 성능 비교 측정 절차

## 목적과 기존 절차

변경 전과 변경 후의 처리 시간 및 한/글 COM 호출량을 같은 PC, 같은 시연 문서 사본, 같은 작업 옵션으로 비교한다. 성능 수치는 릴리즈 서식 검수의 합격 기준을 대신하지 않는다. 최종 서식 일치 판정은 [릴리즈 검수 절차](RELEASE_TEST_PROCEDURE.md)를 따른다.

기준선 수집은 기존 `scripts/perf_baseline_pc.py`를 재사용한다. 이 스크립트는 `DOCFIT_COM_PERF=1` 계측을 켜고 `baseline.json`, `baseline.md`를 기록하며 COM 시험 잠금을 사용한다. 반복 측정 없이 한 번 실행하고, 측정 중 다른 시험이나 빌드를 실행하지 않는 기존 규칙을 그대로 적용한다.

## 측정 준비

1. 측정 PC를 고정하고 재부팅한 뒤 업데이트, 백신 검사, 동기화, 백업, 인덱싱 등 예약·백그라운드 작업이 끝날 때까지 기다린다. 불필요한 앱과 문서 창을 닫고 전원 모드를 고정한다. 두 측정 사이에도 같은 상태를 유지한다.
2. 동일한 시연 원본에서 변경 전용 작업 사본과 변경 후용 작업 사본을 각각 만든다. 원본은 열거나 수정하지 않는다. 두 사본의 내용과 경로·파일명 조건이 같도록 한다.
3. 작업 방식(`--mode`: `spacing`, `unify`, `format`, `all`)과 앱 옵션을 기록하고 전후에 동일하게 설정한다. 비교할 코드 상태를 각각 명확히 기록한다.
4. 결과 폴더는 매 측정마다 새 폴더로 준비한다. 스크립트는 기존 `comperf` 폴더를 덮어쓰지 않으므로 재사용하지 않는다.

## 측정 실행

Windows에서 저장소의 Python 환경으로 변경 전과 변경 후를 각각 한 번 실행한다. 문서 사본 목록, 옵션, 스크립트는 같게 하고 결과 폴더만 분리한다.

```powershell
.\.venv\Scripts\python.exe scripts\perf_baseline_pc.py "시연 사본.hwpx" --mode all --out "결과\before"
.\.venv\Scripts\python.exe scripts\perf_baseline_pc.py "시연 사본.hwpx" --mode all --out "결과\after"
```

스크립트는 `com_test_lock`으로 COM 측정을 보호한다. 잠금 파일은 `C:/HWP_AUTODOCFIT/.com-test.lock`이며, 잠금이 이미 사용 중이면 기존 시험과 충돌하지 않도록 측정을 시작하지 않는다. 잠금 경로를 임의로 바꾸거나 우회하지 않는다. 각 실행 결과의 `baseline.md`와 `baseline.json`을 보관하고 버전/커밋, 실행 시각, PC 상태, 문서 식별정보, 작업 방식과 옵션을 함께 기록한다.

## 기록 표

생성된 기준선 요약을 옮기고 전후 차이와 변화율을 계산한다. 시간·호출량은 줄어든 경우를 개선으로 표시한다. 누락되거나 실패한 실행은 수치 비교에 포함하지 않는다.

| 항목 | 변경 전 | 변경 후 | 차이(후−전) | 변화율 |
|---|---:|---:|---:|---:|
| 전체 처리 시간(초) |  |  |  |  |
| COM 처리 시간(초) |  |  |  |  |
| COM 호출 횟수 |  |  |  |  |
| Python 처리 시간(초) |  |  |  |  |
| 실패 문서 수 |  |  |  |  |

문서가 여러 개면 문서별 수치도 별도 표로 기록한다. 변경 전후 사본의 동일성, 실행 옵션 및 코드 상태가 확인되지 않거나 실패 문서가 있으면 비교 결과를 확정하지 않는다.

## 판정 기준

- 결과물의 서식·내용 보존은 [릴리즈 검수 절차](RELEASE_TEST_PROCEDURE.md)에 따라 별도로 확인한다. 성능이 빨라져도 서식 불일치는 통과가 아니다.
- 동일 조건의 두 실행이 모두 정상 완료되고 문서 사본·옵션이 동일해야 유효한 성능 비교로 기록한다.
- 전체 시간, COM 시간, COM 호출량을 함께 본다. 한 번의 측정은 해당 PC와 해당 문서에서 관찰한 결과일 뿐 일반적인 성능 보장으로 표현하지 않는다.
- 개선 목표가 사전에 정해져 있으면 그 목표와 각 지표의 변화율을 대조한다. 목표가 없으면 수치와 조건만 보고하고 임의의 합격 임계값을 만들지 않는다.
- 판정 기록에는 결과 폴더, `baseline.md`·`baseline.json`, 표, 유효성 여부와 한계 설명을 포함한다.
