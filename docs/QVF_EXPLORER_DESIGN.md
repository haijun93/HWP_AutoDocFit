현재 `kvf/src/main.rs`는 Win+Shift+F·트레이·두 번째 실행을 창 호출로 보내고, `window.rs`가 GDI 이중 버퍼와 Win32 메시지를 처리한다. 창은 현재 `가상 폴더 · {상자}` 머리글, `전체/핵심자료/기초자료/참고자료/임시저장소` 탭, 검색 문자열, 단일 목록·선택·열기/위치 열기 메뉴를 제공한다. 한/글 COM은 없다. `vf_state.rs`는 `Hidden/Loading/List/Search/Empty/Failed/Minimized`와 이벤트·효과를 순수 전이 함수로 관리한다. `vf_data.rs`는 `library.db`의 `box`·`item`을 읽기 전용으로 열고 최대 5,000개 항목을 읽는다. `item`의 `space` 값은 core/basis/reference/temp이고, 기존 데이터베이스를 이 창에서 변경하지 않는 것이 현재 경계다. `settings.rs`에는 단축키, 트레이, 고정, 창 위치·크기, 최근 상자만 저장한다.

설계 경계: 자료함의 상자와 네 영역 탭은 기존 데이터의 분류다. 새 탐색기 화면의 1~4개 패널은 사용자가 동시에 보는 독립 탐색 문맥이다. 패널 배치·패널별 현재 위치·가상 항목 복제본은 `library.db`에 기록하지 않고 kvf 전용 저장소에 둔다. 기존 상자/영역 항목은 읽기 전용 원본으로 보여 주고, 전용 저장소에는 항목 참조와 사용자 가상 항목을 기록한다. 이를 통해 기존 자료함 DB를 수정하지 않고 이동·복제·되돌리기를 제공한다.

## 1. 탐색기 화면

- **상단 제목줄**: `퀵가상폴더`와 최소화·최대화·닫기, 고정 상태. 기존 공용 `kagent/src/frame.rs`의 프레임·DPI 배율·테두리와 `ui_theme` 팔레트를 재사용한다.
- **주소줄/명령줄**: 패널마다 상자 > 기존 영역(core 등) 또는 사용자 가상 폴더 경로를 breadcrumb로 표시한다. 주소 입력은 현재 위치의 이름/경로 선택 이동이며, 원본 파일 시스템 주소를 직접 쓰는 기능과 혼동되지 않게 가상 위치를 명시한다. 위쪽/뒤로/앞으로/새로고침, 보기 전환(목록/큰 아이콘), 새 가상 폴더, 정렬·필터 메뉴를 둔다.
- **패널**: 기본 1개, 설정에서 1~4개. 각 패널은 독립된 상자·영역·가상 폴더 위치, 보기 방식, 정렬, 검색, 선택, 스크롤 위치를 갖는다. 한 패널만 활성화 테두리·주소줄로 식별한다. 최소 크기 미만이면 분할선 이동을 제한한다.
- **목록 보기**: 이름, 유형, 크기(알 수 없으면 공란), 원본 위치, 수정 시각(알 수 없으면 공란), 상자/영역을 열로 표시한다. 정렬 가능한 헤더, 키보드 선택과 다중 선택을 지원한다.
- **큰 아이콘 보기**: 파일 유형 아이콘과 줄바꿈 이름을 격자로 표시한다. 썸네일은 별도 캐시·성능 설계 카드에서 범위를 정하기 전까지 확정하지 않는다.
- **상태줄**: 활성 패널 항목 수, 선택 수, 현재 위치, 작업 진행/완료 및 오류를 표시한다. 선택 항목의 실제 파일 복사에서는 대상 경로와 덮어쓰기 여부를 명시한다.
- **테마·공용 부품**: 몽땅클립보드(`kagent/src/popup.rs`)와 같은 Rust Win32/GDI·`ui_theme`의 밝게/어둡게/시스템·고대비 감지, `frame.rs`의 창 프레임·DPI·공용 그리기 기초를 재사용한다. 패널 배치·분할선·리스트/아이콘 렌더러·명령줄은 kvf 전용이다. IME 조합 문자열 처리는 기존 직접 입력 경로를 보존한다.

## 2. 1~4 영역 분할과 저장

패널 수와 배치는 직렬화 가능한 `Layout`으로 정의한다. 패널 식별자는 순서와 독립적인 안정 ID를 사용하고, 각 패널은 `PanelState { id, location, view, sort, query }`에 대응한다. 패널 크기는 창 클라이언트 영역 기준 정수 비율(0~10,000 basis points)로 저장하고, 그릴 때 DPI 배율과 최소 크기를 적용한다. 반올림 오차는 마지막 열/행에 더해 전체 합이 정확히 10,000이 되게 한다.

| 패널 수 | 기본 배치 | 크기 저장 |
|---|---|---|
| 1 | 전체 창 | 폭·높이 각각 10,000 |
| 2 | 좌우 분할 | 두 폭 비율, 합 10,000 |
| 3 | 좌우 2열 + 우측 상하 | 좌측 폭, 우측 상·하 높이 비율 |
| 4 | 2×2 격자 | 좌우 열 비율 + 상하 행 비율 |

사용자는 분할선 끌기로 각 분할 비율을 바꾼다. 배치 유형(가로/세로/격자)은 패널 수에 맞는 유효한 템플릿을 고르며, 3패널은 `1+2 가로`, `2+1 가로`, `1+2 세로`, `2+1 세로` 템플릿을 제공한다. 2패널은 좌우/상하, 4패널은 2×2를 기본으로 하고 추후 비대칭 템플릿은 별도 결정한다.

설정은 `%LOCALAPPDATA%\\HwpAutoDocFit\\kvf\\settings.json`에 저장한다. 기존 키(`hotkey`, `tray`, `sticky`, `x/y/width/height`, `last_box`)는 하위 호환을 유지하고 다음 버전 키를 추가한다.

```json
{
  "layout_version": 1,
  "panel_count": 2,
  "layout": "columns",
  "split": { "columns": [5000, 5000], "rows": [5000, 5000] },
  "active_panel": "p1",
  "panels": [
    { "id": "p1", "box_id": 12, "space": "core", "virtual_folder_id": null, "view": "details", "sort": "name_asc" },
    { "id": "p2", "box_id": 12, "space": "basis", "virtual_folder_id": null, "view": "icons", "sort": "name_asc" }
  ]
}
```

잘못되거나 알 수 없는 값은 기본값으로 복구한다. `panel_count`는 1~4만 허용하고, 모든 비율은 양수이며 각 축 합은 10,000이어야 한다. 창 크기와 패널 크기 저장을 분리한다. 설정 저장 실패는 화면 상태줄/알림으로 알리고 기존 설정 파일을 보존한다.

## 3. 영역 간 이동·복제 동작

| 시작 동작 | 대상 | 결과 | 파일 시스템 영향 | 이름 충돌·되돌리기 |
|---|---|---|---|---|
| 같은 창 패널 간 드래그 | 다른 패널/가상 폴더 | 이동(가상 항목의 소속/위치만 변경) | 없음 | 대상 가상 위치에서 이름 충돌 시 `이름 (2).확장자`부터 빈 이름을 배정. 실행취소로 이전 위치·이름 복원 |
| Ctrl+드래그 | 다른 패널/가상 폴더 | 복제(새 가상 항목 ID가 원본 참조를 가리킴) | 없음 | 충돌 이름 자동 부여. 실행취소는 새 가상 항목만 제거 |
| 우클릭 메뉴 > 이동 위치… | 선택한 가상 위치 | 가상 항목 이동 | 없음 | 위와 같음. 이동 완료 후 실행취소 지원 |
| 우클릭 메뉴 > 가상 복사본 만들기 | 선택한 가상 위치 | 가상 항목 복제 | 없음 | 위와 같음. 원본 항목과 원본 파일 불변 |
| 우클릭 메뉴 > 실제 파일 복사… | 사용자가 고른 실제 폴더 | 실제 파일/폴더 복사 후 새 결과를 가상 항목으로 등록 | **있음**, 별도 확인 후 수행 | 기본은 덮어쓰기 금지, 번호 붙임 또는 이름 바꾸기. 복사 완료 전 실패 시 부분 결과 정리, 완료 건은 작업 기록으로 역방향 삭제 제공(파일이 이후 변경됐다면 자동 삭제하지 않고 확인) |
| 동일 패널 안 드롭 | 같은 가상 위치 | 순서만 바꾸거나 no-op. 정렬이 이름/날짜 기준이면 수동 순서 기능을 선택할 수 없음 | 없음 | 실제 위치 이동으로 취급하지 않음 |

드래그는 기본 이동, Ctrl을 누르면 복제한다. 메뉴에는 동작을 명시적으로 선택할 수 있게 한다. `Shift` 동작은 예약하지 않는다. 원본 참조 항목과 사용자가 만든 복제본은 모두 별도 가상 ID를 가진다. 이동은 ID의 위치 필드만 바꾸고 복제는 원본 참조를 가진 새 행을 만든다. 실제 파일 복사는 가상 이동·복제와 분리된 명령이며, 확인창에서 원본 경로·대상 경로·항목 수를 보여 준다.

되돌리기 기록은 kvf 전용 작업 저널에 순서대로 쌓고 창 세션 간 보존한다. 레코드는 작업 ID, 명령 종류, 대상 가상 ID, 전/후 위치·표시 이름, 실제 복사 작업의 생성 경로와 완료 상태를 담는다. 우선 최근 작업 100건 또는 30일 보관 중 더 작은 범위로 제한하고, 영구 보장 용량은 구현 카드에서 정한다. 되돌리기/다시 실행은 UI 상태가 아니라 저장소 트랜잭션으로 처리한다.

## 4. 외부 끌어 놓기

**권장 경로: OLE `IDropTarget` 등록.** 파일 탐색기와 바탕 화면은 셸 파일 끌기를 OLE `IDataObject`의 `CF_HDROP`로 제공한다. 창이 실제 폴더 같은 탐색기 동작(복사/이동 피드백, 여러 항목, 향후 확장)을 제공하려면 OLE 경로가 적합하다. Win32 창 스레드에서 `OleInitialize`/`OleUninitialize` 생명주기를 맞추고, `RegisterDragDrop`/`RevokeDragDrop`을 창 생성·파괴와 연결한다. `IDropTarget::DragEnter/DragOver/DragLeave/Drop`은 드롭 위치에서 패널 ID를 찾아 강조 표시하고, `CF_HDROP`의 모든 경로를 수집해 별도 이벤트로 전달한다. 현재 저장소에서 OLE 드롭 타깃 구현은 확인되지 않았다. 몽땅클립보드 `clip.rs`의 `CF_HDROP` 클립보드 처리와는 별개다.

`WM_DROPFILES`는 `DragAcceptFiles`와 `HDROP`만으로 MVP를 단순화할 수 있지만, OLE 기본 동작의 효과 피드백·확장성과 끌기 중 대상 강조가 제한된다. 첫 카드에서 COM 인터페이스 구현·등록의 비용을 확인하되, OLE가 공용 유틸로 흡수될 정도로 복잡하더라도 kvf 화면 이벤트와 분리된 얇은 어댑터로 둔다. 구현이 막힐 때만 `WM_DROPFILES`로 MVP를 내고, 선택한 경로와 제약을 문서화한다.

드롭 시 파일과 폴더 모두 허용하며 여러 경로를 한 번에 처리한다. 기본 동작은 실제 파일을 복사하지 않고 **외부 경로를 참조하는 가상 항목 추가**다. 선택적 메뉴/확인으로 실제 복사도 가능하게 하되 기본 드롭 동작과 구분한다. 폴더 드롭은 폴더 자체를 하나의 항목으로 등록하고 재귀 복사는 사용자가 실제 복사를 선택한 경우에만 수행한다. 존재하지 않거나 접근할 수 없는 경로는 항목별 실패로 보고하며 성공한 나머지 항목은 추가한다. 같은 파일의 중복 등록은 기본적으로 허용하되, 동일 가상 위치의 경로 중복 경고를 제공한다. 네트워크/이동식 경로는 참조 가능하나 오프라인일 때 끊어진 참조 표시를 한다.

## 5. 상태 기계와 시험 계획

기존 `vf_state::Model`의 창 수명주기(`Hidden/Loading/List/Search/Empty/Failed/Minimized`)와 비동기 `seq` 검증은 유지한다. `Context { box_id, space, query, selection }`를 단일 패널 상태로 확장해 활성 패널 ID와 패널별 context/view/sort/selection을 저장한다. 기존 단일 패널은 `panel_count=1`, 안정 ID `p1`로 마이그레이션한다. 새 View 이름을 전부 새로 만드는 대신 기존 View는 데이터 읽기 상태로 쓰고, 상위 `Explorer` 상태에 현재 패널 구성·주소 탐색·드래그·작업 기록을 둔다.

추가 이벤트: `SetLayout`, `ActivatePanel`, `Navigate`, `SetViewMode`, `BeginDrag`, `DragOver`, `DropInternal { source_panel, item_ids, target_panel, ctrl }`, `DropExternal { target_panel, paths }`, `RequestMove`, `RequestVirtualCopy`, `RequestRealCopy`, `Undo`, `Redo`, `OperationCompleted { seq, result }`. 추가 효과: `LoadPanel`, `PersistLayout`, `PersistVirtualOperation`, `CopyFiles`, `RegisterDropTarget`, `RevokeDropTarget`, `Draw`. 상태는 다음과 같다.

```text
Hidden --Call--> Loading(panel snapshots) --Loaded--> Explorer(1..4 panels)
Explorer --query/view/navigation/layout--> Explorer
Explorer --drag begin/over/drop--> Dragging -> OperationPending -> Explorer
Explorer --external Drop--> ImportPending -> Explorer (+ per-item result)
Explorer --Undo/Redo--> OperationPending -> Explorer
Explorer --Close/Outside/Hotkey toggle--> Hidden
Explorer --Minimize--> Minimized(Explorer snapshot)
```

DB 읽기·설정 파일·파일 복사·저장소 변경은 기존 원칙대로 상태 전이 함수 밖의 effect executor에서 수행한다. 작업은 `seq`와 operation ID로 완료를 짝지어 창 닫기·취소·늦은 결과에 대한 stale 응답을 무시한다. 여러 실제 파일 복사는 UI 스레드를 막지 않는 worker에서 처리하고 진행률/취소는 별도 카드에서 구체화한다. 저장소 쓰기는 한 번의 트랜잭션으로 커밋하고, 작업 저널과 가상 항목 변경을 원자적으로 묶는다.

시험 계획(구현 카드에서 추가):

- 순수 모델 단위 시험: 기존 상태 전이 전부 유지, 1~4 패널 전환·3패널 템플릿·비율 정규화·활성 패널 제거/추가·패널별 검색/선택 격리.
- 레이아웃 설정 시험: 기존 설정 파일 읽기, 새 형식 왕복, 잘못된 패널 수/ID/비율/버전 복구, DPI·모니터 변경 시 패널 최소 크기와 합계 유지.
- 가상 작업 저장소 시험: 이동/복제 후 원본 DB 바이트 불변, 중복 이름 번호 부여, ID·참조 보존, 트랜잭션 실패 rollback, undo/redo 및 재시작 후 저널 복원.
- 외부 경로 시험: 단일·다중 파일/폴더, 한글·공백·긴 경로, 사라진 경로·접근 거부 혼합, 드롭 좌표별 패널 지정, drop target 등록/해제와 중복 등록 방지.
- 실제 복사 시험: 복사 성공, 이름 충돌, 취소/중단, 부분 실패, undo 안전 확인, 원본 파일 해시 불변. 테스트 디렉터리 사본만 사용한다.
- UI 실기 시험: Windows 10/11, 100/150/200% DPI, 시스템/밝게/어둡게·고대비, 1~4 분할, 키보드/IME/다중 선택, 탐색기에서 여러 파일·폴더 드롭, 내부 이동·Ctrl 복제·메뉴·실제 복사·undo/redo, 트레이/단축키/고정/최대화 복귀.

## 6. 구현 단계 (최대 4 카드)

1. **QVF-EXPLORER-1 — 저장 모델·레이아웃·상태 기계**: 전용 가상 항목 저장소와 작업 저널의 형식/마이그레이션을 확정하고, 1~4 패널·배치·패널별 문맥을 순수 상태로 구현한다. 기존 `library.db` 읽기 전용 보장을 자동 시험한다.
2. **QVF-EXPLORER-2 — 탐색기 화면·설정**: 주소줄, 목록/큰 아이콘, 상태줄, 패널 분할선, 테마, 창 크기·배치 저장을 구현한다. 기존 단일 패널 설정과 입력/IME/단축키 흐름을 유지한다.
3. **QVF-EXPLORER-3 — 내부 이동·가상 복제·undo/redo**: 드래그/Ctrl 드래그/메뉴, 충돌 이름 처리, 원자적 저장·저널·되돌리기를 구현한다. 기본 작업에서 파일 시스템 쓰기가 없음을 검증한다.
4. **QVF-EXPLORER-4 — 외부 드롭·선택적 실제 복사**: OLE `IDropTarget` 다중 파일·폴더 추가, 항목별 오류 표시, 명시적 실제 복사 확인·취소·복구를 구현하고 Windows 실기 매트릭스를 마친다.

## 미결정 사항

- 사용자 가상 폴더의 저장 UX(패널 상태만 저장할지, 이름 있는 폴더 트리와 즐겨찾기도 제공할지)는 데이터 모델 카드에서 확정한다. 이 문서는 이름 있는 사용자 가상 폴더와 저장 가능한 가상 항목 위치를 전제로 한다.
- 3패널 기본 템플릿은 좌측 1 + 우측 2로 제안했으며, 최초 구현에서 네 템플릿 모두 지원할지 구현 카드에서 판단한다.
- 썸네일, 실제 복사 취소의 파일별 동작, 작업 저널 보관 용량은 성능·오류 복구 요구를 확인해 QVF-EXPLORER-1/4에서 정한다.
