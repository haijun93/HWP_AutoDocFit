# EFF5 — 「한 번에 적용」 중복 방문 줄이기

작성: 2026-11-27 · 브랜치: `feature/EFF5`(`feature/EFF4` 위) · 로컬 커밋만, 푸시 없음.

## 판정

- **E03(대상 필터가 있어도 전체 순회): 사실.** 재검사 대상이 정해진 순회만 줄였다. 합성 문서에서 결과 차이는 0이고, 전체 COM 호출은 -0.7~-2.8%(재검사가 없으면 0%)로 작다. 시간 개선은 확인하지 못했다.
- **E04(한 칸 표를 두 번 처리): 사실. 고치지 않았다.** 두 번째 방문은 같은 읽기의 반복이 아니라 「다음 단어 당김」을 다시 시도하는 별도 처리라서, 빼도 결과가 항상 같다고 증명하지 못했다.

## 코드 확인

### E03

- `문단_내어쓰기_전체_갱신(대상문단=…)`: 대상이 있어도 붙임 번호 수집(전 문단) 뒤 본문 전체를 다시 돌고, 계산 직전에만 걸렀다.
- `본문_기존자간조정`·`본문_문장부호_처리`: 2차 이후 재검사에서 대상이 아닌 문단을 문서 끝까지 이동하며 건너뛰었다.
- `컨트롤_내부_자간조정`·`컨트롤_내부_문장부호_처리`: 한 칸 표 조사(자간 쪽은 서식 표 보호 조사 포함)를 한 뒤 영역마다 걸렀다. 2차 이후 대상은 본문 순회에서 모은 문단이라, 실제 흐름에서는 걸러지고 남는 칸이 없었다.

### E04

`한칸표_자간조정`(서식 단계) 뒤 `컨트롤_내부_자간조정`이 같은 영역을 같은 한도(본문 한도)로 다시 처리한다. 다만 `단어중간_줄바꿈방지`의 「다음 단어 당김」 1회 제한은 **방문마다** 적용되므로, 두 번째 방문은 새 시도를 할 수 있다. 또 두 방문 사이에 문서를 바꾸는 단계들이 있어, 영역별로 "바뀐 것이 없다"를 확정할 기록이 없다.

## 변경 (E03)

- 새 보조 `본문_대상_지남(대상, 위치)`: 본문 순회가 마지막 대상 문단을 지나면 멈춘다. 내어쓰기 갱신·본문 자간·본문 줄 병합에 적용. 멈출 때 `MoveDocEnd`로 커서를 전처럼 문서 끝에 둔다.
- 내어쓰기 갱신: 본문 대상이 하나도 없으면 수집·순회를 하지 않는다. 대상이 있으면 붙임 번호 수집은 전처럼 전 문단을 읽는다(부모 문맥 누락 방지).
- 새 보조 `재검사_본문뿐인가()`: 2차 이후 대상에 칸 문단이 없으면 컨트롤 두 단계는 표를 조사하지 않고 끝낸다. 칸 대상이 하나라도 있으면 기존대로다.
- 전수 검사(1차, `대상 None`)의 처리 대상·순서는 바꾸지 않았다.
- 대상 문단으로 바로 `SetPos` 이동하는 방식은 적용하지 않았다(위치 유효성·붙임 문맥 위험). 마지막 대상 **앞**의 문단은 전처럼 지나간다.

- 작업 방식 `spacing`·`all`(표준서식), 전(`34b10e8c` 사본)·후 각 2회, 총 24회. 모두 저장 성공, 오류 0, 원본 불변.

### 본문 순회가 칸에 들어가지 않는지

저장한 합성 문서 3종(표·각주)과 저장소의 글상자 서식 시험 파일 2종을 새로 열어 `MoveParaEnd`/`MoveLineEnd` + `MoveNextChar` 순회를 돌렸다. 들른 목록은 모두 본문(0)뿐이었고 문단 번호는 줄지 않았다. 표 칸·각주·글상자는 별도 목록 번호였다. 글상자 파일 2종은 본문이 1문단뿐이다.

## E04 실험 (코드에 반영하지 않음)

전 코드에서 컨트롤 순회가 한 칸 표를 건너뛰게 실행 중에만 바꿔 비교했다.

| 문서(all) | COM 호출 전 → 건너뜀 | 글·글자 모양·문단 모양 | section XML |
|---|---|---|---|
| single | 16,721 → 12,668 (-24%) | 차이 0 | 동일 |
| mixed | 61,841 → 59,759 (-3.4%) | 차이 0 | 동일 |
| pull(짧은 단어가 많은 한 칸 표, 1회) | 65,180 → 38,016 (-42%) | 차이 0 | **다름**: 서식이 같은 글자 구간 나뉨 2곳 |

- pull 문서에서 「다음 단어 당김」 시도는 75건 → 36건, 적용은 양쪽 8건. 두 번째 방문은 첫 방문에서 당긴 줄을 남은 한도(1단계)로, 일부 줄은 첫 방문에 없던 단어를 다시 시도했다. 이번에는 모두 실패해 원복했다.
- 즉 절감 여지는 크지만, 두 번째 시도가 성공하는 문서에서는 결과가 달라진다. 세 문서에서 같았다는 것은 증명이 아니므로 기존대로 두었다.
