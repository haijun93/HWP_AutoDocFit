# INDENTW2 결과 — 한/글 실측으로 폭 계산 보정

- 브랜치 `feature/INDENTW2`(`feature/INDENTW1` 병합). 로컬 커밋만, 푸시 안 함.
- 사용자 결정(2026-11-26): 공문 글꼴은 기본안대로, 한/글 방식(`ParagraphShapeIndentAtCaret`) 대비 0.5pt 이내.
- **앱의 내어쓰기 동작은 바꾸지 않았다.** 보정한 계산(`docfit_core/font_widths.py`)은 아직 어디에도 연결되지 않았다.

## 실측 방법

- 도구: `scripts/measure_indent_hangul.py`. 합성 HWPX 를 만들어 **새 한/글 인스턴스**(최소화 창)로 열고, 앱의 `문단_내어쓰기_적용` 과 같은 순서로 `ParagraphShapeIndentAtCaret` 를 값이 멈출 때까지 실행한다.
- 한/글 버전: **9.6.1.10778(한컴오피스 NEO)** — 이 PC 에 설치된 것. 한/글 2020 이상에서는 재지 않았다.
- 본문 폭 42520 HWPUNIT(A4, 좌우 8504).
- COM `ParaShape` 여백 값은 HWPUNIT 의 2배였다.
- COM 잠금을 잡고 실행했고, 전체 시험 잠금이 있는 동안은 기다렸다. 합성 문서만 열었다.
- 한 번은 작업자가 건 500초 제한에 걸려 스크립트가 강제 종료되어 한/글 프로세스와 COM 잠금이 남았다. 창 제목이 이 작업의 합성 문서임을 확인하고 그 프로세스만 종료한 뒤 자기 잠금을 지웠다.

## 한/글의 폭 계산 규칙(실측)

```
s     = floor(크기 × 상대크기 / 4)                  # 4 HWPUNIT 격자
폭    = round(s × 글자폭em)                          # 장평 100%
      = floor(s × 글자폭em × 장평)                   # 장평 100% 아님
      = round(floor(s × 0.5) × 장평)                 # 고정 빈칸
자간  = round(폭 × 자간%)                            # 0.5 는 0 에서 먼 쪽
글자  = (폭 + 자간) × 4
```

### INDENTW1 의 미확인 가정

| 가정 | 실측 결과 |
|---|---|
| 자간은 글자 크기의 % | **틀림.** 장평 적용 글자 폭의 % |
| 고정 빈칸에도 장평·자간 적용 | 맞음. 단 장평은 **한글 칸**, 자간은 **영문 칸** |
| `·` 는 기호 칸 | **틀림. 영문 칸**(U+0080~00FF 전체와 `‘’“”` 도 영문 칸, 그리스·키릴은 기호 칸) |
| 굵게면 굵은 글꼴 폭 | **틀림.** TTF 는 굵게여도 폭이 같다 |
| 반올림은 합계에만 | **틀림.** 글자마다 4 HWPUNIT 격자로 정수화 |
| 빈칸은 영문 칸 | 글꼴 빈칸 옵션이 켜지면 영문 칸 전체, 꺼지면 위 고정 빈칸 규칙 |

### 그 밖에 확인한 것

- 고정폭 빈칸(`hp:fwSpace`) 0.25em(크기·장평 한글 칸, 자간 영문 칸). 묶음 빈칸(`hp:nbSpace`) 0.5em, 자간 없음.
- **HFT 는 굵게면 넓어진다**(대체로 em 의 5%. 대체 글꼴로 그려지는 글자는 그대로). 25종 글자별로 실측해 표에 넣었다.
- 글꼴 빈칸 옵션 + 굵게: 휴먼명조·HY헤드라인M·한컴돋움·HY견고딕은 빈칸이 조금 좁아진다.
- HFT 의 글꼴 빈칸 폭: 0.5em / 0.4em / 0.333em(글꼴마다 다름). 한글 음절은 표본 폭이 글꼴 안에서 모두 같아 전체에 적용했다(전 음절을 재지는 않았다).
- **HY헤드라인M 은 설치본이 둘**(Windows 글꼴 폴더, 한/글 폴더)이고 `*` `-` `.` 폭이 다르다. 한/글은 Windows 설치본을 썼다. 생성 스크립트도 Windows 설치본을 우선한다. Windows 설치본이 없는 PC 는 값이 다를 수 있다.

### 양쪽 정렬

- 기준 위치까지의 폭에 첫 줄이 늘어난 몫이 더해진다. 내어쓰기는 둘째 줄부터라 첫 줄 배치는 적용 뒤에도 같다.
- 남는 폭 = 첫 줄 폭 − 줄 안 글자 폭 합(줄 끝 빈칸 제외) + **줄 끝 글자의 자간**.
- 남는 폭을 **문두 빈칸을 뺀** 첫 줄 안의 빈칸에 똑같이 나눈다.
- 줄 맞춤도 마지막 글자의 자간을 빼고 판단한다. 금칙(줄 머리 `.,)」` 등, 줄 끝 `(「` 등)과 영문·숫자 낱말 붙임을 적용한다.
- HWPX `breakNonLatinWord`: `KEEP_WORD` = 한글 **글자** 단위, `BREAK_WORD` = **어절** 단위로 동작했다.

### 함초롬바탕 `☞ ` 1.59pt 차이(INDENTW1)

한/글 실측은 2268 HWPUNIT 로 계산과 같다. 서식 예시에 저장된 2427 은 현재 글자 모양의 Shift+Tab 값이 아니다. 즉 **계산 오차가 아니다.** 2427 이 어떻게 저장됐는지는 알아내지 못했다. `◈ ` 의 저장값 1648 도 현재 크기(13pt, 계산 1888~1948)와 맞지 않는다(파일은 열어 재지 않았고, 같은 글자 모양의 계산값과 비교한 것이다).

## 남은 문제

1. **앱에 연결되지 않았다.** 연결할 때 호출 쪽에서 문단의 글자 모양(런), 첫 줄 폭, 줄 나눔 설정, `hp:fwSpace`·`hp:nbSpace` → `FW_SPACE`·`NB_SPACE` 변환을 넘겨야 하고, `None`·`exact == False` 일 때는 한/글 Shift+Tab 으로 돌려야 한다.
2. 검증하지 않은 것: 한/글 2020 이상, 탭, 문단 최소 빈칸(condense) ≠ 0, 커닝, 글자 위치(offset)·첨자·외곽선 등 그 밖의 글자 효과, 표 칸·글상자 안, 자동 문단 번호·글머리표, `breakLatinWord` 가 낱말 유지가 아닌 설정, 격자 맞춤.
3. 한자는 TTF 표에 거의 없어 어림(`exact == False`)한다. 표에 없는 글꼴은 `None`.
4. 양쪽 정렬 첫 줄에 늘릴 빈칸이 없으면 `None`(글자 사이 분배 규칙은 확인하지 않음).
5. 글꼴 판(버전)이 다른 PC 는 폭이 다를 수 있다(HY헤드라인M 에서 확인).
