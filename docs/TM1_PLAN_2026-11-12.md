# TM1 계획: 타임머신을 단축키로 부르는 독립 앱 `ktm.exe` (2026-11-12)

조사는 `docs/TM1_RESEARCH_2026-11-12.md`. 기준 커밋 `954fd16f`, 브랜치 `feature/timemachine-popup`. 설계만 담는다(코드 변경 없음).
표기: **확인**(이번에 읽음) · **추정**(계산·다른 실측에서 낸 값) · **미확인**(안 읽음·실기 필요).

## 0. 범위와 제약

### 넣는 것(1차, 단계 T0~T11)
- 별도 실행 파일 `ktm.exe`(사용자 권한). 단축키·트레이·`ktm.exe` 실행으로 부르는 창. 앱 본체·Python·kagent·kvf가 꺼져 있어도 동작.
- 창 한 개, 검색 칸 하나: **통합(이름+본문)·파일명·본문·위계·타임라인** 다섯 칸. 입력 즉시 결과, 키보드만으로 조작.
- 미리보기 칸: 일치 문장 + 앞뒤 문단(색인에 있는 글) + 위계 경로. 문서를 열지 않는다.
- 열기·탐색기에서 위치 열기·경로 복사·"앱에서 자세히"(앱 타임머신 화면으로 넘기기).
- 색인을 **스스로 최신으로 유지**: 바뀐 파일 감지 → 별도 작업 프로세스로 추출·색인(견고성 요건 1).
- 명시적 상태 기계(프로세스·창·검색 세션·색인 가용성), `status.json`, 설치·자동 실행·교체·끄기.

### 빼는 것(2차 이후, 설계만 또는 앱에 남김)
- 연관 문서(Python `related.py`·`series.py` 규칙, 사용자 '관련 없음' 표) → 2차 T12(Rust 이식). 1차에는 "앱에서 연관 문서 보기"로 넘김.
- 썸네일(Python `thumbs.py`, 형식별 디코더) → 앱에 남김.
- 보내기(이름 바꾸기·변환·문서 편집), 조사 폴더·확장자 설정, 본문 색인 관리 화면, Markdown 내보내기 → 앱에 남김.
- 정규식(IS1 Q6), 한/글 COM이 필요한 추출(창 앱은 COM을 쓰지 않는다).
- 드라이브 전체 **본문** 색인(본문은 지금처럼 조사 폴더만, IS1 §1).

## 1. (가) 프로세스 구성

### 1-1. 셋 중 무엇으로 나눌지

| 기준 | P1. `ktm.exe` 하나에 창+파일명 색인(MFT)+본문 색인 | P2. **kfind 서비스(관리자) + `ktm.exe` 창·질의(사용자) + 작업 프로세스(사용자)** (권고) | P3. 창은 kvf에 칸으로 합치고 색인은 kfind |
|---|---|---|---|
| 관리자 권한 | MFT 때문에 창 프로세스 전체가 관리자. 켤 때마다 UAC(또는 예약 작업) | kfind 설치 때 UAC 1번. 창은 일반 권한 | P2와 같음 |
| UAC | 매 실행·자동 실행 때 문제 | 1번 | 1번 |
| 끌어 놓기(UIPI) | 관리자 창 ↔ 탐색기·한/글 끌어 놓기 막힘 | 됨 | 됨 |
| 한/글 연동 | 관리자 창에서 연 한/글이 관리자로 떠 기존 한/글·앱 COM과 무결성 수준이 갈림(미확인, 위험 큼) | 창이 연 문서는 일반 권한 한/글로 열림 → 앱 COM과 같은 수준 | 같음 |
| 공격면 | 문서 파서·창·MFT가 한 관리자 프로세스 | SYSTEM 코드는 이름 열거·질의뿐(IS1 §2.2), 파서는 사용자 권한 작업 프로세스 | 같음 |
| 메모리(숨김) | MFT 색인(80MB/100만)이 늘 창 프로세스에 | 창 1.6MB 목표, 이름 색인은 kfind 몫 | kvf에 붙어 kvf 목표(1.5MB)가 깨짐 |
| 견고성 | 파서 패닉·무한 루프가 창·색인을 함께 멈춤 | 작업 프로세스만 죽고 다시 뜸 | 같음 |
| 기존 결정과 | IS1 §2.2 A안(기각)과 같은 문제 | IS1·VF1B와 일치(책임마다 exe, UI는 일반 권한) | VF1B "가상 폴더 창은 별도 exe"와 어긋나고 kvf 브랜치를 다시 연다 |

**권고 P2.** kvf와는 **합치지 않고 따로 둔다**(Q3에서 확인): kvf는 읽기 전용 `library.db` 목록 창이고 ktm은 색인·감시·작업 프로세스를 가진 검색 창이라 수명·자원·실패 양상이 다르다. 대신 코드는 kvf와 같은 P2(파일 공용 `#[path]`)로 같이 쓴다. 합쳐서 얻는 이득(상주 1.5MB 절약, 트레이 하나)은 Q3의 대가로 적는다.

### 1-2. 프로세스별 책임

| 프로세스 | 권한 | 수명 | 하는 일 | 하지 않는 일 |
|---|---|---|---|---|
| `kfind.exe`(IS1 소관) | SYSTEM 서비스 | 부팅~종료 | 드라이브 전체 이름 색인, USN 따라잡기, 파이프 `query`·`cancel`·`status`·`path_of`. **TM1이 요청할 추가 명령 1개**: `changes_since{cursor, roots}`(조사 폴더 아래 바뀐 경로 목록, 막힘 대기 가능) — IS1 S3에 넣을 것(Q5) | 파일 내용 읽기, 창 |
| `ktm.exe` | 사용자 | 로그인~로그오프(자동 실행 시) | 창·단축키·트레이, 질의 스레드(본문 `kfind-core` 읽기, 타임라인 메모리 거르기, kfind 파이프 클라이언트), 변경 감지 스레드, 작업 프로세스 관리(띄우기·상한·재시작) | 문서 파싱(작업 프로세스로), COM, 관리자 작업 |
| 작업 프로세스 `klib.exe index-content`(또는 `ktm.exe --worker`, (가)-3) | 사용자, Job Object로 상한 | 바뀐 파일이 있을 때만, 다 하면 끝남 | 추출 → 문장 나누기 → `kfind-core` 세그먼트 쓰기 | 창, 상주 |

### 1-3. 작업 프로세스: klib.exe 재사용 vs ktm 안 추출기

| 기준 | W1. `klib.exe index-content`를 ktm 폴더에 함께 설치 (권고) | W2. ktm.exe에 추출기를 넣고 `--worker`로 자기 자신을 띄움 |
|---|---|---|
| 중복 | 없음(앱과 같은 추출·같은 색인 형식 — IS "동시 교체" 결정과 일치) | klib `extract.rs`(705줄)를 `#[path]`로 공용하거나 복사 |
| ktm.exe 크기 | 1.0MB 목표 유지 | 추출 의존성(zip·XML 파서 등)으로 크게 늘 것(미확인) |
| 설치 | klib.exe를 ktm 자료 폴더에 복사(+`.sha256`) — kvf V11과 같은 문제를 **같은 방법으로** 푼다(Q4) | 없음 |
| 버전 맞춤 | 앱 꾸러미가 klib·ktm을 같이 실어 `--upgrade-if-stale`로 함께 교체 | 저절로 맞음 |

권고 W1. klib.exe 크기·시작 시간(C5)이 크면 W2로 바꾼다(T0에서 판정: klib.exe 시작~첫 파일 추출 300ms 이하면 W1).

### 1-4. 쓰는 쪽이 하나여야 하는 것(단일 쓰기)

| 자료 | 지금 쓰는 쪽(확인) | TM1 1차 | 근거 |
|---|---|---|---|
| `timeline.db` | kagent(맡았을 때) 또는 앱 `scan_roots` | **ktm은 읽기만**(kvf C1과 같은 읽기 전용 열기). 둘 다 꺼져 있어 오래되면 화면에 "타임라인 갱신: n분 전" 표시 | 쓰는 쪽을 셋으로 늘리지 않는다. ktm이 쓰는 쪽을 넘겨받는 안은 Q6(2차, `timeline.rs`·`watch.rs` `#[path]` 공용으로 가능 — 두 파일은 `crate::sqlite`·`crate::util`만 씀, 확인) |
| 본문 색인(`kfind-core` 세그먼트, IS S5 이후) | (아직 없음) klib가 쓸 예정 | 쓰기는 **klib 작업 프로세스만**. 누가 띄우든(앱·ktm) 이름 있는 뮤텍스 `Local\HwpAutoDocFit.kfindcore.writer`를 잡은 쪽만 쓴다. 못 잡으면 대기열에 넣고 다음 기회 | 앱과 ktm이 동시에 색인해도 깨지지 않게 |
| 옛 `timeline-content.sqlite` | 앱(Python·klib) | ktm은 **열지 않는다** | 새 엔진으로 동시 교체(IS 결정). 교체 전 기간은 (바)의 "앱에서 자세히"로 |

### 1-5. 변경 감지(자동으로 동작)

| 순서 | 원천 | 조건 | 비용 |
|---|---|---|---|
| 1 | kfind `changes_since`(USN) | kfind가 `ready` | 막힘 읽기 1개, 유휴 CPU 0. 꺼져 있던 동안의 변경도 따라잡음(USN 커서를 ktm 상태에 저장) |
| 2 | `ReadDirectoryChangesW`(kagent `watch.rs` `#[path]` 공용) | kfind 없음·멈춤 | 조사 폴더마다 핸들 1개, 완료 포트 스레드 1개(유휴 0). 넘침이면 그 폴더 mtime 비교 다시 훑기 |
| 3 | 시작 때 mtime·크기 대조 | 로그인 자동 실행 직후 1회(`--delay 30` 뒤) | 꺼져 있던 동안의 변경(1이 없을 때) |

바뀐 파일 → 대기열(중복 제거, 400ms 모음) → 작업 프로세스 1개(`BELOW_NORMAL`·I/O 낮음 우선순위). 사용자가 창에서 입력 중이면 작업 프로세스를 띄우지 않고 창이 숨은 뒤 띄운다(입력 지연 보호). 앱이 본문 색인을 돌리는 중(쓰기 뮤텍스 보유)이면 ktm은 기다린다. **이 자동 색인을 기본으로 켤지는 Q7**(사용자가 모르는 CPU 사용).

## 3. (다) 창 상태 기계와 화면

### 3-1. 화면(몽땅클립보드 방식)
- 단축키 → **마우스가 있는 모니터, 마우스 옆**에 뜬다(작업 영역 밖으로 나가지 않게 보정). 붙박이면 기억한 자리.
- 위에서 아래: ① 머리글 '타임머신' + 항상 위·최소화·최대화·닫기(kagent `frame.rs` 공용, 46px 캡션 단추) ② 칸 줄: 통합·파일명·본문·위계·타임라인(←→·Tab) ③ **검색 칸(늘 포커스, 한글 조합 중 글자도 질의)** ④ 결과 목록(종류 표시·이름·폴더·날짜·일치 문장 한 줄, 일치 낱말 굵게) ⑤ 미리보기 칸(오른쪽, Space·→로 열고 닫음, 창이 좁으면 아래) ⑥ 상태 줄 한 줄: 결과 수·걸린 ms·색인 상태(예: "본문 3,012문서 · 2분 전 갱신", "드라이브 전체 꺼짐").
- 기본 크기 640×440(배율 적용), 최소 440×300.

### 3-2. 키(키보드만으로)
| 키 | 동작 |

### 3-3. 상태(대원칙: 값으로 두고 순수 함수 한곳에서 전이)

네 층. 창 코드는 사건을 만들고 '할 일'을 실행할 뿐 상태를 직접 바꾸지 않는다(kvf `vf_state::step`과 같은 방식).

**① 프로세스 `Proc`** — kvf와 같음: `NotRunning → Starting → Resident(View) → Exiting`. 인자 `(없음)`·`--hidden [--delay N]`·`--reload`·`--quit`·`--status`·`--install`·`--enable [--autostart]`·`--upgrade-if-stale`·`--disable`·`--show-query <글>`(앱의 "작은 창으로" 단추용). 둘째 실행은 `AllowSetForegroundWindow` 뒤 창 메시지만 보내고 끝남.

**② 창 `View`**
| 상태 | 뜻 | 메모리 |
|---|---|---|
| `Hidden{warm}` | 안 보임. `warm`=색인을 아직 쥐고 있음(숨긴 뒤 한 번짜리 타이머 전) | warm이면 엔진 핸들 유지, 아니면 없음 |
| `Opening` | 부름 받음, 색인·타임라인 여는 중(목표 30ms) | |
| `Ready{tab, ctx}` | 검색 칸 빈 글자. 타임라인 칸이면 오늘 목록, 다른 칸이면 최근 검색어 | |
| `Search{tab, ctx, session}` | 글자 있음. `session`은 ③ | |
| `Empty{tab, reason}` | 색인 없음·조사 폴더 없음·결과 0 | |
| `Failed{reason}` | 색인 손상·시간 초과·kfind 오류 등 | |
| `Minimized(이전)` | 숨겼지만 칸·글자·선택 유지 | |

**③ 검색 세션 `Session`**(IS1 §2.7과 같은 이름) — `Idle`·`TooShort`(본문 칸 1글자)·`InFlight{id, phase, pending?}`·`Partial{id, phase}`(`names`·`top`)·`Complete{id, total, ms}`·`Failed{id, reason}`. 낡은 `id` 응답은 버린다.

**④ 색인 가용성 `Availability`**(IS1 `IndexAvailability` + 타임라인·작업 프로세스)
| 하위 | 상태 |
|---|---|
| 파일명 | `DriveOff`·`DriveBuilding(%)`·`DriveReady`·`DriveRebuilding(볼륨)`·`DriveUnavailable(이유)` |
| 본문 | `ContentNone`·`ContentBuilding(n/m)`·`ContentReady{gen}`·`ContentStale{pending}`·`ContentRuleUpgrade`(NFC·문장 규칙 판 바뀜) |
| 타임라인 | `TimelineFresh{writer}`·`TimelineStale{age}`(쓰는 쪽 kagent·앱 둘 다 없음)·`TimelineMissing` |
| 작업 프로세스 | `WorkerIdle`·`WorkerRunning{pid, file, since}`·`WorkerBackoff{until, reason}`(연속 실패 시 지수 대기)·`WorkerDisabled`(Q7 꺼짐) |

전이(요약, 시험은 표 한 줄에 하나):
| 지금 | 사건 | 다음 | 할 일 |
|---|---|---|---|
| `Hidden{*}` | 부름 | `Opening` | 창 보이기(처음이면 만들기), cold면 색인 열기 |
| `Opening` | 열림 완료 | `Ready` 또는 `Empty` | 그리기 |
| `Opening` | 열기 실패·패닉 | `Failed` | 오류 기록 |
| `Ready`·`Search` | 글자 | `Search{InFlight}` | 질의 스레드에 세대+1로 보냄 |
| `Search{InFlight}` | 글자 | 그대로(`pending` 갱신) | 앞 질의 취소 신호 |
| `Search{InFlight}` | 결과(같은 id, 단계) | `Partial`/`Complete` | 그리기, `pending`이 있으면 새 id로 보냄 |
| `Search{*}` | 글자 모두 지움 | `Ready` | |
| 보이는 상태 | Enter | 붙박이면 그대로, 아니면 `Hidden{warm}` | 열기. 파일 없으면 상태 유지 + 알림 |
| 보이는 상태 | Esc(빈 글자)·바깥 클릭(붙박이 아님) | `Hidden{warm}` | 한 번짜리 타이머(기본 5분, Q8) |
| `Hidden{warm}` | 타이머 | `Hidden{cold}` | 엔진 핸들·목록·비트맵 캐시 내려놓기(`EmptyWorkingSet` 포함) |
| `Search{InFlight}` | watchdog 시간 초과(2초) | `Search{Failed(시간 초과)}` | 질의 세대 무효, 로그 |
| 아무 상태 | `Availability` 변화 | 그대로 | 상태 줄만 다시 그림 |

## 8. 남는 위험
- TM1의 핵심 단계(T4·T5·T8)가 아직 없는 IS1 S2·S3·S5·S6에 걸린다. 늦어지면 ktm 1차는 "타임라인 + 타임라인 이름 찾기"만으로 먼저 낼 수 있다(T1~T3·T6·T7·T9) — 총괄 판단.
- `kfind-core` 증분 세그먼트·쓰기 잠금이 IS S5 계획에 아직 명시돼 있지 않다(IS-S1 "다음 단계"로만 기록). Q5로 IS 쪽에 요청.
- 앱이 켜져 있지 않으면 `timeline.db`가 갱신되지 않는다(1차). 사용자가 "자동으로 동작"을 타임라인까지 기대하면 Q6을 앞당겨야 한다.
- 서명 없는 새 상주 exe + 작업 프로세스(klib.exe)가 보안 프로그램에 막힐 수 있다(C9).
- 화면 측정기의 해상도는 화면 갱신 주기(60Hz면 16.7ms)에 묶인다. 20ms 목표 판정은 `query.log`의 내부 시각과 함께 본다.
- 상주 프로그램이 셋(kagent·kvf·ktm) + 서비스(kfind)가 된다. 트레이 아이콘 셋. 합치는 안은 Q3.
