- `ktm.exe`(사용자 권한): 단축키·트레이·실행으로 부르는 창. 앱 본체·Python·kagent·kvf가 꺼져 있어도 동작.

### 1-3. 미리보기를 별도 프로세스로 띄우는 규칙
- Space·→로 미리보기를 열면 `ktm.exe --preview --parent <hwnd> --gen <n>`을 띄우고 `WM_COPYDATA`로 (문서 번호·질의어)를 보낸다. 이미 떠 있으면 메시지만 보낸다.
- 미리보기 프로세스는 같은 매핑 색인을 스스로 연다(본 창에서 자료를 넘기지 않음). 창은 본 창의 소유 창(owned window)이라 본 창과 함께 움직이고 숨는다.
- 닫기·Esc·본 창 숨김 → 미리보기 프로세스 끝남. 본 창은 `WaitForSingleObject` 대신 프로세스 핸들을 메시지 고리의 `MsgWaitForMultipleObjects`에 넣어 끝남을 받는다(폴링 없음).
- 목표: Space → 미리보기 보임 **120ms**(프로세스 시작 + 매핑 열기, 추정, T9 실측). 미리보기 프로세스 개인 메모리는 **따로 표기**(목표 8MB 이하, 연관 문서 계산 포함).
- 미리보기 프로세스가 죽거나 2초 안에 응답이 없으면 본 창은 미리보기 칸에 "미리보기를 열 수 없음"만 표시하고 계속 동작(견고성 3).

### 1-4. 메모리 매핑 색인의 형식·버전·잠금

**자리와 파일**
```
%ProgramData%\HwpAutoDocFit\index\<사용자 SID>\
  manifest.bin                 현재 세대를 가리키는 작은 고정 크기 파일(원자적 교체 대상)
  gen-<u64 16자리>\
    names.seg                  드라이브 전체 이름(그 사용자에게 보여도 되는 것만, §1-5)
    names-delta-<k>.seg        마지막 기본판 이후 바뀐 이름(작은 세그먼트, 1초 묶음)
    content-<k>.seg            kfind-core 문장 비트맵 + 조각 사전(fst) + 문단 원문 + 위계 필드
    timeline.seg               조사 폴더 파일의 시각·종류·폴더 번호 + 이름 비교형
    related.seg                연관 문서 계산용 문서 특징(제목 비교형·시리즈 키 등, T9에서 확정)
  pending-delete.txt           아직 지우지 못한 옛 세대(서비스만 읽고 씀)
```

**공통 머리글(모든 `.seg`, 64바이트, 리틀 엔디언)**: 마법수 `KTMSEG01` · `format_version` u32 · `kind` u32(names/delta/content/timeline/related) · `rule_version` u32(NFC·`fold`·문장 규칙 판, IS1 §2.4·S5) · `gen` u64 · `body_len` u64 · 구획 목차 오프셋 u64 · `body_crc32c` u32 · `header_crc32c` u32. 본문은 구획(목차에 오프셋·길이)으로 나누고 **읽는 쪽은 모든 오프셋·길이를 파일 길이로 검사**한 뒤 슬라이스를 만든다(손상 파일에 패닉·범위 밖 읽기 없음 — 퍼즈 시험 T1).

**`manifest.bin`(4KB 고정)**: 마법수 `KTMMAN01` · `format_version` · `rule_version` · `gen` · `published_at` · `writer_kind`(service/task/user/portable) · `writer_version` · 볼륨별 USN 저널 ID·마지막 USN · 세그먼트 목록(이름·길이·`body_crc32c`) · `manifest_crc32c`.

**버전 규칙**
| 경우 | 읽는 쪽(ktm·kvf·미리보기) | 쓰는 쪽(서비스) |
|---|---|---|
| `format_version` 같음 | 정상 | — |
| 읽는 쪽보다 1 낮음 | 읽는다(N-1 읽기 지원 — 서비스·ktm 업데이트 순서가 엇갈려도 동작) | 새 판으로 다시 게시 예약 |
| 읽는 쪽보다 높음 | `Availability.Index = IndexNewer` → 상태 줄 "ktm 업데이트 필요", 질의 안 함 | — |
| 2 이상 낮음 | `IndexOlder` → "색인 다시 만드는 중" | 새 판으로 처음부터 다시 만듦(옛 세대로 계속 답함) |
| `rule_version` 다름 | 질의는 하되 상태 줄에 `ContentRuleUpgrade` 표지 | 새 규칙으로 백그라운드 재색인, 끝나면 새 세대 게시 |

**원자적 교체(게시)**
1. 서비스가 새 세대 폴더 `gen-<n+1>.tmp\`에 세그먼트를 쓴다. 바뀌지 않은 세그먼트는 옛 세대에서 **하드 링크**(복사 없음, 같은 볼륨).
2. 각 파일 `FlushFileBuffers` → 폴더 이름을 `gen-<n+1>`로 바꿈.
3. `manifest.tmp`를 쓰고 `FlushFileBuffers` → `MoveFileExW(manifest.tmp, manifest.bin, MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)`. **읽는 쪽에는 이 한 번의 바꾸기만 보인다.** 중간에 서비스가 죽으면 옛 `manifest.bin`이 그대로 → 옛 세대로 계속 동작, 다음 시작 때 `*.tmp` 정리.
4. **게시 알림**: 읽는 쪽마다 `index\<SID>\` 폴더에 `FindFirstChangeNotificationW(FILE_NOTIFY_CHANGE_FILE_NAME | LAST_WRITE)` 핸들을 두고 메시지 고리에서 기다린다(폴링 없음, 읽는 쪽마다 따로 다시 걸기 `FindNextChangeNotification` — 공용 이벤트 하나를 여러 읽는 쪽이 리셋하는 경쟁이 없음). 깨면 자기 세대 번호와 `manifest.bin`의 `gen`을 비교만 한다(같으면 아무것도 안 함). 알림을 놓쳐도 다음 부름 때 같은 비교로 따라잡는다. 사용자에게 필요한 권한은 그 폴더 목록 읽기뿐(§1-5에서 줌).

**게시된 파일은 다시 쓰지 않는다**(불변). 바뀌는 것은 늘 새 세대.

**잠금 규칙**
| 대상 | 규칙 |
|---|---|
| 쓰는 쪽 | 사용자 폴더 하나에 쓰는 쪽은 **하나**. 서비스 모드: 서비스 프로세스 안에서 사용자별 게시기 스레드 1개. 대체 모드(예약 작업·사용자 권한·포터블): 이름 있는 뮤텍스 `Local\HwpAutoDocFit.Index.Writer`(사용자 모드) 또는 `Global\HwpAutoDocFit.Index.Writer.<SID>`(예약 작업 모드)를 잡은 프로세스만. 서비스가 등록·실행 중이면 대체 모드 프로세스는 쓰지 않고 끝남(SCM 조회 1회) |
| 읽는 쪽 | 잠금 없음. `manifest.bin`을 `FILE_SHARE_READ|WRITE|DELETE`로 열어 읽고 바로 닫음 → 목록의 세그먼트를 같은 공유 모드로 열어 `MapViewOfFile(FILE_MAP_READ)`. 매핑을 쥔 동안 그 세대는 읽는 쪽에 안정적 |
| 옛 세대 지우기 | 서비스가 새 세대 게시 뒤 옛 세대 파일을 **POSIX 삭제**(`FILE_DISPOSITION_POSIX_SEMANTICS`)로 지운다: 이름은 바로 사라지고 매핑 중인 읽는 쪽은 매핑을 닫을 때까지 그대로 읽는다(추정 — T0 C11에서 매핑된 파일에 대해 확인). 실패하면 `pending-delete.txt`에 넣고 다음 게시 때 다시. 세대는 최대 3개(현재 + 2), 넘으면 가장 옛 것부터 |
| 읽는 쪽의 세대 바꾸기 | 게시 알림을 받으면: 창이 **보이면** 진행 중 질의가 끝난 뒤 새 세대를 매핑하고 옛 매핑을 닫음. **숨어 있으면** 옛 매핑만 닫고 새 세대는 다음 부름 때 연다(숨은 동안 디스크·메모리를 쥐지 않음) |

### 1-5. 접근 권한(같은 사용자만)
- `%ProgramData%\HwpAutoDocFit\index\`: 상속 끊음. SYSTEM·Administrators 모든 권한. 사용자 그룹은 **목록 보기 없음**.
- `index\<SID>\`: SYSTEM 모든 권한, **그 SID에만 읽기·실행**(쓰기·지우기 없음), 다른 사용자 없음. → 다른 사용자는 남의 색인을 열 수 없고, 주인도 고칠 수 없다(서비스가 사용자가 쓸 수 있는 곳에 쓰지 않으므로 SYSTEM 쓰기를 노린 링크·접합점 공격이 없음).
- 게시 알림은 따로 만든 이름 있는 객체 없이 폴더 변경 알림으로 받는다(§1-4 4번) → 서비스가 `Global\` 객체를 만들 필요가 없다.
- **게시 전에 거른다**: 드라이브 전체 이름 중 다른 사용자 프로필(`C:\Users\<다른 사람>`)·`$Recycle.Bin`·`System Volume Information`은 그 사용자의 `names.seg`에 넣지 않는다(IS1 Q9 기본값과 같음). 파일을 열어도 남의 파일 이름은 없다. 그 사용자가 NTFS 권한상 열 수 없는 폴더의 이름은 1차에 거르지 않는다(Everything과 같은 수준, Q14).
- 파이프 `\\.\pipe\HwpAutoDocFit.Index`(IS1 S3 파이프에 명령 추가): 원격 거부, 대화형 사용자·SYSTEM만, 요청 64KB 상한. 클라이언트 SID는 `GetNamedPipeClientProcessId`+토큰으로 확인하고, 명령은 **그 SID의 설정에만** 작용.
  - IS1 그대로: `query`·`cancel`·`status`·`path_of`(앱 Python용).
  - TM1 추가: `register{roots, exts}`(조사 폴더·확장자 — ktm·앱이 사용자 설정을 읽어 보냄, 서비스는 사용자 폴더의 설정 파일을 읽지 않음), `ui_active{on}`(창 보임 동안 작업 미룸), `reindex{path?}`(사용자가 F5로 요청), `status_user`(그 SID의 게시 세대·작업 대기열 수·마지막 오류).

### 1-6. 서비스가 스스로 갱신하는 방법(Q6·첫 판 Q7 결정)
| 자료 | 원천 | 갱신 |
|---|---|---|
| 이름 | MFT 열거 + USN 막힘 읽기(IS1 S2) | 바뀐 이름을 모아 **1초에 한 번 이하** `names-delta` 게시. 델타가 기본판의 5% 또는 6만 항목을 넘으면 기본판 다시 만들기(백그라운드) |
| 본문 | 같은 USN 기록 중 등록된 조사 폴더·확장자에 걸리는 것 → 작업 대기열(경로·USN, 중복 제거, 2초 모음) | 작업 프로세스 1개(사용자 토큰, `BELOW_NORMAL`·I/O 낮음) → 문장 기록 → 서비스가 `content-<k>.seg` 증분 세그먼트를 만들어 게시. 세그먼트가 8개 넘으면 합치기 |
| 타임라인 | 같은 USN 기록(조사 폴더 아래 만들기·고치기·이름 바꾸기·지우기, 시각) | `timeline.seg` 게시. **처음 한 번 씨앗**: 사용자 토큰 작업 프로세스가 `timeline.db`를 **읽기 전용**으로 읽어 지난 기록을 보냄(서비스는 사용자 쪽 SQLite를 직접 읽지 않음). `timeline.db`는 서비스가 쓰지 않는다 → 쓰는 쪽은 여전히 kagent·앱 하나(첫 판 Q6의 "쓰는 쪽 셋" 문제가 생기지 않음) |
| 연관 문서 특징 | 본문 세그먼트를 만들 때 함께 | `related.seg` |

**미룸 규칙**(본문·타임라인 씨앗·합치기만 미룸. USN 읽기·이름 델타는 가벼워 늘 함)
- `ui_active` 켜짐(창이 보이는 동안) → 새 작업 프로세스를 띄우지 않음. 이미 돌던 것은 그 문서까지 하고 멈춤.
- 배터리 사용 중(`SERVICE_CONTROL_POWEREVENT` → `GetSystemPowerStatus`) → 미룸. 전원 연결 사건으로 다시 시작(폴링 없음).
- 사용자가 로그오프 → 그 사용자 토큰이 없으므로 본문 작업 멈춤. USN은 OS가 보관 → 다음 로그온 때 따라잡음.
- 앱이 본문 색인 중 → 1차에 앱은 서비스가 있으면 **서비스에 맡긴다**(IS 동시 교체 뒤, T12). 교체 전 기간에는 앱의 옛 SQLite 색인과 서비스 색인이 따로 존재(서로 쓰지 않음).

### 1-7. 서비스가 없을 때: 대체 사다리
기관 PC에서 서비스 만들기가 막히는 경우(그룹 정책·보안 프로그램·관리자 계정 없음)를 위해 **같은 실행 파일을 모드만 바꿔** 돌린다. 색인 형식·읽는 쪽 코드는 모두 같다.

| 단 | 모드 | 필요 | 이름 색인 | 시작 | 색인 자리 | 상태 표시 |
|---|---|---|---|---|---|---|
| 1 | **서비스**(`ktm-svc --service`) | 설치 때 UAC 1번 | MFT·USN 드라이브 전체 | 부팅(지연 자동) | `%ProgramData%\…\index\<SID>\` | 없음 |
| 2 | **예약 작업**(`--task`): 로그온 트리거, "가장 높은 권한으로 실행", 실패 시 다시 시작(1분 간격 3회) | 만들 때 UAC 1번(서비스 만들기만 정책으로 막힌 경우) | MFT·USN(관리자 토큰) | 로그온 | 같음(작업이 관리자 토큰이라 SYSTEM과 같은 ACL로 씀) | "색인: 예약 작업 모드" |
| 3 | **사용자 권한**(`--user`): `ktm.exe`가 띄우거나 사용자 Run 값 | 관리자 없음 | **조사 폴더만**(`ReadDirectoryChangesW` + 시작 때 mtime 대조, kagent `watch.rs` 공용) | 로그온(ktm 자동 실행 때) | `%LOCALAPPDATA%\HwpAutoDocFit\index\`(사용자 폴더, ACL 기본) | "드라이브 전체 꺼짐(관리자 권한 없음)" |
| 4 | **포터블**(`--portable`) | 없음 | 3과 같음 | `ktm.exe`가 켜져 있는 동안만 | 포터블 폴더 아래 `index\` | "포터블 모드" |

- 단 2·3에서 작업 프로세스는 같은 사용자 권한으로 바로 띄움(토큰 바꾸기 불필요).
- 넘어가는 조건(설치 흐름이 결과 코드로 판정, §1-8): `OpenSCManager`·`CreateService`가 `ERROR_ACCESS_DENIED` → 단 2 제안. UAC 취소(`ERROR_CANCELLED`)·관리자 자격 없음 → 단 3 제안. 서비스는 등록됐는데 30초 안에 `RUNNING`이 안 됨(보안 프로그램이 죽임 — 미확인) → 서비스 제거 후 단 2 제안. 사용자는 늘 "지금은 쓰지 않음"을 고를 수 있다.
- 단 3·4에서 서비스 모드로 올라가면: 서비스가 처음부터 만든 뒤 사용자 폴더 색인을 지움(ktm이 `writer_kind` 바뀐 것을 보고 새 자리로 옮겨 감).

### 1-8. 설치·제거·업데이트 교체
**설치(앱 설정에서 켤 때, 기본 꺼짐)**
1. 앱 설정 "타임머신 작은 창 켜기" → 안내: "드라이브 전체 파일명·자동 색인을 위해 색인 서비스를 설치합니다(관리자 확인 1번). 서비스는 문서 내용을 직접 열지 않습니다." [설치] [관리자 없이 쓰기(단 3)] [취소].
2. [설치] → `ShellExecuteEx(runas, ktm-svc.exe --install --for-sid <SID>)`.
3. 설치 명령(관리자): 자기 자신과 작업 프로세스 exe(`klib.exe`)를 `%ProgramFiles%\HwpAutoDocFit\svc\<버전>\`에 복사 → 앱 꾸러미의 `.sha256`과 대조(다르면 중단) → `svc\current` 가리킴 파일 원자 교체 → `CreateService`(자체 프로세스, LocalSystem, `SERVICE_AUTO_START` + 지연 자동 시작, 필요한 특권만 `SERVICE_CONFIG_REQUIRED_PRIVILEGES_INFO` — 최소 집합은 IS1 S2 실측, 복구: 5초·30초·5분 다시 시작, 하루 뒤 초기화) → `index\` 폴더 ACL(§1-5) → 시작 → `RUNNING` 30초 대기.
4. ktm 쪽은 kvf V8 방식(사용자 폴더 설치·Run 값 `HwpAutoDocFit.Ktm`·`--hidden --delay 30`)으로 따로 설치(관리자 불필요).

**업데이트 교체**
- 앱이 시작 때(그리고 ktm이 `status` 때) 파이프 `status.version`과 꾸러미 버전을 비교 → 다르면 앱 상태 줄에 "색인 서비스 갱신(관리자 확인 1번)". 몰래 교체하는 경로 없음(IS1 보호 조치 5).
- `--upgrade`(관리자): 새 버전 폴더 `svc\<새 버전>\`에 복사·해시 대조 → 서비스 중지(`STOPPED` 15초 대기, 넘으면 중단·옛 버전 유지) → `current`를 새 버전으로 → 시작 → 30초 안 `RUNNING`이고 파이프 `status`가 새 버전이면 옛 폴더 지움, 아니면 **되돌리기**(current를 옛 버전으로, 시작).
- 색인 형식이 바뀐 업데이트: 새 서비스는 옛 세대로 계속 답하면서 새 형식으로 다시 만든다(§1-4 버전 규칙). ktm은 N-1을 읽으므로 ktm·서비스 업데이트 순서가 엇갈려도 동작.
- 서비스 실행 파일은 Program Files(관리자만 쓰기)에만 있고 서비스는 그 사본만 가리킨다(IS1 보호 조치 1 그대로).

**제거**
- 앱 설정 "끄기" → [서비스도 제거](UAC 1번: 중지·`DeleteService`·`svc\`·`index\` 지움) / [ktm만 끄기](서비스는 남겨 앱 파일명 검색에 씀).
- 앱 제거: 설치기(`PrivilegesRequired=lowest`)의 `[UninstallRun]`에서 `ktm-svc.exe --uninstall`을 runas로 부름 → 사용자가 UAC를 거부하면 서비스가 남으므로 제거 화면 안내문 + 다음 로그온 때 서비스가 자기 앱 폴더가 없음을 알면(등록된 사용자 SID 모두의 앱 폴더 없음) 스스로 `index\`를 지우고 서비스 시작 유형을 `DISABLED`로 바꿈(스스로 지우기는 못 함 — 미확인, T6에서 확인). Inno `[UninstallRun]`의 runas 가능 여부 미확인(T6).
- 예약 작업 단: `schtasks /Delete` 같은 일을 `--uninstall`이 함. 사용자 권한·포터블 단: Run 값·사용자 폴더 색인 지움.

**⓪ 서비스 수명 `Svc`(서비스 안, 사용자 SID마다 `UserPub` 하위 상태)**
| 상태 | 뜻 | 들어오는 사건 → 다음 |
|---|---|---|
| `NotInstalled` | 등록 없음(ktm이 SCM 조회로 봄) | 설치 성공 → `Starting` |
| `Starting` | 서비스 시작, 스냅숏 읽기 | 스냅숏 있음 → `CatchingUp` / 없음·저널 ID 다름 → `Enumerating` / 실패 → `Failed` |

| `Ready` | USN 막힘 읽기 대기 | 저널 넘침·ID 바뀜 → `Rebuilding{vol}`(옛 색인으로 답함) / 중지 요청 → `Stopping` |

| `Stopping` | 스냅숏 저장, 작업 프로세스 정리(Job 닫기), 마지막 게시 | → `Stopped` |

## 4. (라) 자원·속도 목표와 비교 측정

### 4-1. 자원과 "창 개인 메모리 2MB"를 지키는 방법(첫 판 Q8을 다시 적음)
매핑 구조에서는 "숨긴 뒤 색인을 몇 분 쥐고 있을까"(첫 판 Q8)가 메모리 문제가 아니다. 파일 기반 매핑 페이지는 **공유·파일 기반**이라 개인 메모리(커밋)에 들지 않고, 숨길 때 `EmptyWorkingSet`으로 작업 집합에서 빼도 OS 대기 캐시에 남아 다시 부를 때 빠르다. 대신 개인 메모리를 늘리는 것은 **힙**이다. 그래서 규칙을 이렇게 바꾼다.

| 규칙 | 내용 | 시험 |
|---|---|---|
| M1 색인은 매핑으로만 | 이름·본문·타임라인 자료를 힙에 복사하지 않는다. `MapViewOfFile(FILE_MAP_READ)`만(쓰기 시 복사 없음) | 숨김 상태에서 `PROCESS_MEMORY_COUNTERS_EX.PrivateUsage`가 색인 크기와 무관(3k·30k 색인에서 차이 0.1MB 이내) |
| M2 질의 중간 자료는 전용 힙 | 비트맵 교집합·결과 목록·비트맵 캐시(IS-QCACHE)는 `HeapCreate`로 만든 질의 힙에만. 상한 32MB(넘으면 캐시부터 버림) | 질의 100회 뒤 숨김 → 개인 메모리 숨김 기준 +0.2MB 이내 |
| M3 숨기면 바로 반환 | 숨길 때 질의 힙 `HeapDestroy`(다시 보일 때 새로 만듦), 미리보기 프로세스 닫기, `EmptyWorkingSet`. **타이머 없음** | 숨김 1초 뒤 개인 메모리 2.0MB 이하 |

## 8. 남는 위험
- 핵심 단계(T4·T5·T6)가 IS1 S2·S3·S5에 걸린다. 늦어지면 ktm 1차를 **단 3(사용자 권한 모드) 먼저**로 낼 수 있다: 같은 형식·같은 읽는 쪽이라 서비스가 나중에 붙어도 ktm 코드는 바뀌지 않는다 — 총괄 판단.
- SYSTEM 서비스가 사용자 토큰으로 작업 프로세스를 띄우는 것(`WTSQueryUserToken`)과 SYSTEM이 받는 글 기록 해석이 새 공격면이다. 기록 형식을 최소(길이 접두 UTF-8)로 두고 퍼즈 시험(T5)을 완료 조건에 넣었다.
- 매핑된 파일의 POSIX 삭제(C11)·파일 매핑의 개인 메모리 계산(C10)은 추정이다. 어긋나면 옛 세대 지우기를 `pending-delete`만으로, 메모리 목표는 측정 정의를 바꿔 Q로.
- 서명 없는 새 서비스·상주 exe가 기관 보안 프로그램에 막힐 수 있다(C9·C12). 대체 사다리(§1-7)로 기능은 줄여도 동작은 유지.
- 서비스 하나가 IS1(앱 파일명 검색)과 TM1·kvf를 모두 받친다. 서비스 결함은 셋에 같이 번진다 → 읽는 쪽이 마지막 세대로 계속 검색(K9)과 앱의 옛 파일명 경로(IS1 대체 동작)를 지킨다.
- 상주가 셋(kagent·kvf·ktm) + 서비스 1. 트레이 아이콘 셋.

## 10. 첫 판(`115b9322`)에서 바뀐 점
