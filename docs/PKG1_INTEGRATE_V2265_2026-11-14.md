## 2. Gemini 초안 검토 결과

초안(WIP 6328475a, 보관 브랜치 `wip/pkg1-gemini-draft`)은 병합 대신 엔진 파일을 옛 판으로 복사해 넣었다(예: `kfind/core/src/index.rs` 약 1,900줄 차이, 시험 파일 다수 누락). 그래서 b58cffe5로 되돌려 실제 병합을 하고, 초안에서는 배포·안내 파일만 골라 고쳐 썼다.

- `docfit_app/kfind_process.py`(초안에 실제로 있었음, `hwp-auto-docfit.py`가 부름): 다시 씀.
  - 대체 방식 값이 Rust(`install.rs` `Fallback` snake_case: `user`·`task`)와 달리 `service`도 썼다 → Rust가 설정 파일을 못 읽어 오류. `user`·`task`만 쓰고, 다른 키는 보존, 원자적 교체로 저장.
  - 파이프 확인이 파이프를 직접 열어 서비스의 "연결 하나에 요청 하나" 인스턴스를 빈 연결로 소모 → `WaitNamedPipeW`로 바꿈(연결 안 함, 바쁨은 살아 있음으로).
  - 검색 엔진 설정이 `legacy`면 띄우지 않음. 실패는 예외 없이 False(검색은 kfind_client의 legacy 대체가 맡음).
  - 관리자 서비스 설치·제거는 UAC 권한 요청(`Start-Process -Verb RunAs -Wait`)으로 실행, stdin 닫음(초안은 권한 없이 실행 → 접근 거부 시 kfind가 stdin 질문에서 멈출 수 있었음). 설치 성공 뒤 이 계정의 사용자 모드 kfind를 끝내고 `--start`.
- `hwp-auto-docfit.py`: 초안의 배경 스레드 호출 유지. CRLF 유지 확인(LF만 있는 줄 0, 시험으로 고정).
- `HWP_AutoDocFit.spec`: 초안의 kfind.exe binaries 추가는 되돌림. kagent·kvf처럼 `resources` 폴더 통째 포함으로 들어간다.
- `.github/workflows/build-windows-exe.yml`: kvf와 같은 방식(시험→빌드→`resources/kfind.exe`·SHA256→얼린 꾸러미 해시 확인). 시험에 `kfind/core`·`kfind/names`도 추가.
- `installer/setup.iss`: 초안의 `[UninstallRun] kfind --uninstall`은 사용자 권한 제거기에서 SCM 접근이 거부되어 의미가 없었다 → 서비스가 있을 때만(`sc query`) 관리자 권한으로 `kfind --uninstall`(서비스 중지·삭제·공개 색인 삭제, Q16)을 부르는 `[Code]`로 바꿈. 이 계정의 사용자 모드 kfind는 `taskkill /FI "USERNAME eq {username}"`으로 먼저 끝냄. `[UninstallDelete]`에 공개·사용자 색인과 kfind 설정 폴더.
- 라이선스 안내: 루트 `LICENSE`에 예외 단락, `README.md`(LF)·`.github/README.md`(CRLF) 두 곳의 라이선스·엔진 설명 갱신(줄바꿈 수 그대로), `THIRD_PARTY_NOTICES.md`에 Cargo.lock 기준 실제 버전(초안의 roaring 0.10·rayon 1.10은 틀림 → 0.12.0·1.12).
- `kfind/names/examples/fn1_bench.rs` 주석의 `G:/docfit-tmp` 경로를 자리표시로(경로 금지 시험).
