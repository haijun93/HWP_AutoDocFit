# RUSTSIDE1 결과 — 사이드바만 먼저 실행, 메뉴마다 별도 창 (2026-11-26)

브랜치 `feature/RUSTSIDE1`. 커밋만 했고 푸시하지 않았다. 설치본의 기본 실행 방식은 바꾸지 않았다. 다음 일은 `docs/RUSTSIDE1_PLAN_2026-11-26.md`.

## 한 일

1. **Rust 사이드바 `sidebar.exe`** (`dock` 크레이트에 추가, 메뉴 묶음·아이콘 글꼴·숨김 해석·자동 숨김 판정 재사용)
   - 화면 왼쪽에 고정. 앱 왼쪽 메뉴와 같은 순서·이름, `hidden_tabs`·`developer_mode`·`theme_mode`를 따르고 설정 파일이 바뀌면 다시 그린다.
   - 같은 설정 파일로는 하나만 실행. 다시 실행하면 떠 있는 것을 보인다.
   - 자동 숨김은 기존 키 `dock_auto_hide`. 사이드바 위쪽 핀 단추로 바꾸며 `docfit_config`(앱과 같은 잠금)로 저장한다.
   - 닫아도 열린 화면 창은 남는다.
2. **Rust 창이 있는 메뉴**: 파일명 일괄변경·몽땅검색·문서뷰·사진뷰·파일변환·아웃라이너·설정. 이미 있으면 앞으로, 없으면 실행. 실행 파일이 없고 앱 화면이 있으면 앱 화면으로 대신 연다.
3. **나머지 메뉴**: 앱 시작 인자 `--screen N`. Flutter 화면은 주소 조각 `#screen=N`을 받아 첫 그림부터 왼쪽 메뉴·가로 탭·빠른 실행 막대 없이 그린다.
4. **여러 프로세스 충돌 처리**
   | 충돌 | 처리 |
   |---|---|
   | 단일 인스턴스 뮤텍스 | 메뉴별 뮤텍스. 같은 메뉴를 다시 켜면 그 창을 앞으로 |
   | 설정 전체 덮어쓰기 | 전용 창은 시작 값에서 바꾼 항목만 저장 |
   | 작업 상태 파일 `desktop-jobs.json` | 메뉴별 파일(다른 창의 작업을 '중단됨'으로 치우던 문제) |
   | 한/글 PID 등록(전후 목록 차이) | 프로세스 간 뮤텍스(남의 한/글을 강제 종료 대상으로 잡는 문제) |
   | 파일 열기 대기열·파이프·상주 도우미 점검·업데이트 확인·Dock | 전용 창은 하지 않음 |
5. **실행 방식 선택**: `sidebar.exe` 직접 실행 / 앱에 `--sidebar` / 설정 `launch_mode: "sidebar"`. `--full-app`은 설정을 무시한다. 업데이트 교체 중에는 넘기지 않는다. 기본은 기존 앱.
6. **패키징**: CI 복사·묶음 확인, spec(있으면 포함), 설치 중 `sidebar.exe` 종료.
7. 측정 도구 `scripts/measure_sidebar.py`.

## 암묵적 상태를 드러낸 것

메뉴 창 상태 closed / launching / open(전이는 계획 문서 0절, `--state-file`로 읽음), 프로세스 상태 "보통 앱 / 메뉴 N 전용 창"(`screen_mode.current()`, 시작 때 한 번 정함).

## 작업 중 찾아 고친 문제

- 상주 점검을 함수로 옮기면서 import가 범위 밖이 되어 **보통 앱의 몽땅검색 시작 점검이 조용히 빠지는** 버그를 만들었다. 기존 시험은 잡지 못했다. 고치고 시험을 추가했다(수정을 빼면 실패, 넣으면 통과 확인).
- 설정 파일을 밖에서 바꾼 뒤 사이드바 상태 파일이 갱신되지 않던 것.

### 실제 실행 확인 (소스 실행, 임시 사용자 폴더)

- 15개 메뉴(0~6, 8~14, 설정): 창이 열림, 다시 눌러도 창 1개, 상태 `open`, 사이드바를 닫아도 창이 남음.
- 사이드바 두 번째 실행은 종료 코드 0이고 창 1개. 핀 단추 → `dock_auto_hide` 저장·다른 키 보존. 설정 파일에서 숨긴 메뉴 반영. 닫기 단추로 종료.
- 화면 확인: 앱 화면 창에 앱 왼쪽 메뉴가 없음(문서편집 안의 '작업 순서' 패널은 문서편집 화면의 일부라 남음).
- 가상 폴더·업무자료함은 작업 폴더에 `klib`를 빌드하지 않아 "klib 없음" 안내까지만 확인했다.
- 열지 않은 것: **몽땅검색**(이 PC의 상주 프로그램을 건드리지 않으려고), 검색 벤치마크(개발자 모드).

## 속도

**정식 측정을 하지 못했다. 실행→사이드바 조작 가능 시간과 탐색기 새 창 시간의 값이 없다.**

- 전체 시험 잠금 파일은 이 작업 세션의 파일 접근 범위 밖이라 확인할 수 없었다.
- 작업하는 동안 다른 시험으로 보이는 프로세스(`flutter_tester`, 이후 CPU를 계속 쓰는 큰 `python` 프로세스)가 돌고 있었다.
- 재는 도구는 준비됐고 `--lock`을 주면 잠금 파일이 있을 때 재지 않는다(아래 '재현').

## 남은 문제

1. 앱 화면 메뉴는 창마다 앱 전체(Python+Tk+WebView2)를 켠다. 창이 뜨는 데 몇 초 걸리고, 내용이 다 그려지는 시간은 더 길다(표템플릿은 8초 뒤에도 로딩 중, 40초 뒤 표시 확인). 창별 메모리는 재지 않았다.
2. 창 사이 파일 보내기는 막고 안내한다.
3. 사이드바만 쓰면 상주 작업(몽땅클립보드 앱 파이프, kagent·kvf·ktm 갱신, 업데이트 확인, 우클릭 메뉴 갱신, 변환 파이프)을 아무도 하지 않는다. 탐색기에서 파일을 열면 보통 앱이 뜬다.
4. 문서편집 전용 창에는 새 문서·작업 로그·사용 방법·몽땅클립보드 진입점이 없다(앱 왼쪽 메뉴·빠른 실행 막대에 있던 것).
5. Rust 창은 앱의 `*_ui` 설정(기본 `flutter`인 것 포함)과 상관없이 연다. 기존 화면과의 기능 대조는 하지 않았다.
6. `launch_mode`를 고르는 설정 화면이 없다(설정 파일·실행 인자만).
7. 자동 숨김이 꺼져 있으면 사이드바(폭 164dip)가 최대화한 창의 왼쪽을 가린다.
8. 설치본(PyInstaller)·설치 프로그램·CI(MSVC) 빌드는 하지 않았다.
9. 손으로 확인하지 않은 것: 자동 숨김의 실제 마우스 동작(판정은 단위 시험), 키보드 이동, 화면 읽기, 125%·150% 실화면(150%는 그림 저장만), 다중 모니터(주 모니터에 배치).
10. 두 창에서 동시에 한/글 작업하는 경우는 시험하지 않았다. PID 뮤텍스는 `한글_COM_인스턴스_생성` 경로에만 걸었다.
11. 설정을 한 창에서 바꿔도 이미 열린 다른 창에는 다시 켜야 반영된다.

## 재현

```
cargo build --release --manifest-path dock/Cargo.toml   # MinGW 도구 경로를 PATH 에 추가
python scripts/measure_sidebar.py --bin <exe 폴더> --runs 15 --menus 16,8,9,14,6,10,0,1,2,3,4,5,11,12,13 --python <pythonw.exe> --lock <전체 시험 잠금 파일>
```

`--bin`에는 `sidebar.exe`와 Rust 창 exe를 함께 둔다. 앱 화면 메뉴는 `desktop_web/flutter` 웹 빌드가 필요하다.
