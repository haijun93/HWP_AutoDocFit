# QMS2WARM1 결과 — ktm 첫 입력 지연 프리워밍 (2026-11-22)

카드: 몽땅검색 통합 2단계 4번(QMS2-PERF-WARM). 기준: `docs/QMS2_DESIGN_2026-11-22.md` 6.2절(표시 직후 첫 입력 50ms 이내), `docs/MG2_KTM_2026-11-14.md` 남은 문제 1(377~586ms).

## 결론

**효과 없음. 코드는 넣지 않았다(저장소 변경은 이 문서뿐).**

- 현재 빌드(`main` 94c12f86)에서 표시 직후(틈 0ms) 첫 입력은 **같은 창의 두 번째 질의와 같은 시간**이다. 첫 입력에만 붙는 콜드 스타트 지연은 재현되지 않았다. 377~586ms는 한 번도 나오지 않았다.
- 후보 프리워밍(서비스 파이프에 읽기 전용 파일명 더미 질의를 별도 스레드로 1회)을 구현해 같은 방법으로 비교했으나 차이가 오차 안이었다.
- 글꼴·DC·미리 그리기(`create_fonts`, `prerender`)와 본문 색인 `Backend::warm()`은 이미 창 표시 전에 실행되고 있다(`window.rs` run()).
- **한계:** 측정 탐침은 `SetWindowTextW`로 글자를 넣는다. 실제 IME·TSF가 붙는 키 입력 경로는 재지 못했다. MG2가 의심한 원인(IME·TSF 붙이기)은 반증도 확정도 못 했다. 확정하려면 사용자 데스크톱에서 실제 키 입력(SendInput)을 쓰는 실기 시험이 필요하다(포커스를 가져가므로 이 카드에서는 하지 않았다).

## 측정 방법

- 빌드: `ktm` release(`--locked`), 합성 색인 3,000건(`examples/fixture`), 임시 SID 폴더.
- 서비스: 이 카드에서 띄운 임시 `kfind --user`(임시 색인 폴더·임시 파이프 `ktm-warm1-tmp`). 실제 색인 서비스·설치된 ktm은 건드리지 않았다(실제 서비스에는 질의도 보내지 않음).
- 탐침: `ktm --self-test`(격리 단축키 Ctrl+Alt+Shift+F24, `KTM_TEST_ROOT`·`KTM_METRICS` 임시 폴더), `KTM_PROBE_SETTLE_MS=0`(표시 직후 바로 입력). 기본 탭은 현재 "전체"(파일명·위계·본문 3갈래 질의)이다.
- 각 조건 5회 중앙값. 시험 PC는 부하에 따라 같은 조건도 약 54ms ↔ 34ms로 달라졌으므로 **같은 시간대에 번갈아 잰 쌍끼리만 비교**했다.

해석: 병목은 첫 입력에만 있는 일이 아니라 결과 그리기(WM_PAINT 한 번 약 35ms, 이 PC 부하 시)이며 첫·두 번째 질의에 똑같이 들어간다. 이 부분은 프리워밍으로 줄일 대상이 아니다(별도 렌더 최적화 과제).

서비스를 방금 새로 띄운 직후 첫 파이프 질의가 느린 경우가 한 묶음(5회 중 첫 3회: 파일명 갈래 48.7 / 30.9 / 15.2ms)에서 관찰됐으나, 뒤이어 다시 잰 같은 조건 10회(프리워밍 켬/끔 각 5회)에서는 1.0~1.8ms로 재현되지 않았다(첫 묶음은 새로 빌드한 exe 직후라 백신·파일 캐시 영향으로 보임, 원인 미확정).

## 남은 일

1. 실제 키 입력(IME·TSF) 경로의 첫 입력 지연 확인 — 사용자 PC 실기 필요. 377~586ms 현상이 사용자 환경에서 재현되면 그때 `slow_dispatch_ms`(메시지 번호 포함)로 UI 스레드 구간을 나눠 잴 것.
2. 결과 그리기 1회 약 35ms(부하 시)는 16ms 기준(6.1절)에 못 미침 — 렌더 최적화 별도 카드 후보(3갈래 결과마다 다시 그리는 구조).
3. 질의 후 쉴 때 개인 작업 집합 5.4~5.6MB 재확인(위 표).
