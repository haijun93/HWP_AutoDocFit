## 통합하면서 찾아 고친 결함

1. **`kfind --user` 가 격리 실행에서도 실제 바탕 화면·문서·다운로드를 자동 색인** (index-manual 구현). `crates/kfind` 의 `svccheck1_pipe` 시험이 실패했다. `--index-root`·`--pipe-name` 을 준 실행은 자동 색인하지 않게 했다. 옵션 없는 앱 실행은 그대로.
   - 알림: 수정 전 첫 시험 실행에서 시험용 kfind 가 이 PC의 해당 폴더 **파일 이름을 읽었다**. 파일 변경은 없고, 시험 프로세스는 종료했으며 색인 위치는 임시 폴더였다(이름 색인은 코드상 메모리에만 둠).
2. **색인 초기화가 검색 서비스(kfind)의 앱 문서를 하나도 지우지 못함.** `stale("tm", 0xffffffff)` 는 `level_src=py` 문서(앱 문서 전부)를 돌려주지 않는다. 기존 시험은 가짜 객체라 통과했다. 실제 kfind 합성 시험에서 수정 전 `0 != 450` 재현, 수정 후 통과.
3. 같은 경로에서 열쇠 1,000개를 한 요청에 담아 64KB 한도를 넘을 수 있었다. 32KB 단위로 나눠 보내고, 지워지지 않으면 반복을 멈춘다.

색인 초기화 확인: 지우는 것은 앱 본문 색인 표와 kfind 의 `tm` 범위 항목뿐이다(코드 확인). 원본 문서 불변은 기존 시험, 다른 범위(`box:`) 보존은 새 시험, 확인 대화상자(취소하면 요청 없음)는 새 위젯 시험으로 확인.

## OUTENGINE1 추가 확인

| 확인 | 결과 |
|---|---|

| 설치 폴더 제거 | 엔진이 앱의 작업 폴더를 물려받던 것을 임시 폴더로 바꿈(코드). 실제 제거는 미확인 |
| 앱 정상 종료 | 자식 종료·임시 사본 삭제(기존 시험) |
| 앱 강제 종료 | 입력 파이프가 닫혀 엔진은 스스로 끝남. 임시 사본은 남음 → **다음 상주 시작 때 지우도록 추가**(합성 시험: 부모 `TerminateProcess` 뒤 확인) |

- 정리 규칙: Windows 에서만, `docfit-outliner-*` 중 주인(`owner.lock`)이 없고 우리 파일만 든 폴더를 지운다.
- **남는 위험**: 강제 종료 뒤 아웃라이너를 다시 쓰기 전(또는 앱 제거 뒤)에는 임시 사본이 남는다. 실제 설치·업데이트·제거, 백신의 임시 경로 실행 차단은 확인하지 않았다. 단발 대체 상태에서는 실행하는 동안 원본이 잠긴다.
- 그래서 **상주를 끌 수 있게 했다**: 설정 `outliner_resident_engine: false` 또는 환경 변수 `DOCFIT_OUTLINER_RESIDENT=0`. 기본은 켬, 설정 화면 항목은 없음.

## 남은 문제·미확인

- 설치본·설치 서비스·실제 설치/제거·실제 앱 화면·IME·한/글 COM 시험은 하지 않았다. `python -m unittest discover` 전체도 돌리지 않았다.
- 퀵몽땅검색 '파일명 색인 지금 다시 만들기'는 사용자 모드(서비스 없음)에서는 "서비스가 필요하다"는 안내만 한다. 확인 대화상자는 없다(옛 색인으로 계속 답하는 재작성이라 지우지 않음).
- 색인 초기화: 멈춘 직후 자동 색인이 끼어드는 경합 가능성(코드 추정, 재현 안 함), 진행 표시 없이 응답을 기다림, 대량 문서 소요 시간 미측정. 검색 방식이 `sqlite` 가 아닐 때의 Tantivy 색인은 이 초기화가 지우지 않는다(코드 확인).
- 파일명 실패가 시간 초과인 경우 위계·본문이 그만큼 늦게 나올 수 있다(미측정). 새 실패 안내 문구는 위젯 시험으로만 확인했고 화면 캡처는 하지 않았다.
- OUTENGINE1 의 0.2초 목표 미달은 그대로이며 다시 측정하지 않았다.
- 파일명 서비스의 새 명령 `names_snapshot` 이 있어야 파일명 단이 나온다. 설치된 서비스는 교체하지 않았다.
