## 진입점 연결 점검

판정 기준: `kclip_settings_mode`는 클립보드 목록 화면 전체의 모양이 아니라 그 화면 안의 설정 진입 선택을 저장한다. 공통 Flutter 화면은 계속 클립 목록·복원 기능을 제공하며, `native`는 [설정 창: Windows 창] 선택 즉시 Win32 설정 창을 연다. `dialog`는 설정을 Flutter 화면 안에서 편집한다. 앱 메뉴의 독립된 몽땅클립보드 설정 메뉴는 확인되지 않았다.

| 진입점 | `native` | `dialog` | 코드 근거·판정 |
|---|---|---|---|

`settings_window` 서비스는 실행 중 kagent의 `status.json`에서 검증된 파이프 이름을 받아 `--settings --pipe`로 실행한다. 빠른 목록의 ⚙는 kagent 자체 설정 메뉴다. 실행 중 창의 `FindWindowW` 조회를 추가해 앱 브리지에서 연 별도 프로세스의 재호출도 기존 설정 창을 앞으로 가져오게 했다. 클래스 조회에 따른 단일 인스턴스는 코드로 보강했으며 다중 프로세스 동시 생성 경합의 실기 확인은 남아 있다.

## 설정 값 저장·공유 구조와 왕복 확인 범위

kagent의 유일한 런타임 설정 저장소는 사용자 데이터 폴더의 `settings.json`이다. kagent 내부 설정 창은 `update_settings`를 거쳐 파일 저장과 실행 중 설정 갱신을 함께 한다. 외부 `--settings --pipe` 창은 `settings_set`을 실행 중 kagent에 보내 같은 설정 모델·파일로 저장하고 즉시 반영한다. 파이프가 연결되지 않으면 파일을 저장해 다음 실행에 적용한다. Python `kclip_service`는 별도 kclip 설정 파일을 소유하지 않고 `settings_get`/`settings_set`을 kagent 클라이언트 파이프로 전달한다. `kclip_settings_mode`는 앱 일반 설정 파일의 UI 선택값이며 kagent 동작 설정이 아니다.

이번 작업에서는 GUI 설정 창 저장 → 실제 kagent 파이프 읽기 → Python 서비스 읽기의 통합 왕복을 실행하지 않았다. 요구된 `KAGENT_TEST_ROOT` 격리에서 프로세스/파이프를 띄우는 전용 하네스가 없고, 제한 조건상 kagent 및 관련 설정 시험 파일은 실행하지 않았다. 따라서 저장소 단일화는 코드 경로로 확인했으나, 요청된 임시 폴더 왕복 시험은 **미확인**이다. 실제 PC kagent·앱은 접근하지 않았다.

카드 수는 Win32의 현재 빠른 목록을 재사용하고, 새 창을 크게 재작성하지 않는 추정치다. 화면 간격, 운영체제 컨트롤, 고대비/DPI, 접근성 검토는 별도 실기 수정 카드가 추가될 수 있다.

### 권장 이관·기본 전환·제거 순서

1. 설정 창 연결과 `settings.json` 동기 왕복 자동화 시험을 완성한다. Flutter의 `dialog` 되돌리기 설정은 유지한다.
2. Win32 빠른 목록과 Flutter 목록의 기능 차이를 항목별로 확정한다. 누락된 상세 미리보기·카테고리 저장·조작 피드백만 필요성에 따라 빠른 목록에 이식한다.
3. 사용자가 실제 앱/에이전트에서 동의, 켜기 성공·실패, 항목 검색·복원, 미리보기, 카테고리, 단축키, 고DPI/IME를 확인한다. 미확인 기능이 남으면 기본값은 바꾸지 않는다.
4. 실기 확인 후 `kclip_settings_mode` 기본값을 `native`로 바꾸되 `dialog` 선택을 되돌리기 스위치로 유지한다. 차이·오류율을 회수한 뒤 충분히 안정되면 Flutter 대화상자 설정 코드를 제거한다.
5. 설정 코드 제거와 목록 화면 제거는 별도 변경으로 진행한다. Win32 기능 동등성이 확인되기 전에는 1,342줄 파일 및 목록 관련 유틸을 통째로 삭제하지 않는다.
