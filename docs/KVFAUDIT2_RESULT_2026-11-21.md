# KVFAUDIT2 결과 — 퀵가상폴더(kvf) 화면 캡처 전수 점검 (2026-11-21)

방법: `kvf.exe --capture-dir <폴더> [--dpi 96|120|144|192] [--scenario <이름>|all] [--dark]`(`--size` 옵션은 없음 — 장면마다 창 크기가 정해져 있고 `min_size_four`·`min_size_message`가 최소 크기). 실제 `vf_paint::draw` 경로로 메모리 DC에 그려 PNG 저장.
20개 장면(빈 상태 `empty_box`·`no_match`, 가상 `[가상]` 줄 `virtual_rows`, 활성 영역, 놓을 영역 `drag_target`, 긴 이름 `long_names`, 도구 막대·탭 `space_tab`, 상태줄 `truncated_status`, 오류 `failed`, 최소 크기 2종 등) × 라이트·다크 × 96·144dpi(=150%) = 80장을 만들어 대표 장면을 직접 열어 확인했다.
캡처 PNG는 저장소에 넣지 않았다(재생성 가능, 이 PC 참고용: `E:/docfit-tmp/KVFAUDIT2-cap/{before,after}/`).

문제 11건 / 수정 6건. 정상으로 확인된 부분(제목줄·주소줄·도구 막대 정렬, 탭 밑줄, 다크 대비, 최소 크기 겹침 없음, 144dpi 배율)은 건드리지 않았다.

## 수정 전·후 (캡처)
- empty_box_96: 전 '항목이 없습니다. …앱…'에서 끊김 → 후 두 줄로 'F5로 다시 불러오세요'까지 표시.
- drag_target_96(_dark): 전 파란 테두리만 → 후 놓을 영역 머리글이 강조 바탕.
- min_size_message_96: 전 '4개 영역 · …'에서 끊김 → 후 '· 5개 외…'까지 더 보임('5,000개 초과 생략'은 글자 폭만큼만 차지).
- four_icons_96·mixed_views_144_dark: 전 '한글 보고서 초…' → 후 '한글 보고서 초 / 안.hwp' 두 줄.
- 자세히 목록 전체: `[file]` → `[파일]`, `[link]` → `[링크]`, `[folder]` → `[폴더]`.

## 변경 파일
`kvf/src/vf_paint.rs`(안내 줄 접기·놓을 영역 강조·상태줄 안내 폭·종류 꼬리표·아이콘 이름 두 줄), `kvf/src/vf_ui.rs`(안내 줄 높이 1.5행, 시험 갱신), `kvf/src/vf_capture.rs`(search 자료), 이 문서.

## 남은 문제
위 표 7~11번. 추가: 실제 앱에서 오류·빈 상태일 때 상태줄 '12개 항목'은 캡처 자료(가짜)가 항목을 둔 탓이며 실제 앱은 0개로 나올 것으로 보이나 확인하지 못함. 한글 줄바꿈은 글자 단위(어절 보호 없음).

## 사용자 실기 확인 항목
- 실제 125·150% 모니터에서 안내 두 줄·아이콘 이름 두 줄 표시, 분할선 끌어 영역을 최소로 줄였을 때 안내 줄(1.5행)이 목록 줄을 가리는지.
- 놓을 영역 강조가 실제 끌어다 놓기 중에 보이는지.
- 고대비 테마에서 놓을 영역 머리글 색.

## 미확인
120·192dpi 캡처는 시험(렌더 통과)만 했고 PNG를 열어 보지 않았다. 실제 창(DWM 테두리·그림자)과의 차이는 캡처 모드로 알 수 없다.
