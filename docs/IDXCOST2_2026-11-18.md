# IDXCOST2 측정 및 구현 기록 (2026-11-18)

## 변경 사항

- `content_short_grams`의 새 형식은 `(gram, doc_id)`이며 `doc_id`는 `content_meta.rowid`를 참조한다.
- Python 색인기는 `PRAGMA user_version=1`을 기록한다. 기존 `(gram, path)` 표를 감지하면 트랜잭션 안에서 새 표로 재생성하고 `content_fts`에서 기존 문서의 조각을 복원한다.
- Python 단어 검색, 키워드 검색, 재색인, 삭제 및 제외 문서 정리 경로를 `doc_id` 조인/삭제로 바꿨다. 조각 표가 완전하지 않은 경우의 기존 LIKE 폴백은 유지한다.
- Rust 색인기는 새 DB에서 `(gram, doc_id)`를 생성한다. 구형 `(gram, path)` 표를 발견하면 해당 구조를 유지하며 구형 방식으로 쓰므로, Python을 거치지 않고 옛 DB를 연 경우도 동작한다.

## 합성 3,000문서 측정

동일한 3,000개 UTF-8 TXT 파일(문서마다 같은 합성 본문 4회, 파일당 약 0.5 KB)을 Rust `index-content`로 각각 색인했다. 구형 DB는 기존 FTS 및 `(gram, path)` 스키마를 미리 만든 뒤 색인했고, 새 DB는 색인기가 새 표를 생성했다. 색인 명령의 전체 경과 시간과 WAL 체크포인트 후 SQLite 페이지 크기를 측정했다.

| 표 구조 | 문서 수 | 조각 행 | DB 크기 | 색인 시간 |
|---|---:|---:|---:|---:|
| `(gram, path)` | 3,000 | 292,956 | 80,228,352 bytes (76.5 MiB) | 163.752 s |
| `(gram, doc_id)` | 3,000 | 292,956 | 29,655,040 bytes (28.3 MiB) | 104.635 s |
| 변화 | — | 동일 | −50,573,312 bytes (−63.0%) | −59.117 s (−36.1%) |

측정은 이 PC의 release `klib.exe`와 같은 문서 입력으로 수행했다. 이 수치는 합성 TXT 입력에서의 비교이며 다른 문서 형식·본문 분포의 성능을 보장하지 않는다.

## 검증 상태

- `cargo build --release --manifest-path klib/Cargo.toml`: 통과 (release 빌드, 9분 27초; 기존 deprecation/dead-code 경고 출력).
- `KLIB_EXE=... python -X utf8 -m unittest tests.test_rlev_rust_index_levels`, `python -m unittest discover -s tests -p "test_timemachine*.py"`, `cargo test --manifest-path klib/Cargo.toml`: 실행하지 않음.
- 작업 트리만 변경했으며 커밋·푸시는 하지 않았다.
