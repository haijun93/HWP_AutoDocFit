# IDXCOST2 측정 및 구현 기록 (2026-11-18)

## 변경 사항

- `content_short_grams`의 새 형식은 `(gram, doc_id)`이며 `doc_id`는 `content_meta.rowid`를 참조한다.
- Python 색인기는 `PRAGMA user_version=1`을 기록한다. 기존 `(gram, path)` 표를 감지하면 트랜잭션 안에서 새 표로 재생성하고 `content_fts`에서 기존 문서의 조각을 복원한다.
- Python 단어 검색, 키워드 검색, 재색인, 삭제 및 제외 문서 정리 경로를 `doc_id` 조인/삭제로 바꿨다. 조각 표가 완전하지 않은 경우의 기존 LIKE 폴백은 유지한다.
- Rust 색인기는 새 DB에서 `(gram, doc_id)`를 생성한다. 구형 `(gram, path)` 표를 발견하면 해당 구조를 유지하며 구형 방식으로 쓰므로, Python을 거치지 않고 옛 DB를 연 경우도 동작한다.

## 합성 3,000문서 측정

동일한 3,000개 UTF-8 TXT 입력을 Rust release 색인기로 각각 색인했다. 각 문서는 동일한 합성 한국어 문단 4개와 문서 번호를 포함한다. 구형 DB는 `(gram, path)` 표를 미리 만들었고, 신형 DB는 색인기가 `(gram, doc_id)` 표를 생성했다. 명령 전체 경과 시간을 재고, WAL 체크포인트 후 DB 파일 크기와 조각 행 수를 읽었다.

| 표 구조 | 문서 수 | 조각 행 | DB 크기 | 색인 시간 |
|---|---:|---:|---:|---:|
| `(gram, path)` | 3,000 | 34,823 | 29,802,496 bytes (28.42 MiB) | 130.072 s |
| `(gram, doc_id)` | 3,000 | 34,823 | 23,633,920 bytes (22.54 MiB) | 83.908 s |
| 변화 | — | 동일 | −6,168,576 bytes (−20.7%) | −46.164 s (−35.5%) |

이 측정은 같은 PC·release 실행 파일·합성 입력에 대한 비교다. 다른 문서 형식이나 본문 분포의 성능을 보장하지 않는다.

## 검증 상태

- `cargo build --release --manifest-path klib/Cargo.toml`: 통과. 기존 deprecation/dead-code 경고 출력.
- `KLIB_EXE`를 방금 빌드한 release 실행 파일로 지정한 `python -X utf8 -m unittest tests.test_rlev_rust_index_levels`: 7건 통과. 새 `doc_id` 스키마 쓰기와 구형 `path` DB 쓰기를 포함한다.
- `python -X utf8 -m unittest discover -s tests -p "test_timemachine*.py"`: 303건 통과. 테스트 도우미가 구형 열 이름을 사용하던 14건을 새 스키마 관계에 맞춰 수정했고, 기존 검색 및 일관성 검증은 유지했다.
- `cargo test --manifest-path klib/Cargo.toml`: Rust 통합시험 묶음 22건 통과, klib 테스트 123건 통과·1건 무시, HWP 스캔 3건 통과, 문서 시험 0건.
- 저장소 `.venv` 실행 파일이 없어 PC에 설치된 Python 3.14로 Python 시험을 실행했다.
- 변경은 작업 트리에만 두었으며 커밋·푸시는 하지 않았다.
