# SEMI1 구현 범위와 합격 기준

- 기준선: `bf624ca5`, 기능 브랜치에서만 작업하고 로컬 커밋까지만 한다.
- 범위: Python·Rust 순수 파서, SQLite·Tantivy 본문/파일명 교집합, 묶음별 근거, ktm 옵션·칩·강조, 합성 결과 대조, legacy 연결 설계.
- 기존 설정·API의 기본 동작은 유지한다. Python은 `related_groups=True`, ktm은 `settings.json`의 `related_queries=true`로 새 경로를 켠다.
- 문법: 묶음은 따옴표 밖 `;`, 공백은 낱말 AND, 따옴표 안 공백·세미콜론은 문자 그대로다. 빈 묶음·빈 따옴표는 무시한다. 미완성 따옴표는 검색 오류이며 입력 중 화면은 멈추지 않는다. `&`, `~N`, 필터 모양은 새 경로에서 일반 문자다. 근접·필터 문법 결합은 이번 범위 밖이다.
- 같은 문단에 모든 낱말이 있는 묶음별 결과를 만든 다음 문서 교집합을 구한다. 문단이 검색 단위다(문장 분리는 후속). 파일명은 하나의 문단으로 본다. 순위는 가장 높은 위계, 묶음별 일치 문단 수 합, 경로 오름차순이다. 결과 제한은 교집합 뒤 적용한다.
- 근거는 `group_matches`: 묶음 순번·원래 질의·낱말·일치 문단 수·문단 번호/위계/발췌/강조 좌표. 좌표는 Unicode 문자 번호이며 ktm 자체 강조 좌표는 기존대로 UTF-8 바이트다.
- 기존 응답 키는 보존하고 새 필드만 추가한다. 기본 질의는 기존 경로에 그대로 위임한다.
- 상태: Rust 어댑터 `stopped → ready → request → ready`, I/O 오류/시간 초과는 `stopped`로 복귀한다. stdout은 프로세스당 독자 하나만 읽는다. ktm 입력/첫 그림에서는 I/O·검색을 수행하지 않고 기존 worker·세대 취소 흐름을 유지한다.
- 합격: 새 회귀 시험 통과, 합성 seed 20261124의 SQLite/Rust 문서 집합·묶음 근거 차이 0, 관련 cargo 및 전체 Python 시험 기록. 실제 첫 그림 16ms 충족은 격리 실측으로만 판정한다.
- 기준선에는 `search_backend.py`, `search_cli.rs`, SRCH3 문서·생성기가 병합되지 않았다. 별도 SRCH3 소스는 읽기만 했고 자동 cherry-pick하지 않는다. 이번 어댑터/CLI는 독립된 옵션 기능이므로 SRCH 통합 병합 시 명령·계약 조정이 필요하다.
