# LEVELKEY0 결과 — 같은 위계 단위 내어쓰기 값 그림자 측정

## 판정

**실제 재사용은 제안하지 않는다.** 이번에 값이 기록된 표본에서 `marker_only` 유형은 같은 키라도 값이 달라지는 문단이 있었고, 100% 일치한 유형의 추정 절감은 기록된 호출의 30%에 못 미쳤다. 3개 ALLQA 문서의 JSONL이 비어 있어 ALLQA 전체의 절감률은 확정하지 못했다. 제품 엔진에는 재사용 로직을 넣지 않았다.

| 항목 | 결과 |
|---|---:|
| ALLQA 대상 | 6건 (TXT 2, HWP 1, HWPX 3) |
| JSONL 실측 행 | 94건, 3개 문서에서만 확보 |
| JSONL 문서별 서로 다른 키 | `txt_short` 2, `txt_long` 11, `hwpx_continuation` 3 |
| 값이 달라진 키 | `txt_long` 2개 키 (14문단/7값, 5문단/3값) |
| 표본의 전체 추정 절감 | 62/94회 (66.0%, 불일치 키를 제외한 개별 키 기준) |
| 100% 일치 유형만 대상으로 한 추정 | 5/94회 (5.3%, `custom_prefix`) |
| 결과 문서 비교 | 완료 5/5건 변경 문단 0, 텍스트·정규화 서식 해시 모두 일치 |
| 측정 실패 | `hwpx_table`은 문서 열기 실패. `hwp_reference`, `hwpx_shapes`, `hwpx_table` JSONL 0행 |

여기서 62회는 유형 안전성을 적용하기 전, 관측된 각 키 그룹 중 값이 모두 같았던 그룹만의 상한 추정이다. `marker_only`나 콜론 라벨처럼 유형 안에 불일치 키가 하나라도 있으면 해당 유형 전체를 제외한다. 그 기준에서 남는 `custom_prefix` 절감 추정은 기록된 호출의 5/94회(5.3%)다. 미기록 문서가 있으므로 ALLQA 전체 30% 기준은 미측정으로 남긴다.

## 키 정의 및 계측 범위

그림자 레코드는 `DOCFIT_INDENT_KEY_SHADOW=1`일 때만 추가한다. 내어쓰기 적용이 성공해 최종 쌍을 검증한 직후 `(LeftMargin, Indentation)` HWPUNIT 값을 JSONL에 한 행 기록한다. 키는 다음 필드의 조합이다.

- `prefix`: 문단 텍스트의 시작부터 본문 기준 오프셋 직전까지의 선행부 원문
- `prefix_style`: 본문 기준점 캐럿에서 읽은 한글 글꼴·높이·장평·자간·굵기
- `paragraph`: 기준 왼쪽 여백, 문단 정렬, 표 안 여부, 자동 줄바꿈 여부

글자 모양은 선행부 각 글자를 따로 순회해 얻은 서식 벡터가 아니라 본문 기준점 캐럿의 대표값이다. 페이지 번호는 기록하지 못했다. 자동 줄바꿈은 값 측정 직전 기존 여백을 0으로 두고 얻은 첫 줄 끝을 사용하므로 최종 적용 후 페이지 배치와 다를 수 있다. 따라서 이 표본은 후보 유형을 거르는 그림자 분석이며 적용 안전성 증명으로 해석하지 않는다. `DOCFIT_INDENT_KEY_SHADOW`가 설정되지 않으면 훅은 파일을 기록하지 않는다.

## 호출 절감 추정과 비교 검증

JSONL 한 행은 내어쓰기 값의 성공 측정 1회를 뜻한다. 동일 문서의 동일 키에서 값이 모두 같은 그룹에 대해 `문단 수 - 1`을 줄일 수 있었던 측정 호출로 계산했다. 이 방식의 키 적중률은 62/94회지만, 불일치가 있는 유형을 통째로 제외하면 5/94회(5.3%)로 줄어든다.

이번 실행의 COM 성능 기록에서 내어쓰기 세 단계 호출은 합계 16,564회였다. 비교용 기존 ALLQA 결과와 `allqa_compare.py`를 실행했다. 완료된 문서 5건 모두 변경 문단 0개였고 텍스트 XML 및 정규화 서식 XML 해시가 일치했다. `hwpx_table`은 두 결과 모두 열기 실패라 비교할 산출물이 없다. 기존에도 나타난 텍스트 보존 QA 실패는 TXT 2건과 `hwp_reference`에서 양쪽 모두 동일했다.

그림자 읽기 자체가 COM 계측에 추가되므로 기준 스냅샷 대비 전체 COM 호출 수는 비교 대상 완료 문서에서 1,410회 늘었다(TXT 짧은 120, TXT 긴 1,170, HWPX 연속문서 120). 이 증가는 출력 변경이 아니라 그림자 기록의 COM 속성 읽기 비용이다. 단회 측정이며 시간 차이는 성능 개선이나 저하 근거로 사용하지 않는다.

SPDMEMO3 표본은 저장소의 ALLQA manifest와 `docs`, `tests`에서 확인되지 않아 포함하지 못했다. ALLQA에 없는 추가 자료가 따로 있다면 이 보고서 결과 범위 밖이다.

## 적용 권고

이번 표본으로는 적용하지 않는다. 같은 기호 유형에서 불일치가 있었고 안전 유형으로 좁힌 추정 절감률도 30% 기준보다 낮다. 따라서 키 무효화 조건·verify 모드·런타임 재사용 설계는 제안하지 않는다. 향후 재검토 시에는 페이지 위치와 선행부 전체의 글자 모양 벡터를 포함한 계측, JSONL 누락 문서의 원인 확인, 대상 문단 30% 이상 절감 여부를 먼저 확인해야 한다.
