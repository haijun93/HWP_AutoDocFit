# INDENTW3 결과 — 폭 표 내어쓰기를 일괄 적용에 연결

- 브랜치 `feature/INDENTW3`(`feature/INDENTW2` 병합). 로컬 커밋만, 푸시 안 함.
- 사용자 결정(2026-11-26): 공문 글꼴은 기본안대로, 한/글 Shift+Tab 대비 0.5pt 이내.

## 한 일

확인한 글꼴·조건의 문단만 폭 표 값을 쓰고, 나머지는 기존 한/글 Shift+Tab 그대로다.

1. **XML 직접 기록** — HWPX 일괄 서식 직후, 일괄 서식이 처리한 문단 중 조건에 맞는 문단의 `left`/`intent` 를 직접 쓴다.
2. **Shift+Tab 건너뛰기** — 최종 내어쓰기 단계에서 문서를 HWPX 로 한 번 떠 표 값을 계산하고, 한/글의 현재 값이 표 값과 같은(±2 HWPUNIT) 문단은 Shift+Tab 을 실행하지 않는다. 값이 다르면 Shift+Tab 으로 처리한다.
3. 설정 `indent_table`(기본 켜짐). 끄면 두 경로 모두 동작하지 않는다.
4. 로그: `[폭 표 내어쓰기] XML 직접 기록 N문단`, 단계마다 `[폭 표 내어쓰기] 표 처리 A문단 / 한/글 처리 B문단`.

### 표를 쓰지 않는 조건(기존 방식)

- 원본이 HWP(확장자만 `.hwpx` 인 바이너리 포함). 작업용 HWPX 로 바꿔 처리해도 기존 방식.
- 한/글 판이 실측 판(9.6.1.10778)과 다름, 글꼴 파일(SHA-256)·HFT 묶음이 표를 만든 때와 다름(`resources/font_widths_env.json`).
- 표 칸·글상자·개체가 있는 문단, 탭, 고정폭·묶음 빈칸.
- 가운데·오른쪽 등 정렬, 최소 빈칸(condense) ≠ 0, 글꼴에 어울리는 줄 높이, 번호·글머리표, `breakLatinWord` 가 낱말 유지가 아님, 자동 간격.
- 커닝, 글자 위치, 첨자, 외곽선, 그림자, 밑줄, 취소선, 강조점, 기울임, 양각, 음각.
- 크기 10~22pt, 장평 70~120, 자간 −15~10, 상대크기 90~110 밖.
- 격자 맞춤, 가로 방향 쪽, 제본 여백, 다단, 세로쓰기. 양쪽 정렬인데 본문 줄을 좁힐 수 있는 떠 있는 개체가 있는 구역.
- 계산이 `None` 이거나 `exact == False`, 표에 없는 글꼴, 왼쪽 정렬에서 기준 뒤 첫 낱말이 첫 줄을 넘을 수 있음.
- 문서 끝 번호 붙임 묶음(기존 번호 세로 정렬 규칙).
- 문단 세트 방식(`알파_문단세트_사용`, 기본 꺼짐)은 검사기를 넘기지 않으므로 모두 Shift+Tab.

## 합성 문서 전후 비교(실제 한/글 9.6.1.10778)

합성 TXT(8묶음, 저장 결과 61개 문단 중 내어쓰기 58개, 5쪽, 모든 긴 문장이 서로 다름)를 `scripts/smoke_engine_pc.py --mode format` 으로 처리. 설정 폴더는 임시 폴더로 돌려 사용자 설정을 쓰지 않았다. 끔·켬을 번갈아 2회씩.

| 항목 | 끔 1 / 2 | 켬 1 / 2 | 차이 |
|---|---|---|---|
| 전체 시간(초) | 240.0 / 239.5 | 206.7 / 206.3 | 약 −33초(−14%) |
| 최종 서식 기준 내어쓰기(초 / COM 호출) | 33.1 / 8,854 · 32.8 / 8,854 | 22.1 / 6,573 · 22.1 / 6,573 | −11초, −2,281회 |
| 최종 내어쓰기 재확인(초 / COM 호출) | 34.2 / 8,856 · 34.6 / 8,856 | 11.6 / 4,607 · 11.7 / 4,607 | −23초, −4,249회 |
| 내어쓰기 두 단계 합(초) | 67.3 / 67.4 | 33.7 / 33.9 | −50% |
| COM 호출 총계 | 90,221 / 90,221 | 83,692 / 83,692 | −6,529회(−7.2%) |
| XML 직접 기록 | – | 8 / 8문단 | |
| 표 처리 / 한/글 처리(1차 단계) | 0 / 58 | 32 / 26 | |
| 표 처리 / 한/글 처리(재확인) | 0 / 58 | 56 / 2 | |

- **내어쓰기 값**: 58개 중 50개는 같고 8개(`※` 문단)가 1 HWPUNIT(0.01pt) 다르다. 왼쪽 여백 차이 0. 끔끼리는 차이 0.
- 쪽수(5)·문단 수(59)·공백 제외 글자·원본 파일은 모든 실행에서 보존.
- 1차 단계의 "표 처리 32" 는 XML 로 쓴 8개와, 일괄 서식이 서식 예시 값으로 이미 같은 값을 넣은 24개다.

### 측정에서 알게 된 것

- 처음 만든 합성 문서(긴 문장이 8번씩 반복)에서는 XML 직접 기록이 **0문단**, COM 98,877 → 93,004회였고 전체 시간은 끔 360.7 / 271.9초, 켬 376.5 / 366.7초로 흔들려 단축을 확인할 수 없었다. 반복 문장은 일괄 서식 대상에서 빠지고(한 번만 나온 글만 대상), 시간은 호출 수가 같은 "쪽 맞춤" 단계가 96~174초로 흔들린 영향이 컸다. 출력 값 차이는 0건이었다.
- 따라서 효과는 문서 구성에 따라 다르다. XML 직접 기록은 일괄 서식이 처리한 문단에만 닿고, 한/글 경로로 서식을 입히는 문단은 1차 단계에서 여전히 Shift+Tab 을 쓰며 재확인 단계에서만 줄어든다.

## 한/글 COM 안전

- 합성 문서만 새 인스턴스에서 열었고 COM 잠금을 잡았다. 전체 시험 잠금이 있는 동안은 기다렸다.
- 한 번은 비교 실행에 590초 제한을 걸어 두 번째 실행 중에 강제 종료됐고, 한/글 프로세스 1개와 COM 잠금이 남았다. 창 제목이 이 코드의 합성 임시 문서(`indent_table.hwpx`)임을 확인하고 그 프로세스만 종료한 뒤 자기 잠금을 지웠다.

## 남은 문제

1. **HWP 문서에는 효과가 없다**(카드 범위). 파이프라인은 HWP 를 작업용 HWPX 로 바꿔 처리하므로, 실제 HWP 문서로 0.5pt 를 확인하면 켤 수 있다.
2. HWPX 입력 문서로는 전후 비교를 하지 않았다(TXT 입력만). 양쪽 정렬·HFT 글꼴이 섞인 실제 서식에서의 파이프라인 비교도 없다. 계산 정확도 자체는 INDENTW2 의 대조 결과에 의존한다.
3. 다른 한/글 판·다른 글꼴 판 PC 에서는 꺼진다. 대상 PC 가 이 PC 와 다르면 이득이 없다.
4. 최종 내어쓰기 단계마다 문서를 임시 HWPX 로 저장한다(기존 제목·쪽 맞춤 단계와 같은 방식). 큰 문서에서의 저장 시간은 재지 않았다.
5. 한/글이 `scripts/measure_indent_hangul.py` 의 합성 문서 `pagePr` 여백을 무시하고 기본 여백(8504)을 쓴다. 한/글이 저장한 HWPX 는 실제 여백을 기록하므로 앱 동작에는 영향이 없지만, 원인은 알아내지 못했다.
