# HS2-H 조사·재현 및 검증 (2026-11-12)

## 개선 전 재현

- 실제 Markdown 2개를 추출·색인. `split.md`: 문서 제목 `시설 사업`, 장 제목 `관광안내판`, 본문 `해체공사 시행 계획을 수립한다.`
- `direct.md`: 같은 문서 제목, 장 제목 `일반 시설`, 본문 `관광안내판 해체공사 시행 계획을 수립한다.`
- 질의 `관광안내판 해체공사`: 2건 반환. 분산 문서 1위, 직접 일치 문서 2위.
- 분산 문서 선택 문단은 본문이 아닌 `## 관광안내판`. breadcrumb는 `시설 사업`, context_hits=0. 직접 일치 문서 breadcrumb는 `시설 사업 > 일반 시설`.
- 문서 단위 AND로 회수는 되지만, 원하는 본문 선택과 직접 일치 우선 순위를 충족하지 못하므로 개선 필요.
- 재현 시험: `tests.test_hs2_hsa` 1개 통과.

## 성능 기준선

`scripts/benchmark_hs2_hsa.py`: 300문서 × 40문단(12,000문단), 분산 질의 5개와 직접 일치 질의 5개. 각 질의 예열 1회 후 5회 측정 중앙값, 이 10개 값의 중앙값을 비교. SQLite 합성 색인 사용, 추출 시간 제외, 기본 limit=100.

- 개선 전 질의별 중앙값(ms): 62.223, 57.343, 77.000, 71.494, 58.592, 157.127, 165.027, 188.159, 236.386, 154.915.
- 개선 전 전체 중앙값: **115.958ms**.

## 개선 내용과 결과

- 색인 스키마·저장 본문·스키마 버전은 변경하지 않았다. 기존 색인으로 검색 가능하며 재색인이 필요하지 않다.
- SQL 집계로 한 문단에 모든 질의어가 있는지 확인한다. 그런 문서의 기존 선택 문단·점수·정렬 기준은 그대로 사용한다.
- 직접 일치가 없는 후보 문서만 문단을 읽고 `hierarchy_path.parents`로 조상을 계산한다. 문단 본문과 조상 제목 원문이 질의어를 모두 포함하면 해당 문단을 선택한다. 표시 경로의 60자 제한은 검색 문맥에 적용하지 않는다.
- 문맥 일치 결과는 기존 직접 일치 결과 뒤에 둔다. `score`, `match_counts`, `total_matches`는 기존 실제 본문 언급 횟수를 유지한다. `context_hits`에는 선택 문단의 조상에 있는 서로 다른 질의어 수를 반환한다.
- 예제 개선 후: 직접 일치 문서 1위, 분산 문서 2위. 분산 문서 발췌문은 `해체공사 시행 계획을 수립한다.`, breadcrumb는 `시설 사업 > 관광안내판`, context_hits=1.
- 의도한 순위 변화: 재현 예제의 직접 일치 문서는 2위→1위, 분산 문서는 1위→2위. 직접 일치 문서끼리의 상대 순위와 반환 내용은 유지한다. 세 정렬 모드에서 이를 별도 시험했다.
- 기존 문서 단위 AND 결과는 제거하지 않는다. 본문+조상에서 AND를 충족하지 못하는 기존 결과는 종전 선택/집계로 반환한다(호환성 유지).
