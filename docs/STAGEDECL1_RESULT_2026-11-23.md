# STAGEDECL1 결과 — 선언표와 shadow planner

작성일: 2026-11-23

## 구현 범위

`docfit_core/stage_registry.py`에 `StageDeclaration`, `StageKind`, `STAGE_REGISTRY`, `plan_stages(...)`, `StagePlanDiff`를 추가했다. 선언표는 `stage_selection.py`의 단계 키 32개와 `pipeline.py` 선행 `선행목록`의 XML 처리기 19개를 담아 총 51개 선언이다. 단계 종류는 XML 처리기, 한/글 읽기, 한/글 쓰기, 조판 의존 네 가지다. 쪽 범위 지원 여부와 모드·세부 선택 조건을 선언에 기록했다. 계획기는 문서 엔진이나 COM을 호출하지 않는다.

계획 입력은 작업 모드, 파이프라인 옵션 매핑, 쪽 범위 지정 여부, 세부 단계 선택 매핑이다. 모드별 단계는 `stage_selection._MODE_STAGES` 순서를 따르고, 선행 XML 목록은 모드·옵션·프로필·쪽 범위 조건으로 계산한다. `StagePlanDiff`는 순서, 누락, 중복/추가를 비교한다.

## 무회귀 비교

현재 저장소의 `stage_selection.py`에서 유효한 작업 모드는 `all`, `format`, `spacing`, `unify` 네 종류다. 요청 설명의 여섯 모드와 달라 저장소에서 실제 제공하는 네 모드를 모두 대상으로 삼았다. 모드마다 독립 옵션 256 조합을 만들고, 세부 단계 선택 상태와 쪽 범위 미지정/지정을 포함해 총 **2,048개** 입력을 비교했다. 기준 함수는 시험 파일 안에서 `pipeline.py`의 선행 목록 추가 조건을 옮겨 작성했으며, 엔진을 가져오거나 실행하지 않았다.

- 전체 입력 비교 차이: **0건**
- 입력별 이름·순서 차이: **없음**
- 선언 ID 중복: **없음**
- 존재하지 않는 선행 선언 참조 및 순환: **없음**
- `stage_selection` 키 중 선언 누락: **없음** (32/32)

## 한계와 다음 단계 제안

현재 비교 기준은 시험 안의 `pipeline.py` 조건 전사본이다. macOS에서 Windows 전용 엔진 경로를 실행할 수 없어 실제 런타임 `선행목록`과 동적 프로필 값을 직접 관찰한 검증은 아니다. 조합에서 사용한 옵션은 파이프라인 분기를 대표하는 독립 불리언 및 선택 상태이며 실제 모든 사용자 설정 객체의 값 공간 전체를 열거한 것은 아니다. 따라서 이 결과는 지정 범위의 순수 계획 비교 통과를 뜻하며 실행 동등성이나 문서 결과 동등성을 뜻하지 않는다.

다음 단계에서는 Windows 시험 환경에서 엔진 진입 전 실제 컨텍스트 값을 planner 입력으로 변환하고, 기존 `선행목록`과 planner의 XML 처리기 이름/순서를 shadow 비교 로그로 대조할 것을 제안한다. shadow 결과를 충분히 축적한 뒤 별도 변경에서만 목록 생성부를 planner 호출로 바꾸고, 실제 실행 경로 전환은 별도 회귀 검토 후 진행한다. 이번 단계에서는 `pipeline.py` 실행 경로를 수정하지 않았다.
