## 구현과 안전 경계

호출은 `generate_hwpx(markdown_text, new_target, image_dir=asset_directory)`이며 `render_hwpx`와 `parse_markdown`에도 같은 선택 인자를 추가했다. 이미지 디렉터리 생략 시 파일을 찾으러 다니지 않고 경고와 Markdown 참조를 남긴다. 문자열 API이므로 MD 파일 위치에 대한 암묵적 추정은 하지 않는다. 경로를 다루는 입력 어댑터가 MD 부모 또는 별도 이미지 디렉터리를 명시해야 한다.

정상 PNG/JPG/JPEG는 기존 Pillow 13.0.0으로 형식·픽셀·압축 데이터 손상을 확인한 뒤 원본 바이트 그대로 `BinData/imageN.png|jpg`에 넣는다. 본문·제목·강조·표 칸에서 `hp:pic`를 만들고 `hc:img/@binaryItemIDRef`로 OPF 항목을 참조한다. 대체글은 `hp:shapeComment`에 보관한다. 일반 본문 글자로 중복 삽입하지 않는다. PNG/JPG 파일 내용과 확장자가 다르면 거절한다.

`path_utils.path_is_within`과 `Path.resolve()`로 이미지 디렉터리 내부 여부를 검사한다. `../`·역슬래시 상위 이동·절대 경로·드라이브 상대 경로·UNC·URL·NTFS ADS·심볼릭 링크 이탈을 거절한다. 누락·손상·미지원 형식·상한 초과도 경고 후 참조 전체를 일반 글자로 남긴다. 참조 거절은 문서 전체 오류로 전파하지 않는다. 그림당 16MiB·4천만 픽셀, 문서당 256개·64MiB 상한이다. 파일 크기는 stat와 제한 읽기 양쪽에서 확인한다. 경로에 괄호가 있거나 `<…>`로 둘러싼 경로, 선택적 따옴표 제목, `.jpeg`도 추가 단위 시험으로 확인했다.

그림의 기본 크기는 96dpi(픽셀당 75 HWPUNIT)이며 확대하지 않는다. 폭은 본문 48,189 HWPUNIT(170mm), 표 칸에서는 칸 폭에서 좌우 여백을 뺀 값 이내로 축소한다. 세로도 70,000 HWPUNIT 이내로 비율을 유지해 한 쪽 높이에 들어가게 한다. 정수 반올림으로 1 HWPUNIT 이내 차이가 날 수 있다. 그림은 글자처럼 배치한다.

제목은 1~6단 각각 `제목 N`/`Heading N` 스타일로 기록한다. 4·5·6단은 한컴돋움 굵게 14·12·11pt이고 1~3단은 기존 16pt를 유지한다. Markdown `#` 표식은 본문에 남기지 않는다. 코드 블록은 별도 `코드`/`Code` 스타일, 고정폭 `굴림체` 10pt·왼쪽 정렬이며 강조/HTML/그림을 해석하지 않는다. 빈 줄과 앞 빈칸을 보존하고 탭은 4칸 탭 정지점으로 펼친다. 인라인 코드도 같은 고정폭 글꼴을 쓴다. 더 긴 닫는 코드 울타리도 허용한다.

링크는 표시 글자·내부 강조를 보존하고 “하이퍼링크 대상 미지원: 표시 글자만 보존했습니다” 경고를 낸다. URL의 중첩 괄호가 본문에 남지 않게 참조 끝까지 읽는다. **하이퍼링크 필드는 미구현**이다. 일반 문단의 soft/hard 줄바꿈·역슬래시·`<br>`와 표 칸 줄바꿈은 기존처럼 `hp:lineBreak`로 보존한다.

상태 순서는 입력 해석 → 안전한 그림 읽기/참조 폴백 → XML/ZIP 조립 → 임시 패키지 검증 → 배타적 새 파일 게시다. 기존 결과를 덮어쓰지 않으며 검증 실패 시 최종 파일을 게시하지 않는다. 새 의존성·COM·kordoc·네트워크 호출을 생성기에 추가하지 않았다.

## BinData와 OPF 조사

RSXML0의 ZIP 멤버·바이너리 해시·tail 텍스트 보존, RSXML4의 서식 ID/개수·본문/칸 폭 규칙을 확인했다. 이 문서들에는 BinData 등록 명세가 없어 저장소의 `resources/서식예시/표 서식모음.hwpx` 실제 구조를 함께 읽었다.

샘플은 `Contents/content.hpf`의 `opf:item id="image1" href="BinData/image1.jpg" media-type="image/jpg" isEmbeded="1"`와 본문 `hc:img binaryItemIDRef="image1"`를 연결한다. **header.xml에는 별도의 BinData 목록이 없다.** 따라서 임의의 header binaryData 요소를 만들지 않고 OPF에 등록했다. JPEG MIME은 `image/jpeg`를 사용했다. OPF namespace 끝 `/`와 ZIP 루트 기준 href는 KORDOCC1에서 확인한 규칙을 유지했다. META-INF manifest에도 같은 그림 항목을 등록했다.

첫 COM 시험부터 19/19 열기에 성공해 OPF 원인 분리 재시험은 필요하지 않았다. 한/글 재저장 뒤에도 그림 바이너리 SHA-256·대체글·크기가 모두 동일했다. 생성 XML 문법만 검사해 열림을 추정한 결과가 아니다.

## 시험과 재현

사용자 지정 Python 3.15.2, Pillow 13.0.0을 사용했다. 신규 11개 시험은 19종 독립 정답, PNG/JPG 패키지·바이트·대체글·비율·표 칸 폭, 경로 거절·심볼릭 링크 이탈·손상·확장자 위장·자원 상한, 제목 스타일, 코드 폰트/빈 줄, 링크/줄바꿈, 괄호·선택 제목·JPEG 확장자를 검사하며 모두 통과했다.

관련 72개(기존 생성기/추출기 19 + 기존 비교 harness 42 + 신규 11) 실행 결과는 통과 71, 실패 1, 제외/오류 0이다. 기존 `test_unsupported_features_explicitly_warn`는 제목·코드가 미지원인 시점의 경고 수 4를 기대한다. 새 동작의 실제 경고는 이미지 디렉터리 누락과 링크 대상의 **2개**다. 원 시험 수정·경고를 인위적으로 추가하는 우회는 하지 않았다. 전체 시험 완전 통과로 보고하지 않는다.

```text
python -m unittest discover -s tests -p test_markdown_hwpx_v2.py
python scripts/benchmark_markdown_hwpx.py generate --out <새 산출폴더> --reference
python scripts/benchmark_markdown_hwpx.py com --out <같은 산출폴더>
python -m unittest discover -s tests
```

산출폴더는 저장소 밖이어야 한다. `--reference`는 설치된 kordoc 4.24.9와 동일 이미지 디렉터리/보고서 프리셋을 사용한다. 네트워크 설치를 하지 않았다. 전체 시험은 구현 커밋 `554456b3`의 git archive 격리 사본에서 공용 COM 잠금 아래 단독 실행했다. **3,620개 실행·통과 3,591·제외 28·실패 1·오류 0, unittest 1,026.512초, 래퍼 1,043.963초, 종료 코드 1**이다. 실패는 위 경고 개수 기대 시험 한 건이며 다른 실패는 없다. 20분 상한 안에 종료했고 시험 사본의 코드를 수정하지 않았다. 최종 커밋에서는 결과·근거·진행·인계 문서만 추가/보완했다.

원시 로그에는 logging의 `%d` 인자 형식 오류 2회, `test_startup_deferral`의 파일 닫힘 ResourceWarning, 종료 시 임시 `timeline-content.sqlite` 잠금으로 인한 atexit 정리 오류 1건도 있었다. logging/atexit 현상은 KORDOCC1 보고에도 기록돼 있다. 이 경고들의 별도 원인 조사는 **확인 못 함**이며 이번 생성기 밖의 후속 과제다. unittest 오류 수와 구분해 남긴다. 작업 폴더의 fixture·본체는 바뀌지 않았고 본체 CRLF 3,523줄을 유지했다. 커밋 전 UTF-8·한글 깨짐·PC 전용 경로·공백 검사를 수행했다.

## 미구현·확인 못 함·KORDOCD 연결 제안

- 하이퍼링크 필드는 미구현이다. 링크 대상 클릭·필드 호환성은 확인 못 함. 지원 동작은 경고+표시 글자다.
- 이미지 EXIF 방향·색 프로필·애니메이션, 투명 PNG의 화면 렌더링, PDF 픽셀 비교, 긴 다쪽 문서 조판·복잡한 부동 개체 배치는 확인 못 함. 이번 COM 결과는 화면 조판 동등성 판정이 아니다.
- CommonMark 전체 문법, 참조형 링크/그림·복잡한 HTML·병합/중첩 표·수식·각주·사용자 템플릿은 이번 범위 밖이다. 19종의 성공을 오피스 입력 전체 합격으로 확장하지 않는다.
- 앱에는 연결하지 않았다. KORDOCD에서 MD 입력 어댑터가 UTF-8 원문과 명시적 이미지 루트를 넘기고, DOCX/XLSX/PPTX 어댑터는 `Paragraph/Run/Table/Image` 공통 블록으로 제목/번호/그림 자원을 전달하도록 제안한다. 구조 입력 writer의 외부 공개 API는 후속 구현이다.
- 설정 키 `markdown_hwpx_engine = kordoc | internal | auto`를 제안한다. 첫 연결의 기본값은 기존 `kordoc`으로 둔다. `auto`는 지원 범위 입력에 내부 생성기를 시도하고 구조 검증 실패·그림 삽입 실패 등 손실 경고가 있으면 kordoc으로 한 번만 폴백한다. 링크 대상 필수 입력도 내부 경로를 피한다. 취소·기존 결과 충돌은 엔진 폴백 사유로 삼지 않는다.
- 라우팅 상태는 `입력 준비 → 내부 생성 시도 → 내부 검증 → 게시` 또는 `폴백 결정 → kordoc 시도 → 검증 → 게시/실패`로 명시한다. 양쪽 결과를 별도 임시 경로에 만들고 경고/검증을 판정한 뒤 최종 이름을 한 번만 배타적으로 게시한다. 이미 게시한 파일을 덮어쓰는 폴백·무한 재시도는 금지한다. 실패 사유와 실제 사용 엔진을 결과에 남긴다.
