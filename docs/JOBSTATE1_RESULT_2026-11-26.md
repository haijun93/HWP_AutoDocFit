# JOBSTATE1 — 파일별 상태 구분·이어하기·실패 보호

작성: 2026-11-26 · 브랜치: `feature/JOBSTATE1` (`feature/ROLLBACK1` 병합 상태에서 시작) · 로컬 커밋만, 푸시 없음

## 이어받은 변경의 처리

시험하지 않은 미커밋 변경을 검토·실행했다. 새 시험 9개 중 4개가 오류였고, 코드에서 다음을 확인해 그대로 쓰지 않고 다시 구현했다. 원래 변경은 로컬 참조 `refs/wip/jobstate1-untested`에 보존했다.

- 화면이 `세부작업`·`표준서식_세부_전달`을 만들기 전에 옵션 지문에 사용해, 코드상 「실행」이 매번 오류가 나는 상태였다.
- 정상 저장 문서의 `item_done` 상태를 `converted`에서 `saved`로 바꿔 기존 소비자와 어긋났다.
- 실패 문서의 `continue`가 문서 사이 한/글 재시작 블록을 건너뛰었다.
- 저장 뒤 예외는 여전히 결과 경로 없이 기록됐고, 검수 중 취소는 검수 실패로 표시됐다.

## 수정

| 지적 | 수정 |
|---|---|
| F04 | 저장·빈 문서 검사 직후 기록을 만들고 `saved` 사건을 보낸다. 이후 검수 실패·중단·예외는 상태만 `inspection_failed`/`cancelled`로 바꾼다. 결과 파일 경로는 유지된다 |
| F05 | `integrity_failed` 상태를 새 사건 `document_state(원본, 상태, 안내)`로 전달한다. 작업 API는 `log` 사건에 `result_status`를 덧붙인다. 화면 완료 요약에 「무결성 확인 필요 N개」를 따로 표시한다. 기존 `success`, `saved` 4개 항목, `item_done.status=converted`는 그대로다 |
| PM 타입 | `DocumentCancelled`/`DocumentFailed`로 구분한다. 중단 요청이 없는 `False`는 실패이며 다음 문서를 계속 처리한다. 실패가 있으면 「모든 작업 완료」 대신 「작업 종료 — 처리하지 못한 문서 N개」 |
| PM 재시작 | 재시작 블록을 보호한다. 실패하면 남은 문서를 `unprocessed`로 보고하고 정상적으로 `finished`를 보낸다 |
| PM 실패 문서 | 재시작하지 않는 설정에서 다음 문서가 남아 있으면 `Clear(1)`(저장 안 함)로 닫는다. 닫지 못하면 남은 문서를 `unprocessed`로 두고 멈춘다 |
| F08 | 위치 계산을 없애고 결과 파일이 있는 문서의 기록을 키워드 전용 `완료_문서`로 넘긴다. 파일 키로 건너뛰며, 실행 인자·서식 프로필·장평 설정의 지문이 다르면 처음부터 다시 한다 |
| 추가 발견 | 실행 후 실패가 있는 작업이 먼저 끝나면 `_절약초` 속성 오류로 완료 처리가 중간에 끊겼다. 고쳤다 |

`작업_실행`의 기존 위치 매개변수는 바꾸지 않았다(`tests.test_run_signature` 수정 없음).

## 시험

- 신규 16개: `tests/test_job_state_save.py` 7, `test_job_state_batch.py` 6, `test_job_state_resume.py` 3. 실제 `문서_처리`·`작업_실행`·화면 메서드를 가짜 한/글로 실행하며 저장은 합성 HWPX다.
- 최종 시험 파일을 수정 전 코드(`25be963b`)에서 실행: 16개 중 14개 실패·오류(7/7, 4/6, 3/3). 통과한 2개는 정상 경로·취소 보호 확인이다.
- 수정 후 관련 53개 모듈: `Ran 421 tests` / `OK`. `test_v2_t04_t19`의 import 방식 때문에 `PYTHONPATH=tests`를 지정했다.
- 중간 커밋도 따로 확인: 1번 `Ran 11` OK, 2번 `Ran 17` OK.
- 기존 시험은 수정하지 않았다. 전체 시험은 PM 릴리스에서 한다.
- **실제 한/글 COM 시험은 실행하지 못했다**: `.com-test.lock`이 있었다. 사용자 문서는 사용하지 않았다.

커밋은 F04·F05, PM 실패 보호, F08의 3개와 이 기록이다. 1번 커밋에 `_절약초` 수정이 함께 있다.

## 남은 문제

- 실제 한/글에서 `Clear(1)` 정리, 재시작 실패, 저장 후 검수 중 중단은 확인하지 못했다.
- 저장 후 검수 결과 안의 개별 항목 `status: error`(재열기 실패 등)는 이전처럼 최종 검수 확인 사항으로만 남고 `inspection_failed`가 되지 않는다.
- 이어하기는 결과가 있으면 검수 실패·검수 중 중단 문서도 다시 처리하지 않는다. 중단 뒤 원본 내용이 바뀐 것은 감지하지 않는다.
- 이어하기는 이전처럼 「중단」 뒤에만 제안한다. 재시작 실패로 남은 미처리 문서에는 제안하지 않는다.
- 옵션 지문은 작업 스레드의 인자(`Thread._args`)를 읽는다. 준말 등록 등 인자 밖 설정의 변경은 지문에 반영되지 않는다.
- Flutter 화면의 대기 목록은 바꾸지 않았다. 상태는 완료 요약과 작업 API `log` 사건으로 전달한다. 실제 화면 확인은 하지 않았다.
- 서식 예시 만들기는 이제 검수에 실패해도 저장된 결과를 예시로 가져갈 수 있다(코드상 판단, 시험 없음).

## JOBVERIFY1 — 실제 한/글 확인과 검수 `error` 상태

작성: 2026-11-26 · 브랜치: `feature/JOBVERIFY1` · 로컬 커밋만, 푸시 없음

### 수정: 검수 항목 `error` → 검수 실패

저장 후 검수 항목 중 하나라도 `status: error`(재열기 실패, 검사 예외)면 기록을 `inspection_failed`·`success: False`로 두고 `document_state`를 보낸다. 항목별 결과(`rule_checks`), 무결성 대조, 결과 파일 경로는 남긴다. 무결성도 실패면 상태는 `inspection_failed`이고 오류·안내 문구에 「무결성 확인 필요」를 함께 적는다. `passed`·`failed`·`incomplete`·`not_applicable`은 이전과 같다.

동작 변화: 이런 문서는 이전에는 성공으로 셌지만 이제 실패 수에 들어가고 `document_error`도 나간다(다른 검수 실패와 같은 처리).

### 시험

- 신규 4개(`tests/test_job_state_save.py`). 수정 전 코드: `Ran 11` / `FAILED (failures=3)`. 통과한 신규 1개는 `error` 아닌 상태가 유지되는지 보는 확인이다.
- 수정 후 JOBSTATE1 3개 모듈: `Ran 20 tests` / `OK`.
- 수정 후 관련 55개 모듈(`PYTHONPATH=tests`): `Ran 603 tests` / `OK (skipped=11)`. 전체 시험은 실행하지 않았다.

### 실제 한/글에서 실행한 것

`scripts/verify_jobstate_com.py`(`.com-test.lock` 배타 생성, DispatchEx, 합성 HWPX 3개, 임시 `APPDATA`). 실제 `작업_실행`을 서식 적용 모드·세부 작업 끔으로 실행했다((c)·(d)는 `page_group` 검수만 켬). 실패·중단은 주입했다. 네 경우 모두 대화상자 감지 0건, 원본 해시 불변, 남은 한/글 프로세스 0개.

| 경우 | 주입 | 결과 |
|---|---|---|
| (a) 실패 문서 닫기, 재시작 끔 | 첫 문서를 고친 뒤(`IsModified` 참) 단계가 `False` 반환 | 저장하지 않고 닫힘. 다음 문서 시작 때 열린 문서 1개, 주입한 글 없음. b·c 저장, `finished` 성공 2·실패 1, a 결과 파일 없음 |
| (b) 재시작 실패 | 두 번째 인스턴스 생성에서 예외 | a 저장, b·c `unprocessed`, `finished` 성공 1·실패 2 |
| (c) 검수 중 중단 | 저장 결과를 다시 연 직후 중단 요청 | `saved` 뒤 `cancelled`, 결과 파일 있음, 기록의 출력 경로 유지, `stopped`. b·c는 시작하지 않음 |
| (d) 재열기 실패 | 검수의 문서 열기가 `False` 반환 | 3개 모두 저장, `inspection_failed`, `finished` 성공 0·실패 3 |

### 실행하지 못했거나 확인하지 않은 것

- 화면(Tk·Flutter)의 결과 목록 표시는 실제 한/글과 연결해 보지 않았다. (c)는 엔진의 사건과 기록까지 확인했다.
- 실패·재시작 실패·재열기 실패는 주입한 것이다. 한/글이 스스로 멈추거나 죽는 경우는 아니다.
- 대화상자 감지는 창 클래스(`#32770`, `dialog` 포함)와 시간 제한에 의존한다.
- 보안 모듈 설치·등록 단계는 레지스트리를 쓰지 않으려고 건너뛰고 이미 등록된 값을 썼다.
- 자동 닫기 끔·비교 보기 창 구성, `.hwp` 원본, 서식 단계를 켠 문서는 확인하지 않았다.

### 남은 문제

- 저장은 됐지만 검수 실패한 문서도 상태줄이 「작업 종료 — 처리하지 못한 문서 N개」로 표시한다((d)에서 확인). 문구가 사실과 다르게 읽힐 수 있다.
- 위 '남은 문제' 중 실제 한/글 확인(첫 항목)과 검수 `error`(둘째 항목)는 이 절의 범위에서 해결했다. 나머지는 그대로다.
