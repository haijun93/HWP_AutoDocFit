# PDFUI2 조사 격차 — 2026-11-18

## 조사 결과

| 영역 | 현재 상태 | 격차 및 적용 |
|---|---|---|
| `pdf_edit_core` (Rust) | `lopdf`로 PDF 열기와 쪽 수 조회, 삭제·재정렬·회전·분할 수행. | 쪽 크기와 회전 정보를 반환하는 읽기 API가 없어 `page_info`와 CLI `info`를 추가한다. 원본은 읽기만 한다. |
| `docfit_app/pdf_edit_service.py` | 편집 명령은 Rust CLI에 위임하며 `pypdf`로 암호화·손상 파일을 사전 분류한다. | 정보 및 썸네일 명령이 없다. 기존 분류를 통과한 PDF에 한해 정보/썸네일 응답을 추가한다. |
| Flutter PDF 편집 | `pdf_edit_workspace.dart`가 고정 12개 번호 카드를 표시한다. | 실제 페이지 수 조회가 없고 카드 이미지는 없다. API 결과를 표시하고 로딩/오류 시 번호 카드를 유지한다. |
| 앱의 PDF 렌더 수단 | `docfit_core/timemachine/thumbs.py`는 `pypdfium2`, PDFium 잠금, JPEG 축소·캐시를 제공한다. PDFium은 타임머신 추출 및 `table_units_service.py`에서도 사용된다. | 공용 타임머신 렌더는 첫 쪽만 대상으로 한다. PDFUI 전용 API에서 선택 쪽을 렌더하고 같은 캐시·잠금 기반시설을 재사용한다. 렌더링 결과는 160px JPEG로 제한한다. |
| 타임머신/기타 탐색 | `kagent/src/thumb.rs`는 PDF 렌더 API로 쓰이는 경로가 아니며, `timemachine_service.py`에는 별도 시간 제한 렌더 프로세스가 있다. | 기존 앱에 PDFium이 존재하므로 새 렌더 의존성은 불필요하다. PDFium 점유 또는 렌더 실패 시 UI는 번호 카드로 대체한다. |

## 제한

- PDF 편집 코어 기존 입력 제한(1..3000쪽, 1GiB)과 암호화 파일 거부를 유지한다.
- PNG 대신 JPEG를 사용해 타임머신의 작은 썸네일 규격과 캐시를 공유한다.
- 현재 Flutter API는 썸네일을 쪽별로 요청한다. 3000쪽 PDF에서 다량 요청 비용을 줄이는 일괄/지연 로딩은 후속 격차다.
