# ROLLBACK3 — 맞춤 실패 때 원래 쪽 나눔 되살리기

작성: 2026-11-27 · 브랜치: `feature/ROLLBACK3` · 로컬 커밋만, 푸시 없음. 사용자 승인 작업.

## 해당 경로

| 경로 | 수정 전 | 수정 후 |
|---|---|---|
| `_문서유형별_쪽맞춤_본체`: 보고서 안 쪽 나눔 해제 → `보고서_1쪽_맞춤` 실패 | 해제된 채 남음 | 되살리고 다시 읽어 확인 |
| 같은 곳: 해제 → 붙임 때문에 담기 불가능해 건너뜀 | 해제된 채 남음 | 되살리고 다시 읽어 확인 |
| `중제목_외톨이_정리`: 뒤 □의 쪽 나눔 해제 → 정상 실패 | 다시 켰으나 확인 없음 | `_쪽나눔_원복`으로 다시 켜고 확인 |

- 예외·중단 경로는 ROLLBACK2 그대로다.
- 확인하지 못하면 `fail_required_edit`(필수 수정 실패)로 올려 결과 저장을 막는다. 한 곳이 실패해도 나머지는 모두 시도한다.
- 성공(맞춤 성공, 또는 해제만으로 목표 쪽 안에 들어감)은 해제한 상태를 유지한다.
- `_묶음_쪽나눔_이동`은 이미 실패 때 원래 값으로 돌리고 확인한다(ROLLBACK2). `_묶음_같은쪽_이동`, 선형·고속 쪽 수 맞춤은 쪽 나눔을 해제하지 않는다.
- 대상은 '문단 앞에서 쪽 나눔'(문단 모양)이다. Ctrl+Enter 쪽 나눔은 해제 대상이 아니며, 실제 한/글에서도 전후 모두 그대로였다.
- "원래"는 이번 맞춤 시도 직전 상태다. 앞 단계의 쪽 배치가 넣은 쪽 나눔도 시도가 실패하면 그대로 되살아난다.
- `쪽맞춤_보고서조정됨`은 되살려도 켜진 채 둔다. 저장 단계의 보존 판단과 쪽 수 재확인 조건을 바꾸지 않기 위해서다.

## 그대로 둔 것(실패와 무관한 의도적 동작)

- `문서_쪽나누기_전체해제`(저장 직전 일괄 해제): `쪽나누기_사용`이 False일 때만 돈다. 현재 코드의 기본값은 True이고 저장소에서 이를 바꾸는 설정은 찾지 못했다. 따라서 되살린 쪽 나눔은 결과 파일에 남는다.
- 원본에서 새 쪽에 시작한 보고서 첫 문단에 쪽 나눔을 **넣는** 동작: 해제가 아니며 맞춤이 실패해도 유지한다.
- 변경 코드는 `docfit_engine/page_fit.py`뿐이다. 본체 `hwp-auto-docfit.py`는 바꾸지 않았다(CRLF 유지).

## 시험

- 신규 `tests/test_rollback_page_break.py` 10개(상태형 가짜 hwp).
  - 수정 전 코드: `Ran 10 tests` / `FAILED (failures=7)`.
  - 수정 후: `Ran 10 tests` / `OK`.
- 기존 시험 파일 1개를 고쳤다: `tests/test_page_group_table.py`의 가짜 hwp가 마지막으로 쓴 쪽 나눔 값을 돌려주게 했다(원복 확인이 다시 읽기 때문). 단언은 바꾸지 않았다.
- 관련 시험(`hwp-auto-docfit`·`page_fit`·`docfit_engine`·`pipeline`을 참조하는 모듈, `PYTHONPATH=tests`): `Ran 1347 tests in 200.878s` / `OK (skipped=7)`.
- `test_final_review_guards` 별도 실행: `Ran 13 tests in 9.903s` / `OK`.
- 처음에 `PYTHONPATH` 없이 돌렸을 때는 오류 3건이었다: 가져오기 경로 2건과 위 가짜 hwp 1건. 마지막 실행에서는 모두 통과했다.
- 이 시험들은 COM을 쓰지 않으며, 일부 실행은 다른 작업의 `.full-test.lock`이 있는 동안 했다.
- 전체 Python 시험은 실행하지 않았다.

## 실제 한/글 전후 비교(합성 문서)

`.full-test.lock`이 풀린 뒤 COM 잠금을 배타 생성하고, DispatchEx 새 인스턴스(창 숨김)만 사용했으며 끝나면 종료했다. 수정 전은 HEAD 사본, 수정 후는 작업 폴더다. 엔진 함수를 파이프라인의 세로 배치 순서(쪽 수 맞춤 → 문단 페이지 배치 → 재확인 → 최종 확인 → 줄간격 통일)로 불렀고, 원본 쪽 수 1을 지정해 맞춤이 돌게 했다. 파이프라인 전체나 EXE를 실행한 것은 아니다.

### 맞춤이 실패하는 문서

'바뀐 문단'은 처음 문서와 줄간격·문단 간격이 다른 문단 수다. '미해결'은 문단 페이지 배치 한 회에서 배치하지 못한 묶음 수다.

| 문서(문단 수, 처음 쪽 수, 쪽 나눔 문단) | 최종 쪽 수 전 → 후 | 저장본 문단 앞 쪽 나눔 전 → 후 | 바뀐 문단 전 → 후 | 미해결 전 → 후 | 쪽 번호가 전후 다른 문단 |
|---|---|---|---|---|---|
| 경계에 1곳(103, 4쪽, 19) | 4 → 4 | 없음 → 19 | 64 → 0 | 0 → 0 | 36 |
| 묶음 중간 2곳(109, 5쪽, 14·62) | 4 → 5 | 없음 → 14·62 | 30 → 58 | 0 → **4** | 81 |
| 뒤쪽 1곳(91, 3쪽, 70) | 3 → **4** | 없음 → 70 | 67 → 67 | 0 → 0 | 21 |
| 묶음 중간 1곳(103, 4쪽, 33) | 4 → 4 | 없음 → 33 | 64 → 61 | 0 → **2** | 6 |
| Ctrl+Enter 19 + 문단 앞 40(103, 4쪽) | 4 → 4 | 없음 → 40 | 0 → 33 | 0 → 0 | 24 |
| 5줄 넘침(46, 2쪽, 22) | 2 → 2 | 없음 → 22 | 40 → 0 | 0 → 0 | 17 |

- 맞춤 직후 단계에서는 여섯 문서 모두 쪽 나눔과 쪽 구성이 처음과 같았다.
- Ctrl+Enter(19)는 전후 모두 저장본에 남았다.

### 이후 단계가 다르게 동작한 경우

- **뒤쪽 1곳**: 문단 페이지 배치가 1·2쪽 줄간격을 170%로 넓혀 뒤로 밀자, 되살린 쪽 나눔(문단 70) 앞에 4문단(66~69)만 있는 쪽이 생겼다. 쪽별 문단 수가 33·33·25(전) → 33·33·4·21(후)이고, 처음 문서 3쪽보다 1쪽 늘었다. 문단 페이지 배치는 이 상태를 미해결로 기록하지 않았다.
- **묶음 중간 2곳·1곳**: 원본 쪽 나눔이 □ 묶음 가운데에 있어 문단 페이지 배치가 줄간격으로 모으지 못했다. 미해결과 검수 기록이 늘고, 1곳 문서는 30문단이 180%가 되었다(전 0문단).
- **Ctrl+Enter 문서**: 전에는 문단 페이지 배치가 바꾼 것이 없었고, 후에는 33문단을 170%로 넓혔으며 쪽 수 재확인·최종 확인까지 다시 돌았다.
- **경계에 1곳·5줄 넘침**: 후에는 줄간격 변경과 재확인이 없어 처음 문서 그대로 남았다.

### 맞춤이 성공하는 문서

| 문서(문단 수, 쪽 나눔 문단) | 성공 방식 | 쪽 수(처음 → 최종) | 전후 결과 |
|---|---|---|---|
| 28문단, 13 | 해제만으로 1쪽 | 2 → 1 | 단계별 상태 같음, `section0.xml`·`header.xml` 바이트 동일 |
| 37·40문단, 22 | 해제만으로 1쪽 | 2 → 1 | 위와 같음(2건) |
| 34문단+아래 간격 5pt, 22 | 해제 + 간격 축소 레벨 2 | 2 → 1 | 위와 같음, 간격이 바뀐 문단 33 |
| 37문단+아래 간격 5pt, 22 | 해제 + 간격 축소 레벨 4 | 2 → 1 | 위와 같음, 간격이 바뀐 문단 36 |

성공한 다섯 문서는 전후 모두 쪽 나눔이 해제된 채 저장되었고 검수 기록이 없었다. 43문단(간격 0, 22) 문서는 전후 모두 맞춤 실패(넘친 줄 2)여서 성공 비교에서 뺐다. 수정 후에는 이 문서도 처음 상태(22·21문단 2쪽)로 남았다.

실행 중 한 번은 실험 스크립트가 통계 값을 잘못 초기화해 수정 후 실행이 중간에 멈췄다(제품 코드 문제 아님). 고친 뒤 전후를 처음부터 다시 실행했고 위 수치는 그 결과다. 각 실행은 하네스의 백그라운드 실행(상한 2시간)으로 돌렸고 상한에 걸린 실행은 없다.

### 확인하지 않은 것

- 원복 실패는 실제 한/글에서 만들지 않았고 가짜 hwp 시험으로만 확인했다.
- `중제목_외톨이_정리` 경로, 붙임 때문에 건너뛰는 경로, 보고서 여러 개인 문서는 실제 한/글에서 만들지 않았다(앞 둘과 보고서 2개는 가짜 hwp 시험).
- 실제 문서, 표가 있는 문서, 다른 한/글 판, 설치본·EXE.

## 남은 문제

- [판단 필요] 쪽 나눔을 되살리면 문단 페이지 배치가 쪽 나눔을 고려하지 않고 앞 줄간격을 넓혀 **짧은 쪽이 하나 더 생길 수 있다**(위 '뒤쪽 1곳'). 이번 범위에서는 문단 페이지 배치를 바꾸지 않았다.
- 원본 쪽 나눔이 묶음 가운데에 있으면 미해결 검수 항목이 늘 수 있다.
- 실패가 재확인에서 반복되면 `[보고서 쪽 수 초과]` 검수 기록이 여러 번 남는다(수정 전에도 같음).
- `_묶음_쪽나눔_이동`에서 바꾸기 전 값을 읽지 못하면 설정 명령의 성패만 본다(ROLLBACK2에서 남긴 것).
- 1쪽 맞춤이 실패해도 `문단_줄수_원본맞춤`이 바꾼 자간은 남는다(ROLLBACK2에서 남긴 것).
