## 2. kordoc 의존 줄이기 (docs/KORDOC2D_DESIGN_2026-11-23.md)
- 진행 순서는 설계의 권고(A 기준선 → B 품질 비교 harness → C Markdown→HWPX 생성기 → D 입력 어댑터 → E 라우팅·MCP → F 런타임 분할 → G 준비 상태 UI → H 실문서 회귀)를 따른다.
- 합격선은 설계의 잠정안(구조 100%, 텍스트 재현율 99.5%·정밀도 99%)을 채택한다. 형식별 예외는 harness 결과를 보고 근거와 함께 문서로 기록한 뒤에만 허용한다.
- Pandoc GPL 표기는 라이선스 검토 전까지 **기본 번들에서 새로 늘리지 않는다**(현 상태 유지). 라이선스 검토가 끝나지 않은 의존은 추가하지 않는다.
- PDF 고급 변환·글자 인식은 kordoc 에 남기고 '고급 변환 엔진' 추가 꾸러미로 분리(F 단계). 기본 설치에 포함 여부는 F 단계에서 설치 크기 실측으로 결정한다.
- 앱에 연결되지 않은 kordoc 고급 기능(표 분석·폼·patch/lint/IR/RAG)은 **공개 목록에서 제외된 상태를 유지**하고 삭제는 하지 않는다(제품 사용 여부 미확인).

## 3. 독 13번 아이콘
- 독 13번의 라벨은 '업무자료함/노트북'이고 아이콘도 업무자료함(menu_book)인데 `dock::route()` 는 클립보드(kagent)를 실행한다. 독 메뉴에 클립보드 항목은 없고 클립보드는 별도 단축키(Ctrl+Shift+V)가 있으므로, **13번은 업무자료함 화면을 열도록 수정**한다(DOCKFIX1).
