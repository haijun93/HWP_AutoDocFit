## 설계·검증 메모

- 기본 범위 계산은 드라이브·프로필·OneDrive 경로를 주입받는 순수 함수로 분리한다. Windows 고정 드라이브만 자동 열거하고 이동식·네트워크는 제외한다.
- 제외 규칙은 Windows/Program Files/ProgramData/Recycle Bin/System Volume Information/AppData와 개발 폴더명, 사용자 제외 폴더, 클라우드 오프라인 속성을 포함한다. 클라우드 파일은 항목을 보일 수 있지만 내용을 열지 않는다.
- kfind `DocMeta`는 검색에 필요한 파일의 메타데이터를 담지만 폴더를 인덱싱하는 API인지 현재 코드 조사만으로 보장할 수 없다. 색인 외 확장자·폴더 보충도 필요하므로 파일 목록 재사용은 서비스 인터페이스와 신선도 규칙 확인 전에는 안전하다고 볼 수 없다.
- 기존 사진 `registered_folders`·사진 레코드·태그는 보존한다. 새 기본 범위가 기본 동작이며 기존 등록 폴더는 추가 범위로 중복 처리하지 않고 무시하는 전환이 적합하다.
- 전체 드라이브 순회는 대량 I/O와 지연이 예상된다. 현재 서비스 명령은 동기 호출이며 진행률/취소 상태가 없다. 첫 실행에서 UI 응답성과 취소 가능성은 구현·시험에서 별도 확인이 필요하다.

## 현 단계 미확인

- 설정 화면에서 제외 경로를 추가·삭제하는 기존 API/저장 구조의 정확한 연결 지점.
- Windows 고정 드라이브 열거와 OneDrive Desktop 변형 경로의 실제 PC 값. 사용자 PC 경로를 시험에 고정하지 않는다.
- kfind 검색 결과 목록을 전체 문서/사진 파일의 권위 있는 디렉터리 인덱스로 재사용할 수 있는지. `DocMeta` 정의만으로는 판정할 수 없다.
