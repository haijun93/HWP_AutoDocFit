# OUTKEYS2 결과 — 처리 중에 친 글자·Enter 보존 (앱 안 아웃라이너)

대상: `flutter_ui/lib/features/outliner/`. `outliner_core` 의 키 규칙, 네이티브 창(`outliner_win`)은 바꾸지 않았다.

## 원인

- 명령 처리 중에는 Tab 외의 모든 키를 "처리함"으로 돌려줘 Enter 가 버려졌다. 실제 키보드의 글자도 입력 칸에 전달되지 않을 수 있었다.
- 처리 중에 입력 칸에 들어온 글(한글 조합 등)은 결과를 반영하면서 덮였다.

## 고친 동작

블록 편집 명령(키 명령, 다른 칸 저장, 실행 취소·다시 실행, 새 블록, 완료 표시)을 처리하는 동안:

- 글자는 입력 칸이 그대로 받는다. 결과가 오면 새로 친 글만 떼어 **커서가 옮겨 간 블록의 커서 자리**에 넣는다.
- Enter·Shift+Enter·Ctrl+Enter·Tab·Shift+Tab 은 누른 순서대로 예약한다(최대 64개). 각 키 앞에 친 글은 그 키보다 먼저 반영한다.
- 친 글 안에서의 Backspace·Delete 는 동작한다.
- `[[` 후보가 열려 있으면 Enter·Tab·↑↓·Esc 는 평소처럼 후보에 쓴다.
- 블록 입력 칸의 클릭은 무시한다(포커스도 풀리지 않는다). 처리가 끝나면 누를 수 있다.
- 검색 칸 등으로 포커스를 옮겨도 이미 친 글은 지우지 않는다. 처리가 끝나면 이전처럼 커서 블록으로 돌아온다.
- 명령 결과가 블록 선택이어도 그 사이에 친 글이 있으면 선택하지 않고 커서를 둔다.
- 명령이 실패하면 예약한 키는 보내지 않는다. 친 글은 칸에 남기고, 적용하지 않은 키 수를 알린다.
- 처리 중 블록 검색 제출은 무시한다(명령이 겹치지 않게).

## 보장하지 못하는 경우와 처리 방안

| 경우 | 지금 동작 | 제안 |
|---|---|---|
| 실제 Windows 한글 IME 조합 중에 커서가 새 블록으로 옮겨 감 | 위젯 시험의 조합 값은 한 번만 들어간다. 실제 IME 는 음절 중복·분리 가능성을 확인하지 못했다 | 실기 확인. 문제가 있으면 조합이 끝날 때까지 이동을 미루는 방식 검토 |
| 실제 키보드의 글자가 처리 중에 입력 칸에 도달하는지 | 키를 넘기는 것까지만 시험했다 | 실기 확인(영문·한글) |
| 친 글이 없을 때의 Backspace·Delete(예: Enter 직후 Backspace 로 다시 합치기) | 이전처럼 받지 않는다 | 키 예약에 포함할지 결정 |
| ↑↓←→·Home·End·PageUp/Down·Esc, Ctrl·Alt 단축키(붙여넣기·실행 취소 포함) | 이전처럼 받지 않는다. 커서를 옮기면 친 글의 자리를 알 수 없다 | 필요한 키부터 순서 예약에 추가 |
| 페이지 열기·이름 바꾸기·삭제·복원 처리 중 입력 | 이전처럼 받지 않는다. 다른 페이지에 글이 들어가면 안 된다 | 처리 중 표시 추가 |
| Enter·Tab 을 누른 채 반복 | 처음 누름만 예약한다 | 필요 시 반복도 예약 |
| 명령 실패 | 예약한 Enter 의 줄 나눔은 적용되지 않고 글이 한 블록에 이어진다(미저장) | 확인 후 Enter 를 다시 누른다 |
| 처리 중 아웃라이너 화면 자체가 닫힘 | 예약한 키와 미저장 글은 남지 않는다 | 화면 종료 전 저장은 별도 과제 |

참고:

- 예약이 남아 있는 동안에는 아직 보내지 않은 글이 현재 커서 블록에 잠시 이어 보이고, 명령이 차례로 끝나면 제 블록으로 간다.
- 확정하지 않은 글이 있는 채 페이지를 바꿀 때의 동작은 이번에 바꾸지 않았다.
