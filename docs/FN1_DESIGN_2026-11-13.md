## 1. 조사

### 1-1. Everything이 빠른 이유(공개 자료, 폐쇄 소스)
| 기법 | 내용 | 근거 |
|---|---|---|
| MFT 직접 열거 | 볼륨 핸들로 `FSCTL_ENUM_USN_DATA`(또는 `$MFT` 직접 읽기)로 이름·부모·속성을 한 번에 | voidtools FAQ·포럼(IS-BENCH 요약) — 확인(문서), 내부 방식 미확인 |
| USN 저널 | 변경분만 반영, 꺼져 있던 동안의 변경도 따라잡음, 저널이 덮어쓰이면 재색인 | 같음 |
| 메모리 상주 | 이름만 메모리, 100만 항목 약 100MB(IS1 조사 인용) | 공개 수치, 이 PC 미확인 → §4에서 실측 |
| 정렬 미리 계산("fast sort") | 이름·경로·크기·날짜 정렬 순서를 색인에 미리 둠 | Everything 옵션 이름 — 확인(설정), 구조 미확인 |
| 서비스 분리 | `Everything.exe -svc`(LocalSystem)가 볼륨을 열고 클라이언트는 사용자 권한 | 이 PC `sc qc Everything` 확인 |
| 질의 | 한 덩어리 이름 버퍼 순차 비교(추정), 1.4판 검색 스레드 수 미확인 | 미확인 |

### 1-2. 다른 사례
- **UFFS**(Rust, Everything 대비 12/12 승): 카드 인용. 저장소·수치는 **미확인**(이번에 웹을 보지 않음). 이름으로 보아 MFT 직접 읽기 + 병렬 검색으로 추정.
- **plocate**: trigram 역색인으로 후보를 줄이고 원문 확인(IS-BENCH 확인). 디스크 상주 DB가 전제라 우리처럼 메모리 상주·수 MB/s 이상 SIMD 훑기가 되는 경우엔 짧은 질의에서 이득이 작다(아래 1-3).
- **ntfs-reader 0.4.5**, **usn-journal-rs 0.4.0**: Rust MFT·USN 열거(IS-BENCH). 의존성을 늘리지 않으려고 `FSCTL_ENUM_USN_DATA`·`FSCTL_READ_USN_JOURNAL`을 `windows-sys`로 직접 불렀다(약 200줄, `kfind/names/src/ntfs.rs`). `$MFT` 원시 해석(크기·날짜까지)은 2차(Q-F2).

### 1-3. 후보 기법과 채택 여부
| 후보 | 채택 | 이유 |
|---|---|---|
| `FSCTL_ENUM_USN_DATA` 열거 | **채택** | 관리자면 가장 빠른 공개 API. 레코드 번호 = 파일 참조 번호 아래 48비트 |
| `$MFT` 직접 병렬 파싱 | 보류(Q-F2) | 크기·날짜가 필요할 때. 열거보다 빠르다는 공개 수치 있음(미확인) |
| 이름 비교형(NFC·casefold·글자/숫자만)을 0으로 구분한 **한 덩어리 버퍼**, u32 오프셋 | **채택** | `memmem` 한 번으로 버퍼 전체를 SIMD로 훑음. 항목마다 따로 부르는 것보다 호출 비용 없음 |
| SIMD 부분 문자열(`memchr::memmem`, AVX2) + rayon 분할 | **채택** | 버퍼를 항목 경계에서 스레드×4 조각으로 |
| 찾은 바이트 위치 → 항목 번호 | **질주 탐색**(galloping)으로 위치 배열 위 이동 | 일치가 촘촘하면 거의 선형, 드물면 로그 |
| trigram/bigram 비트맵 | **불채택(측정 근거)** | §4 표: 1~3글자 질의가 이미 수 ms. 비트맵은 항목당 메모리(+수십 B)와 USN 갱신 비용을 늘리는데, 병목은 "찾기"보다 "일치 개수 세기"(1글자 질의는 항목의 절반 이상이 일치) → 비트맵으로 줄지 않음 |
| 입력 연장 시 앞 결과 안에서만 거르기 | **채택** (`Searcher`) | "보"→"보고"→"보고서": 앞 일치 번호 목록만 확인 |
| 상위 N 먼저 + 정렬 키 미리 계산 | **채택** | 항목마다 u64 키 = 깊이(6비트)·비교형 앞 7바이트. 질의는 등급 2비트만 얹음. 같은 키일 때만 전체 비교 |
| 부모 번호 트리로 경로 지연 조립 | **채택** | 결과 N개만 부모 사슬로 |
| **DFS(전위) 순서 저장** | **채택(새 기법)** | 형제를 이름순으로 두고 트리 전위 순서로 번호를 매기면 한 폴더의 하위가 연속 구간 `[id, end[id])` → `path:`·제외 폴더가 **구간 계산**으로 끝나고 훑을 버퍼 자체가 줄어든다. 번호 순서 = 경로 정렬 순서(미리 계산된 경로 정렬) |
| mmap 공유(`names.seg`) | **채택** | 질의 코드는 빌린 보기(`View`)만 읽어 소유판·매핑판이 같은 코드. 매핑 열기 때 전체 구조 검사 |
| USN 실시간 반영 | **채택** | 지운 표지 + 뒤에 덧붙이기, 옮긴 폴더는 옛 번호 → 새 번호 넘김표. 덧붙임이 5%·6만을 넘으면 기본판 다시 만들기 |

## 3. 설계

### 3-1. 저장 구조(항목당 바이트)
| 열 | 바이트 | 내용 |
|---|---|---|
| `parent` | 4 | 부모 번호(DFS 번호) |
| `fold_off` | 4 | 비교형 버퍼 위치(n+1개) |
| `name_off` | 4 | 원래 이름 버퍼 위치(n+1개) |
| `key` | 8 | 정렬 키(깊이·비교형 앞 7바이트) |
| `ext` | 2 | 확장자 번호(표는 따로, 6.5만 종 넘으면 이름에서 다시 계산) |
| `flags` | 1 | 폴더·숨김·시스템·지움·덧붙임·재분석 |
| `end` | 4 | 하위 트리 끝 번호 |
| 비교형 | 평균 길이+1 | `0, f0, 0, f1, …` |
| 원래 이름 | 평균 길이 | UTF-8 |
| 레코드 표 | 약 4×(레코드 수/항목 수) | MFT 레코드 번호 → 항목 번호(USN 반영용, 서비스만) |

고정 27B + 이름 두 벌. 실측 항목당 바이트는 §4.

### 3-2. 질의 실행
1. 해석: 낱말 비교형, 다른 낱말에 들어 있는 낱말은 뺌("보고 보고서" → "보고서").
2. 구간: `path:` 낱말마다 그 낱말을 품은 폴더들의 하위 구간 합집합 → 낱말끼리 교집합, 제외 폴더 구간을 뺌. 기본판 밖(덧붙인 항목)과 옮긴 폴더 아래는 부모 사슬로 확인.
3. 1차 낱말(가장 긴 것)로 구간들의 비교형 버퍼를 rayon 조각마다 `memmem` → 항목 번호 → 나머지 조건(표지·종류·확장자 표·다른 낱말·제외 낱말) → 개수 + 조각별 상위 N(정렬된 작은 배열, 꽉 차면 마지막보다 작은 것만 넣음) → 합치기.
4. 버퍼가 256KB 이하면 스레드를 쓰지 않음(작은 색인에서 스레드 비용 회피).
5. `Searcher`: 새 질의가 앞 질의의 연장(범위 조건 같고, 앞 낱말이 모두 새 낱말 중 하나에 들어 있고, 제외 낱말이 늘기만)이면 앞 일치 번호 목록만 확인. 세대(USN 반영)가 바뀌면 버림. 결과는 처음부터 찾은 것과 **같음**(시험).
6. 취소: 조각마다·1.6만 일치마다 취소 표지 확인(파이프 `cancel{id}`).

### 3-3. 상태 기계(서비스, `names_status.state`)
| 상태 | 들어오는 길 | 나가는 길 | 질의 |
|---|---|---|---|
| `empty` | 시작 | `names_build`·서비스 시작 → `building` | 오류 `names index unavailable (empty)` |
| `building` | `names_build` | 성공 → `ready`, 실패 → 옛 색인 있으면 `ready`(+`last_error`), 없으면 `failed` | 옛 색인이 있으면 그것으로 |
| `ready` | 만들기 성공 | `names_build` → `building` | 정상. USN 반영은 상태를 바꾸지 않고 `generation`만 올림 |
| `failed` | 첫 만들기 실패 | `names_build` → `building` | 오류 |
불가능한 전이: `building` 중 `names_build`(거절 "already running"). USN 저널 잘림·저널 없음은 `last_error`에 적고 그 볼륨 따라가기만 멈춤(다음 `names_build`에서 다시 열거).
잠금 순서: 색인(RwLock)과 상태(Mutex)를 동시에 쥐지 않는다. USN 반영·다시 만들기는 쓰기 Mutex 하나로 한 번에 하나.

### 3-4. 파이프 명령(길이 접두 JSON, 기존 kfind 파이프)
- `names_query{id,text,limit=100(≤1000),sort=relevance|name|path,hidden=true}` → `{id,generation,total,items:[{name,dir,is_dir}],narrowed,search_ms,ms}`
- `names_build{roots?}`(서비스: 없이, 사용자 모드: 절대 경로 ≤64개) → `{state:"building"}`
- `names_status{}` → `{state,mode,entries,generation,heap_bytes,delta,build_ms,volumes:[{name,source:mft|walk,entries,ms,note}],usn_followers,last_error,failed}`
- 서비스 모드는 시작하자마자 `names_build`, 멈출 때 USN 막힘 읽기를 `CancelSynchronousIo`로 깨워 정리.

### 3-5. 알려진 대가
- 옮긴 폴더 아래 항목의 관련도 순 "깊이"는 기본판을 다시 만들 때까지 옛 값(이름·경로 순과 일치 집합은 정확 — 시험).
- 하드 링크는 열거가 주는 이름 하나만.
- 크기·날짜 정렬 없음(Q-F2).
