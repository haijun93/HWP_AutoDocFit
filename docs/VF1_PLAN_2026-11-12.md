# VF1 계획: 가상 폴더를 단축키로 부르는 경량 창 (2026-11-12)

조사는 `docs/VF1_RESEARCH_2026-11-12.md`. 기준 커밋 `d3173daa`, 브랜치 `feature/vfolder-popup`. 이 문서는 설계만 담는다(코드 변경 없음).

## 0. 범위와 제약

### 넣는 것 (이번 범위, 단계 V1~V7)
- 단축키·트레이 메뉴·`kagent.exe --vfolder`로 부르는 가상 폴더 창. 앱 본체가 꺼져 있어도 동작.
- 상자(가상 폴더) 고르기, 영역 칸(전체·핵심자료·기초자료·참고자료·임시저장소), 항목 목록.
- 찾기: 고른 상자 안에서 이름·경로로(글자를 치면 바로, 한글 조합 중 글자 포함).
- 열기(Enter·두 번 클릭), 탐색기에서 위치 열기, 원본 위치 열기(`origin_path`가 있을 때).
- 창 틀·크기 조절·최소화·최대화·항상 위·위치 기억은 몽땅클립보드와 같게.
- 명시적 상태 기계와 `status.json`의 가상 폴더 상태.

### 빼는 것 (다음 범위, 단계 V8~V9는 설계만)
- 파일 끌어 넣기로 추가, 영역 이동, 삭제, 이름 바꾸기, 새 상자 만들기 — 모두 쓰기라 klib.exe가 필요하다.
- 본문 찾기(tantivy), 모든 상자에서 찾기.
- 관계선, 캔버스, 메모 편집, 업무자료함 연결, 내보내기 — 앱 화면에 남긴다.
- 창에서 끌어 내기(다른 프로그램에 파일 놓기), 클립보드로 파일 복사.
- 앱 설정 화면에서 가상 폴더 단축키 바꾸기(이번에는 kagent 설정 파일·파이프 `settings_set`으로만).

### 제약
| 제약 | 기준 |
|---|---|
| 유휴 CPU | 0. 타이머·폴링·파일 감시를 새로 만들지 않는다. 창은 단축키·트레이·명령줄·키·마우스 메시지로만 깨어난다 |
| 개인 메모리 | 기준선은 몽땅클립보드 실측 1.8~1.95MB(`docs/KAGENT_DESIGN.md:30`, `39`). 창을 숨긴 상태에서 기준선 대비 증가 0.2MB 이하. 항목 1,000개를 보이는 동안 증가 1.0MB 이하 |
| 실행 파일 | kagent.exe 증가 100KB 이하. 새 의존성 크레이트 0개 |
| 단독 실행 | 앱 본체·Python·klib.exe 없이 읽기·열기가 된다 |
| DB 동시 접근 | 창은 `library.db`에 **쓰지 않는다**. 스키마 만들기·`PRAGMA journal_mode`·색인 폴더 접근 없음. 읽을 때만 연결을 열고 다 읽으면 닫는다(읽기 트랜잭션을 붙잡지 않아 klib의 WAL 정리를 막지 않는다). 잠겨 있으면 200ms까지만 기다리고 오류 상태로 간다 |
| 원본 보호 | 창은 어떤 파일도 만들거나 고치거나 지우거나 옮기지 않는다. 여는 대상은 `자료 폴더\<box_id>\<space>\` 바로 아래의 사본뿐. 원본 경로는 '원본 위치 열기'(탐색기에서 고르기)로만 쓴다 |
| 기존 동작 | 몽땅클립보드 창·단축키·트레이·기존 시험 109개(소스의 `#[test]` 수)의 결과를 바꾸지 않는다 |

## 1. 결정

### (가) 어느 프로세스에 넣을지 → **kagent 안의 두 번째 창**

| 기준 | A. kagent 안의 두 번째 창 (권고) | B. 별도 exe (`kvf.exe`) |
|---|---|---|
| UX | 트레이 아이콘 하나, 설치·자동 실행·업데이트가 이미 있다. 몽땅클립보드를 켠 사용자는 바로 쓴다 | 트레이 아이콘·자동 실행 항목이 하나 더 생긴다. 몽땅클립보드와 무관하게 켤 수 있다 |
| 자원 | 숨긴 상태 추가 메모리는 코드 몇 십 KB. 프로세스 하나 | 프로세스가 하나 더 떠 개인 메모리 약 1.8MB가 더 든다(같은 구조라고 볼 때) |
| DX | 틀·단축키·트레이·상태 파일·SQLite·설치 절차를 그대로 쓴다. `popup.rs`의 틀 함수를 공용으로 빼야 한다 | 틀·단축키·설치 절차를 복사하거나 공용 크레이트로 빼야 한다(더 큰 구조 변경). 꾸러미·서명·설치 시험이 하나 더 는다 |
| AX | `status.json` 한 파일에서 두 창의 상태를 읽는다 | 상태 파일·파이프가 둘 |
| 깨질 수 있는 것 | kagent 안의 공용화(V1)가 몽땅클립보드 창을 건드린다 → 함수 옮기기만 하고 시험 수 유지로 막는다 | 기존 코드는 안 건드리지만 새 설치 경로가 생긴다 |
| 되돌리기 | 모듈 하나와 단축키 등록을 빼면 된다 | exe·설치 항목 제거 |

권고 A. 이유: 사용자 지시가 "램 상주 가능·경량"이고, 프로세스를 하나 더 띄우는 B는 같은 일을 하면서 메모리를 약 두 배로 쓴다. B의 유일한 이점(몽땅클립보드와 독립)은 kagent의 '기록 일시정지' 상태로 얻을 수 있다(조사 문서 Q2, 사용자 결정 대기 — 이번 범위는 kagent가 떠 있을 때만 동작).

"단독 실행"의 뜻: 앱 본체 없이 동작한다. kagent는 이미 앱과 따로 뜨고 자동 실행된다(`kagent/src/main.rs:543`). 추가로 `kagent.exe --vfolder`를 둔다 — 떠 있으면 그 프로세스에 창을 열라고 알리고, 안 떠 있으면 띄운 뒤 연다(`--quit`·`WM_SHOW`와 같은 길, `main.rs:1028-1040`).

### (나) 단축키 기본값과 충돌 처리 → **`Win+Shift+F`, 실패 알림은 몽땅클립보드 것을 일반화해 재사용**

- 기본값 `Win+Shift+F`(Folder). 전역 단축키는 다른 프로그램의 같은 조합을 빼앗으므로 프로그램들이 흔히 쓰는 `Ctrl+Shift+글자`는 피한다. `Ctrl+Shift+F`는 Excel 셀 서식·편집기의 전체 찾기와 겹친다고 알고 있다(이 세션에서 실기 확인 안 함). `Win+Shift+F`가 비어 있는지도 실기 확인이 필요하다(조사 C2). 사용자 영향이 있는 선택이라 Q1로 올린다. 설정 값이라 되돌리기 쉽다.
- 설정 키 `vf_hotkey`(글자 40자 이하, `hotkey`와 같은 규칙). 빈 글자면 단축키를 등록하지 않는다(끄기).
- 충돌 처리:
  1. `register_hotkey`를 `(id, 설정 글자, 이름)`을 받게 일반화한다. id 1 = 몽땅클립보드, id 2 = 가상 폴더.
  2. 실패 판정은 순수 함수 `hotkey_failure_notice`를 그대로 쓰고 실패 기억을 id별로 둔다 — 같은 조합의 연속 실패는 한 번만 알린다(기존 동작과 같음).
  3. 알림 제목·본문에 이름을 넣는다: "가상 폴더 단축키를 쓸 수 없습니다 / Win+Shift+F는 다른 프로그램이 이미 쓰고 있습니다. 트레이 아이콘을 눌러 열 수 있고…". 몽땅클립보드 쪽 글은 글자 하나 바뀌지 않아야 한다(기존 시험 `invalid_hotkey_notice_reason_and_deduplication`이 본문 앞부분을 검사한다, `main.rs:1535-1544`).
  4. 두 단축키가 같은 조합이면 가상 폴더 쪽을 등록하지 않고 "몽땅클립보드와 같은 단축키입니다"로 알린다(순수 함수 `same_hotkey`).
  5. `status.json`에 `vf_hotkey`, `vf_hotkey_ok`를 싣는다. 트레이 메뉴에 '가상 폴더 열기'를 넣어 단축키가 막혀도 열 수 있게 한다.

### (다) 창의 상태 기계

대원칙(운영 규칙 0절)에 따라 상태를 값 하나(`enum View`)로 두고, 전이는 순수 함수 `step(상태, 사건) -> (새 상태, 할 일 목록)` 한곳에서만 한다. 창 처리 코드는 사건을 만들고 '할 일'을 실행할 뿐 상태를 직접 바꾸지 않는다. 몽땅클립보드 창처럼 플래그(`minimized`)와 `IsWindowVisible`을 섞어 읽지 않는다.

상태:

| 상태 | 뜻 | 화면 | 메모리 |
|---|---|---|---|
| `Hidden` | 닫힘 | 안 보임 | 목록 없음(비움) |
| `Loading` | 부름을 받아 DB를 읽는 중 | 틀 + "불러오는 중" | — |
| `List { box, space }` | 상자·영역의 목록 | 목록 | 고른 상자의 항목만 |
| `Search { box, query }` | 찾기 글자가 있음 | 거른 목록 | 같음 |
| `Empty(이유)` | DB 없음·상자 없음·항목 없음 | 이유 한 줄 + 할 수 있는 일 | — |
| `Failed(오류)` | DB를 못 읽음(잠김·손상·`winsqlite3.dll` 없음) | 오류 글 + "F5로 다시" | — |
| `Minimized(이전 상태)` | 숨겼지만 상자·영역·찾기·선택 유지 | 안 보임 | 목록 유지 |

'항목 열기'와 '메뉴 열림'은 상태가 아니라 할 일이다(끝나면 곧바로 다음 상태가 정해진다). '끌어 넣기'(`DropHover`, `Adding`)는 다음 범위에서 추가한다.

전이:

| 지금 | 사건 | 다음 | 할 일 |
|---|---|---|---|
| `Hidden` | 부름(단축키·트레이·`--vfolder`) | `Loading` | 창 보이기, DB 읽기 |
| `Loading` | 읽기 성공(항목 있음) | `List` | 그리기 |
| `Loading` | 읽기 성공(없음) | `Empty` | 그리기 |
| `Loading` | 읽기 실패 | `Failed` | 그리기 |
| `List` | 글자 입력 | `Search` | 메모리 목록 거르기 |
| `Search` | 글자를 다 지움·Esc(글자 있음) | `List` | 거르기 |
| `List`·`Search` | 상자 바꿈 | `Loading` | 그 상자 읽기 |
| `List`·`Search` | 영역 칸 바꿈 | `List`(찾기 글자 지움) | 거르기 |
| `List`·`Search` | Enter·두 번 클릭 | 붙박이면 그대로, 아니면 `Hidden` | 열기. 실패하면 상태 유지 + 알림 + 다시 읽기 |
| `List`·`Search`·`Empty`·`Failed` | F5 | `Loading` | DB 읽기 |
| 보이는 상태 모두 | Esc(글자 없음)·닫기 단추·바깥 클릭(붙박이 아님) | `Hidden` | 숨기기, 목록 비우기 |
| 보이는 상태 모두 | 최소화 단추 | `Minimized(지금)` | 숨기기 |
| 보이는 상태 모두 | 부름(붙박이) | `Hidden` | 숨기기(몽땅클립보드와 같은 토글) |
| `Minimized(s)` | 부름 | `Loading`(끝나면 s의 상자·영역·찾기·선택 복원) | 보이기, DB 다시 읽기 |

불가능한 전이(시험으로 막는다): `Hidden`에서 열기·찾기·영역 바꿈, `Loading`에서 열기, `Empty`·`Failed`에서 열기, `Minimized`에서 키 입력 처리. 늦게 온 읽기 결과는 번호(`seq`)가 다르면 버린다(`popup.rs:357-362`와 같은 방법).

대원칙 세 축:
- UX: 지금 무엇을 하고 있고 왜 비어 있는지 항상 한 줄로 보인다(`Empty`의 이유, `Failed`의 오류).
- DX: 상태·전이가 한 파일의 표와 순수 함수이고 창 없이 시험한다.
- AX: `status.json`에 `vf_view`(`hidden`·`loading`·`list`·`search`·`empty`·`failed`·`minimized`), `vf_box`, `vf_items`, `vf_error`를 바뀔 때만 쓴다.

몽땅클립보드 창의 암묵적 상태(`minimized`·`sticky_popup`·`popup_collapsed`·`restore_rect`)는 이번에 고치지 않는다(아무것도 깨뜨리지 않기). 같은 방식으로 옮기는 일은 별도 카드 후보로 남긴다.

### (라) 첫 화면에서 할 수 있는 일

|---|---|---|---|

끌어 넣기를 다음으로 미루는 이유: 사본 만들기·링크와 정션 거부·자기 폴더 복사 방지·색인 갱신이 모두 klib 안에 있고(`klib/src/db.rs:263-307`, `361-443`), kagent가 이를 다시 구현하면 원본 보호 규칙이 두 곳으로 갈린다. klib.exe는 kagent 자료 폴더에 설치되지 않으므로(`kagent/src/main.rs:1300`) 설치 절차부터 넓혀야 한다. 읽기와 열기는 klib 없이 된다.

### (마) klib DB를 읽는 방식 → **읽기 전용으로 직접 열기**

| 기준 | A. `winsqlite3.dll`로 읽기 전용 직접 열기 (권고) | B. klib 파이프 |
|---|---|---|
| 단독 실행 | 된다. klib.exe가 없어도 읽는다 | klib.exe가 kagent 옆에 설치돼 있어야 하고, 부를 때마다 띄워야 한다 |
| 속도 | 프로세스를 띄우지 않는다. 파일 하나 열고 질의 두 번 | klib.exe 첫 실행 시간 + 파이프 왕복. klib는 tantivy까지 든 큰 실행 파일이다(크기·시작 시간 미측정) |
| 메모리 | 읽는 동안만 연결 | klib.exe가 60초 동안 떠 있다 |
| 동시 접근 | WAL이라 읽는 쪽이 klib의 쓰기를 막지 않는다. 쓰지 않으므로 충돌 없음 | 요청이 klib 안에서 줄을 선다(안전) |
| DX | 표 구조를 kagent도 알아야 한다 → 구조가 바뀌면 두 곳을 고친다 | 표 구조는 klib만 안다 |
| 깨질 것 | 없음(읽기만) | klib 설치 절차 변경 |

권고 A. 구조 결합은 다음으로 줄인다: 질의는 `box`의 5개 열과 `item`의 9개 열만 읽고, `origin_path`·`managed_path` 열이 없는 예전 DB는 `PRAGMA table_info(item)`로 확인해 빈 글자로 읽는다(klib가 열을 붙이는 방식과 같음, `klib/src/db.rs:113-119`). 표가 없거나 질의가 실패하면 `Failed`로 간다. klib 쪽에는 "이 열을 kagent 가상 폴더 창이 읽는다"는 주석과 구조 고정 시험을 둔다(V7).

읽기 규칙:
1. `SQLITE_OPEN_READONLY`로 연다. 파일이 없으면 만들지 않고 `Empty(자료 없음)`.
2. 실기에서 WAL DB가 읽기 전용으로 안 읽히면(조사 C1) '읽기·쓰기 열기(만들기 없음) + `PRAGMA query_only=ON`'으로 바꾼다. 어느 쪽이든 `CREATE`·`ALTER`·`INSERT`·`UPDATE`·`DELETE`·`PRAGMA journal_mode`는 코드에 없다.
3. `busy_timeout` 200ms. 넘으면 `Failed("다른 작업이 자료를 쓰는 중입니다. F5로 다시")`.
4. 부를 때마다 상자 목록 + 고른 상자의 항목을 읽고 연결을 닫는다. 보이는 동안은 메모리 목록만 쓴다. 다시 읽기는 부름·상자 바꿈·F5·열기 실패 때만.
5. 항목 상한 5,000개(넘으면 "5,000개까지만 보입니다. 앱에서 보세요" 한 줄). 숨기면(`Hidden`) 목록을 비운다.

앱이 떠 있을 때의 규칙: 앱(→klib)이 쓰는 동안 창은 읽기만 한다. 창이 보이는 사이에 앱에서 옮기거나 지운 항목은 목록에 남아 있을 수 있다 → 열 때 파일이 없으면 "자료가 옮겨졌거나 지워졌습니다" 알림 뒤 자동으로 다시 읽는다. 창은 klib.exe를 띄우지 않고 색인 폴더를 열지 않는다.

여는 경로 검사(순수 함수 `openable`): `managed_path`가 비어 있지 않고, `..`이 없고, 부모 폴더가 `자료 폴더\<box_id>\<space>`와 같고, 파일이나 폴더가 있고, 실행 파일 확장자가 아니다. 링크는 `open_item::safe_web_url`. 어긋나면 열지 않고 이유를 알린다. klib의 `validate_copy_location`(`klib/src/db.rs:315-330`)과 같은 뜻이되 링크·정션 검사는 kagent에 그 함수가 없어 이번에 넣지 않는다(읽기·열기만 하므로 klib가 사본을 만들 때의 검사에 기댄다. 남는 위험으로 적는다).

## 3. 남는 위험

- kagent가 klib의 표 구조를 직접 읽는다. V7의 구조 고정 시험이 없으면 klib 쪽 열 이름 변경이 조용히 창을 깨뜨린다.
- 여는 경로의 링크·정션 검사가 kagent에는 없다(klib가 사본을 만들 때 한 검사에 기댄다). 누군가 사본 폴더를 손으로 정션으로 바꾸면 창은 그것을 따라 연다. V6에서 `GetFileAttributesW`로 재분석 지점 검사를 넣을지 총괄이 정한다(권고: 넣는다, 함수 하나·시험 하나).
- `Win+Shift+F`가 비어 있다는 것은 확인하지 않았다(C2).
- 몽땅클립보드를 켜지 않은 사용자는 이번 범위에서 이 창을 못 쓴다(Q2).
- `popup.rs`의 그리기·입력 처리 세부를 읽지 않았다(조사 문서 '미확인'). V5 워커가 먼저 읽고, 공용으로 더 뺄 것이 있으면 V1과 같은 '옮기기만' 규칙으로 따로 커밋한다.
