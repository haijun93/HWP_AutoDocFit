## 0. 기준선 숫자 읽는 법 (계산의 전제)

계측기는 **메서드 1회를 기록 2건**으로 센다(`hwp.Run` 속성 읽기 1건 + `Run()` 호출 1건, `com_perf.py` `__getattr__`).
속성 값 읽기(`pset.SpacingHangul`)는 1건이다. "함수" 열은 한/글을 직접 부른 가장 가까운 우리 함수 이름이다.
그래서 기준선 숫자를 실제 실행 횟수로 바꾸면 다음과 같다(1차 단계).

| 기준선 함수 | 기록 | 1회당 기록 | 실제 횟수 |
|---|---:|---|---:|
| `hwp_run` | 13,008 | Run 2건 | Run 명령 6,504회 |
| `단어모드_범위선택` | 8,328 | SetPos+SelectText = 4건 | 2,082회 |
| `단어모드_한글자` | 3,500 | SetPos+GetPos = 4건 | 875회 |
| `현재선택영역_텍스트` | 5,496 | InitScan+GetText+ReleaseScan = 6건 | 916회 |
| `단어모드_서식보관` | 2,290 | 글자당 GetDefault 2건 + 호출당 객체 얻기 4건 | 글자 1,079개, 호출 약 33회 |
| `<genexpr>`(서식보관 안) | 15,106 | 글자당 자간 7 + 장평 7 = 14건 | 글자 1,079개(나누어떨어짐) |
| `단어모드_자간적용` | 2,500 | 구간당 CreateAction·CreateSet·SetItem×7·Execute = 20건 | 구간 적용 125회 |
| `두_위치_사이_줄바꿈_문자인가` | 3,220 | SetPos×2+읽기 3 = 10건 | 322회 |
| `단어모드_줄범위` | 6,232 | 10건(자동 줄바꿈 줄) 또는 12건 | 약 573회(추정) |

- 범위선택 2,082회 = 서식보관 1,079 + 한글자 875 + 자간적용 125 + 기타 3 → 계산이 맞아떨어진다.
- `hwp_run` 6,504회의 실제 호출자(추정): 줄범위 약 2,400 / 한글자 1,750(이동 1 + Cancel 1) / 서식보관의
  `_단어모드_다음위치` 1,079 / 두_위치 644 / 나머지 약 630(줄마다 고정 6회 안팎 → **처리한 화면줄 약 100줄**, 추정).
- 현재선택영역_텍스트 916회 중 875회가 한글자다. 옛 경로(`_자간자동조정_본체` 1402줄 반복)는 줄마다 4회 이상 읽으므로,
  기준선은 `단어중간_줄바꿈방지` 경로(작업 방식 all의 '단어 분리 최종 검사', spacing.py:1389)로 돌았다고 본다(추정).

## 3. 구현 단계 (위험 '없음'만: A, B, C, D)

**명시적 상태(운영 규칙 0절)**: 지금은 "이 줄을 아직 안 고쳤다"가 코드에 드러나지 않는다. `줄검사_기억`이라는 값 하나로 드러낸다.

- 상태: `없음`(기억 안 함, 기본) → `편집전`(기억함) → `편집후`(기억 비움, 다시 기억하지 않음) → `없음`.
- 전이: `단어중간_줄바꿈방지` 진입 시 `없음→편집전`, 끝날 때(finally) `→없음`. 자간·장평·글자색 적용이나
  이동·Cancel·Select가 아닌 `hwp_run` 명령이 실행되면 `편집전→편집후`.
- 불가능한 전이: `편집후→편집전`(같은 줄 처리 안에서는 다시 기억하지 않는다). `없음` 상태에서는 지금 코드와 완전히 같게 움직인다.
- 읽는 곳: 진단로그에 줄마다 "기억 적중 n / 실제 호출 m / 상태" 한 줄(개발자·에이전트용), COM 계측에는 호출 감소로 드러난다.

## 4. 전후 결과 HWPX 비교 방법

1. **결과 만들기**: 변경 전 커밋과 변경 후 커밋에서 각각 지정 시연 문서 **사본**을 같은 설정(작업 방식 all)으로 처리해
   결과 HWPX를 `E:/docfit-tmp/perf2/before`, `…/after`에 둔다. 실행은 `scripts/perf_baseline_pc.py`(계측 포함,
   `feature/perf-baseline` 병합 필요) 또는 `scripts/regression_pc.py`(사본 처리, `--flag`로 전역 플래그 지정 가능).
   한/글 시험이므로 `C:\HWP_AUTODOCFIT\.com-test.lock` 잠금을 잡는다.
2. **주 비교: `scripts/analyze_hwpx_diff.py before.hwpx after.hwpx --output diff.json`**. 스타일 ID를 header.xml로 풀어
   문단별 글(`text_change`)·문단 모양(`paragraph_format`)·글자 모양(`character_format`, 자간·장평 포함)·줄 배치(`line_layout`)를
   비교한다(defusedxml 사용). **합격 = `changed_paragraphs`가 빈 목록이고 `paragraph_count` 전후가 같음.**
   한계: `Contents/section0.xml`만 읽는다(109~112줄). 구역이 여러 개인 문서는 3번으로 보완한다.
3. **보조 비교**: 두 HWPX를 풀어 `Contents/section*.xml`, `Contents/header.xml`의 SHA-256이 같은지 본다. 같으면 그대로 합격.
   다르면 2번 결과로 판정한다(한/글이 저장할 때마다 ID·시각 같은 값이 달라질 수 있어 바이트 비교만으로 불합격 처리하지 않는다).
   같은 커밋으로 두 번 돌린 결과끼리 먼저 비교해 "원래 흔들리는 값"을 확인해 둔다.
4. **`scripts/compare_versions_pc.py`**: 두 코드 폴더(`--beta-root`, `--alpha-root`)를 번갈아 실행해 시간과 결과를 비교한다.
   결과 비교는 글 해시(`text_identical`)와 문단·표·그림 수뿐이라 **글자 모양·문단 모양은 보지 않는다**(235~262줄).
   속도 전후 비교(반복 측정, `--require-same-layout`)에는 쓰되 "결과가 같다"의 근거로는 2번을 쓴다.
5. **로그 비교**: 처리 로그의 `[단어 분리]`·`[다음 단어 당김 적용/미적용]`·`[단어 중간 줄바꿈 방지]` 줄과 통계
   (`단어분리_통계`, `다음단어_통계`, `단계탐색_통계`의 탐색·측정 횟수)가 전후 같아야 한다. 탐색·측정 횟수가 같으면
   "시도한 단계가 하나도 바뀌지 않았다"는 뜻이다.

## 5. 남은 문제

- 2절 감소 수치는 기준선 한 번의 숫자에서 역산한 **추정**이다(줄 수·중복 비율 미실측). 3절 1단계가 이를 실측으로 바꾼다.

- 표/컨트롤·개요 자간 단계의 바깥 반복은 읽지 않았다(미확인). 같은 함수를 쓰므로 효과는 있겠지만 수치는 따로 재야 한다.
