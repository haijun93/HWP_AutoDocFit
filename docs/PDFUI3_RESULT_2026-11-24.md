# PDFUI3 검증 결과 — 2026-11-24

## 범위와 기준

- 기준: 로컬 `mac/PDFUI2`의 `bc3b2bec`, 작업 브랜치 `feature/PDFUI3`.
- PDF 위젯 실패 4건과 중괄호 린트 info 3건을 재현한 뒤 수정했다. API 이름·요청 형식·원본 보존 정책은 유지한다.
- PDF 편집 화면·네이티브 브리지의 중괄호·PDF 위젯 시험을 수정했다. 실제 WebView2 실기는 포함하지 않는다. 커밋만 하며 푸시하지 않는다.

## 원인과 수정

| 실패 시험 | 확인한 원인 | 수정 및 검증 |
| --- | --- | --- |
| PDF 쪽 정보 오류 안내·다시 시도 | 쪽 정보 오류가 미리보기 Text와 작업 패널 SelectableText에 중복 표시됐다. 재시도는 로딩 상태를 다시 켜지 않아 진행 표시가 없었다. | `_pageError`를 일반 작업 메시지에서 분리해 미리보기에 한 번 표시한다. 재시도 시작 시 이전 오류를 비우고 로딩 상태로 전환한다. 응답을 지연시켜 진행 표시를 확인하고, 재시도 성공·쪽 카드 복원·오류 제거를 검증한다. |
| 드롭 영역·비활성 실행 상태 | 파일을 열기 전 작업 패널 전체가 없어 저장 버튼도 없었다. 시험이 요구한 비활성 저장 상태를 화면이 제공하지 않았다. | 넓은 화면은 빈 상태에도 작업 패널을 표시하고, 좁은 화면은 드롭 영역 아래 비활성 저장 버튼을 표시한다. 파일 열기 버튼·드롭 영역·도구·저장 비활성 기대값을 유지했다. |
| 방향키·드래그 순서 변경 저장 | 1024×768에서 완료 메시지와 결과 카드가 나타나면 작업 패널 Column이 아래로 25px 넘쳤다. | 고정 작업 패널 내부를 스크롤하게 해 완료 내용까지 접근할 수 있게 했다. 방향키·드래그 동작, 정수 목록 `[2, 3, 1]`, 최종 저장 경로·완료 안내를 확인한다. |
| 회전 후 삭제 누적 저장 | 동일한 완료 작업 패널 넘침으로 실패했다. | 회전→삭제 호출 순서, 정수 쪽 목록 `[1]`→`[2]`, 회전각 90, 중간 결과를 다음 입력으로 연결하는 처리, 최종 저장 경로·완료 안내를 검증한다. |

화면을 수정했고 기존 시험의 통과 기준은 낮추지 않았다. 저장 경로 검증을 추가하는 과정에서, 순서 변경 후 선택된 쪽이 남아 있으면 현재 도구(기본 삭제)를 자동으로 추가하는 결함도 발견했다. 누적 편집이 있으면 그 목록만 저장하며, 누적 편집이 없을 때만 현재 도구·선택 쪽을 사용한다. 순서 변경 저장에 삭제 API 호출이 없다는 검증을 추가했다.

쪽 정보 상태는 비어 있음→로딩→준비/오류이며, 오류→재시도 로딩→준비/오류로 전이한다. 일반 편집 실행은 쪽 정보를 읽는 중이거나 쪽 정보가 없으면 비활성이다. 저장 중 상태와 작업 결과 메시지는 쪽 정보 오류와 분리한다.

`bridge_native.dart`의 빈 파일 선택·폴더 선택 분기 2곳과 PDF 화면의 오류 안내 분기 1곳에 중괄호를 추가했다.

## 글꼴

- 이 화면에는 직접 작성한 RichText가 없고 Text·SelectableText·입력 필드가 앱 테마를 상속한다. `tab_navigation_shell.dart`처럼 RichText를 직접 만들 때 기본 글꼴을 잃는 문제와 구분했다.
- 실제 앱의 `buildAppTheme`을 사용하는 밝은/어두운 테마 위젯 시험 2건을 추가했다. 빈 드롭 화면 및 한글·기호 파일명/회전 작업 표시 상태에서 생성되는 한글 RichText의 `NotoSansKR`와 `NotoSansSymbols2`/`STIXTwoMath` 폴백을 확인했다. EditableText 스타일도 확인했다.
- 글꼴 파일은 기존 번들 선언을 사용한다. 폴백 스타일 검사 통과는 실제 WebView2의 글리프 렌더링·시각 검증을 대신하지 않는다.

## 시험 결과

- 수정 전 `flutter test test/pdf_edit_workspace_test.dart`: 통과 11건·실패 4건.
- 수정 전 `flutter analyze`: info 3건, 종료 코드 1.
- 수정 후 PDF 위젯 시험은 최초 17건 통과 후, 작은 화면 2종의 저장 및 재시도 대기 중 진행 표시 검증을 보강했다. 최종 `flutter test test/pdf_edit_workspace_test.dart`: `00:08 +19: All tests passed!`, 종료 코드 0.
- 최종 `flutter analyze`: `No issues found! (ran in 8.3s)`, 종료 코드 0.
- 첫 전체 `flutter test`: `05:45 +821 ~3 -1: Some tests failed.` PDF 시험은 모두 통과했다. 별도 자료함 탐색기 더블클릭 시험 1건이 폴더 진입 후 파일 행을 찾지 못했다. 해당 화면은 `DateTime.now()`로 두 클릭 사이 500ms를 판단하므로 부하에 영향을 받을 가능성이 있다. 관련 없는 구현·시험은 수정하지 않았다.
- 최종 전체 `flutter test --concurrency=1`: `11:43 +824 ~3: All tests passed!`, 종료 코드 0. 대상 시험 파일 111개, 통과 824건·기존 제외 3건, 실패 0건. 앞서 실패한 자료함 시험도 통과했으나 병렬 실행에서의 시간 의존성은 이번 수정 범위 밖으로 남긴다.
- 전체 Python `python -m unittest discover -s tests`: 시험 모듈 397개를 대상으로 3,590건 실행, 통과 3,572건·조건부 제외 18건, 실패·오류 0건, 종료 코드 0. 실제 종료 요약:

```text
Ran 3590 tests in 1027.843s

OK (skipped=18)
```

전체 Python 시험은 변경하지 않는 별도 소스 사본에서 실행했다. 작업 worktree에 가상환경이 없어 원본 worktree의 기존 Python 3.14 가상환경을 재사용했다. COM 시험 잠금을 획득한 상태에서 다른 시험·빌드와 겹치지 않게 실행했고, 종료 후 잠금 해제도 확인했다. 브리지·PDF 화면·위젯 시험 파일이 작업 브랜치와 사본에서 동일함을 해시로 대조했다. 엔진 경로와 임시 폴더는 실행 환경변수로만 지정했다. 기존 SyntaxWarning/ResourceWarning 출력은 있었으나 시험 실패·오류는 없었다.

Python 종료 시 시험 sandbox의 `timeline-content.sqlite`를 정리하는 atexit 콜백에서 파일 사용 중 `PermissionError (WinError 32)`가 출력됐다. unittest 결과는 위의 OK이며 프로세스 종료 코드는 0이다. 이 임시 DB 정리 문제는 PDF 화면 수정과 별개로 남겼고 시험 코드를 변경하거나 숨기지 않았다.

최종 변경 파일의 UTF-8 디코딩과 한글 diff를 확인했고 `git diff --check`를 통과했다. 원본 사용자 문서·본체 CRLF·기존 API 요청 형식은 변경하지 않았다.

## 확인하지 못한 것

- 실제 Windows WebView2의 OS PDF 드롭 경로 전달과 탭 활성 상태 연동.
- 네이티브 열기·다중 선택·저장 대화상자의 실제 동작과 취소 처리.
- 실제 PDF 렌더링, 한글·기호의 시각적 표시 및 화면 캡처.

위 3개 실기 범위는 사용자의 실제 앱 확인이 필요하다. 이 작업은 설치·배포·태그·원격 푸시를 수행하지 않는다.
