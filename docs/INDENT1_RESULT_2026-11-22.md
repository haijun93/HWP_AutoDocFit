# INDENT1 결과 — 2026-11-22

## 판정

- ALLQA 세트 6건을 `all` 모드로 기준 1회(`DOCFIT_INDENT_DIRTY=off`), 개선 1회(`label=indent`, 기본 추적 켬) 실행했다. 두 배치 모두 잠금을 유지하고 문서를 한 번에 하나씩 처리했다.
- 처리 성공은 각 5/6건이며 `hwpx_table`은 두 배치 모두 한/글 열기 단계에서 실패했다. 완료된 5개 결과의 본문 문단 수·텍스트 XML·서식 XML 비교는 **5/5 동일**이다. 실패 문서는 결과가 없어 비교하지 못했다.
- 전체 시간 합계는 296.853초에서 477.777초로 늘었고, COM 호출은 154,212회에서 153,012회로 1,200회(0.78%) 줄었다. 전체 시간 개선은 확인되지 않았다. 단 한 번씩의 실행 결과이므로 시간 변화 원인을 분리하거나 속도 향상을 주장하지 않는다.
- `txt_short`, `hwpx_continuation`, `hwpx_shapes`는 바뀐 문단이 없어 최종 재확인을 생략했다. `hwp_reference`는 6개, `txt_long`은 37개 문단을 최종 재확인했다. `txt_long`의 재확인은 거의 전 문단이 후보여서 이 문서의 시간·호출 감소는 나타나지 않았다.
- 현재 대상 필터는 내어쓰기 계산을 대상 문단에만 호출하지만, COM 문단 순회와 붙임 번호 대상 수집은 전체 문서를 훑는다. 따라서 후보가 있는 문서의 재확인 COM 호출을 줄이지 못할 수 있다. 이 측정에서 `txt_long`의 최종 재확인 호출은 5,186→5,238회였다.

## 세 번의 내어쓰기 단계

1. **최종 서식 기준 내어쓰기** — 보고서 표준서식과 표·개요 서식을 적용한 뒤, 본문 항목 문단의 현재 글꼴·크기·장평을 기준으로 한/글 Shift+Tab의 실제 위치를 재서 처음 내어쓰기를 맞춘다. `all`의 첫 본문 자간 조정 전에 실행한다.
2. **자간 조정 후 내어쓰기** — 자간·장평이 실제 바뀐 문단만 다시 계산한다. 내어쓰기 재적용 후 자간 검사를 최대 3회까지 반복하며, 반복 검사는 직전 내어쓰기에서 바뀐 문단만 대상으로 한다.
3. **최종 내어쓰기 재확인** — 자간 조정·짧은 줄 처리·페이지 간격/배치가 끝난 뒤 실제 변경 문단을 재확인한다. 자간 변경 집합과 페이지 조정 집합을 합쳐 대상 위치를 추적하고, 알려진 변경 집합을 얻지 못하거나 위치가 잘못된 경우에는 전체 확인으로 되돌린다. `DOCFIT_INDENT_DIRTY=off`도 전체 확인을 강제한다.

## 안전 장치 및 확인 범위

- `DOCFIT_INDENT_DIRTY=off`이면 변경 집합과 관계없이 기존 전체 확인 경로를 사용한다.
- 위치 집합의 누락·형식 오류·추적 불확실성은 전체 확인으로 폴백한다. 알려진 변경 집합이 비어 있으면 최종 재확인을 생략한다.
- 변경 문단을 직접 `SetPos`로 찾아가는 방식은 이번 구현에 포함되지 않았다. 대상이 있는 문서에서도 전체 순회가 남아 있어 결과는 같았지만 재확인 처리 시간 개선은 확인되지 않았다.
- 픽스처 원본과 처리 입력 사본의 SHA-256은 기준·개선 각 6/6 불변이었다.
- 작업 폴더에 `.venv`가 없어 ALLQA와 단위 시험은 설치된 시스템 Python 3.14로 실행했다(`win32com`, `defusedxml` 사용 가능 확인).
- 기존 ALLQA 기준에서 TXT/HWP 입력의 원문 텍스트 보존 검수가 실패하고 `hwpx_table`이 열리지 않는 현상은 개선 배치에서도 같았다. 결과 동일성 판정은 완료된 두 HWPX 결과 문서의 내용·서식 비교로 별도 확인했다.
- 변경 문단 선택 로직 합성 입력 단위 시험 4건 통과, `py_compile` 통과. 전체 시험은 실행하지 않았다.
- 측정 출력은 저장소 밖에 보관했다. 이 결과서는 측정 수치와 확인 한계를 함께 기록한다.
