## 구현

- 상태: `없음 → 편집전 → 편집후 → 없음`. 같은 줄의 `편집후 → 편집전` 전이는 금지한다.
- `DOCFIT_SPACING_MEMO=verify`: 기억이 있어도 실제 COM 호출 후 비교한다.
- `DOCFIT_SPACING_MEMO=reuse`: 편집 전 적중 결과만 재사용한다. 변수 미지정 시 호출 생략 없음.
- 자간·장평·글자색 적용 및 이동/선택/취소 외 명령에서 기억을 비운다. `finally`에서 종료한다.
- RunContext가 사용자 정의 객체를 공유하므로 줄 진입 시 현재 실행에 새 기억·편집 훅을 배정한다.
- 요약 누락 원인: `pipeline.py`의 `진단로그`는 `검수_사용`이 켜져야 작업 로그로 전달한다. 계측은 검수 OFF여서 별도 저장도 없었다. 활성 모드의 줄 요약을 작업 `로그`에 직접 기록하도록 수정했다. 불일치 상세는 기존 진단로그, 건수는 줄 요약에 남는다.

## 변경 크기·보존

- 인계 시 일반 diff 321줄 추가/199줄 삭제, `diff -w` 127줄 추가/5줄 삭제. 차이의 대부분은 종료를 보장하는 try/finally로 기존 줄 처리 본문을 한 단계 들여쓴 부분이다. 기존 알고리즘은 제거·주석 처리하지 않았다.

- verify의 `original_unchanged=true`, `copy_unchanged=true`, 오류 0, 저장 1개.
- TXT 대비 결과의 `text_preserved_ignoring_whitespace=false`도 기록됐다. TXT→표준서식 변환의 원문 대조 지표이며 변경 전후 HWPX 동일 판정과 구분한다. 원문 보존 검사를 통과했다고 주장하지 않는다.

## 남은 판정

**지정 시연 문서의 두 합격 기준 충족**: 본문 자간 COM 기록 **67,182 → 55,848 (11,334회·16.871% 감소)**. 전체 COM은 **148,211 → 132,667 (15,544회 감소)**. 본문 단계 시간은 **118.6797 → 99.2718초**, 전체 시간 **387.137 → 330.102초**. 1회 측정이므로 시간 차이는 반복 검증된 성능 보장으로 해석하지 않는다.

- 주 비교(`i1-reuse-diff.json`): 문단 53→53, `changed_paragraphs=[]`. 본문·글자 모양·문단 모양·줄 배치 동일.
- 보조 비교(`i1-comparison-summary.json`): HWPX의 header.xml 및 section0.xml이 각각 SHA-256까지 동일하다. 이 문서는 구역 1개이다.
- reuse 요약: 133줄, 기억 적중 739회, 실제 검사 800회. verify 대비 검사 739회를 실제 생략했다. 편집 전 적중 합계는 A·B 합산 실측이며 함수별 적중 수는 따로 계측하지 않았다.
- 전후 통계 로그 5줄 동일: 단어 분리 대상 22/성공 22/실패 0, 단계 탐색 37회/줄 배치 측정 133회, 다음 단어 당김 대상 15/적용 9/미적용 6. 문장부호 병합·세트문장 페이지 통계도 동일. 세부 진단 판정 로그는 검수 OFF로 양쪽 모두 없어 상세 판정별 대조는 못 했다.
- reuse도 원본·처리 사본 보존 true, 오류 0, 저장 1개. 종료 후 한/글 프로세스와 COM 잠금이 남지 않았다.

호출 생략은 opt-in `reuse`만 제공한다. 회귀 문서 묶음은 실행하지 않았고, 변경 전 전체 시험의 최종 집계는 없다. 시연 문서 1개의 결과를 모든 문서로 일반화하지 않는다. 설계서의 전체 회귀 묶음 완료로 표시하거나 기본 활성화하지 않는다. 후속 C·D 구현은 하지 않았다.
