# EFF4 — 자간 조정의 글자 단위 한/글 읽기 줄이기

작성: 2026-11-27 · 브랜치: `feature/EFF4` · 로컬 커밋만, 푸시 없음.

## 판정

장평을 바꾸지 않는 경로에서 장평 7슬롯 읽기만 뺐다. 합성 문서 실측에서 본문 자간 단계 COM 호출은 장평 끔 **-16.9%**, 장평 켬 **-6.1%**이고 결과 HWPX의 글자별 글자 모양 차이는 0건이다. **시간 단축은 측정 흔들림이 커서 크기를 확정하지 못했다.**

## 후보별 결정

| 후보 | 결정 | 이유 |
|---|---|---|
| (a) 장평을 바꾸지 않는 경로는 장평을 읽지 않음 | 적용 | 장평 값은 장평 축소 시도에서만 쓰며, 설정이 꺼져 있으면 그 함수는 바로 돌아간다. 자간 보관(연결 부호·괄호 안 공백·다음 줄로 밀기·서식 통일)은 자간만 쓴다 |
| (b) 값을 바꾸기 직전까지 읽기를 미룸 | 미적용 | 보관하는 곳은 첫 변경 전에 탐색 한도(보관 값의 최소·최대)를 계산하므로 미룰 구간을 찾지 못했다 |
| (c) 같은 서식 구간이면 한 번만 읽음 | 미적용 | SPDMEMO5: 범위 읽기는 첫 글자 값만 돌려주고 혼합을 알리지 않는다. 같은 서식임을 확정할 다른 근거를 이번에 새로 조사하지 않았다 |

글자별 이동·선택·`GetDefault`와 자간 7슬롯 읽기, 쓰기·원복 코드는 바꾸지 않았다.

## 변경

- `docfit_engine/spacing.py` `단어모드_서식보관(start, end, 장평포함=None)`: `None`이면 `장평_줄이기_사용`을 따른다. 읽지 않은 장평 자리는 빈 목록이 아니라 `None`(모르고 원복에 쓰면 조용히 지나가지 않게).
- `단어모드_자간보관`은 `장평포함=False`, `단어모드_장평보관`은 `True`.
- `tests/test_format_save_and_pagefit.py` 1줄: 장평까지 읽는 계약을 보는 시험에 `장평_줄이기_사용: True`를 명시했다. 단언은 그대로다. ROLLBACK1 시험 파일은 고치지 않았다.
- 신규 `tests/test_eff4_format_read_calls.py`(7개): 상태형 가짜 hwp로 호출 수, 혼합 자간·장평 80/160의 보관·원복 값을 확인.

## 실제 한/글 전후 비교 (측정)

- 합성 문서: 8문단 1,224자, 자간·장평(80·160·언어별 상이)을 섞음. 표·컨트롤 없음.
- 작업 방식 `spacing`, COM 계측 켬. 변경 전 = `cb36d780` 코드 사본, 변경 후 = 작업 폴더. 전후를 번갈아 순차 실행.
- COM 잠금 배타 생성 후 `DispatchEx` 새 인스턴스만 사용(`Dispatch` 대체 경로 차단). 프로필 환경 변수를 임시 폴더로 돌려 사용자 설정을 쓰지 않았다. 장평 설정은 실행 중 메모리에서만 지정.
- 드라이버는 도구의 백그라운드 실행(상한 2시간)으로 돌렸다. 상한에 닿지 않았고 강제 종료는 없었다.

| 장평 설정 | 전/후 | 본문 자간 단계 COM 호출(회차마다 동일) | 단계 시간 1 / 2 / 3회(초) | 전체 COM 호출 |
|---|---|---:|---|---:|
| 끔(기본) | 전 | 42,356 | 69.2 / 68.8 / 90.1 | 44,201 |
| 끔(기본) | 후 | 35,209 (-7,147, -16.9%) | 62.8 / 164.4 / 81.2 | 37,054 |
| 켬 | 전 | 43,662 | 84.0 / 72.5 / - | 45,507 |
| 켬 | 후 | 41,016 (-2,646, -6.1%) | 74.6 / 71.5 / - | 42,861 |

- 끔 2회차의 후(164.4초)는 호출 수가 같은데 COM 시간 전체가 늘었다(`단어모드_서식보관`의 다른 호출도 약 2배). 원인은 확인하지 못했다. 그래서 끔 설정은 한 쌍을 더 쟀고, 모든 값을 그대로 적었다.
- 시간: 끔 1·3회차는 후가 약 9~10% 짧고 2회차는 반대다. 같은 코드(전)도 68.8~90.1초로 흔들린다. **시간 개선율은 주장하지 않는다.** 첫 쌍의 속성 읽기(`<genexpr>`) 시간은 5.6→3.1초였다.
- 결과 동일성: 10개 결과 모두 같은 설정끼리 글자별 글자 모양(글꼴 참조·자간·장평·색 등 charPr 전체) 차이 0, `linesegarray`를 뺀 section XML 동일. 원본 대비 변경 글자는 끔 953, 켬 1,023이라 조정이 실제로 일어났다.
- 처리 통계(첫 쌍 로그 확인): 끔 = 단어 분리 15/15 성공, 단계 탐색 21회·측정 62회, 다음 단어 당김 6건(적용 4·미적용 2). 켬 = 14/14, 23회·81회, 7건(7·0). 전후 같다.
- 사본 원본 해시 불변, 오류 0. 종료 뒤 COM 잠금과 Hwp 프로세스가 남지 않았다.
