## 설정 전달 방식

CLI `hwpx_fmt <처리기> <입력> <출력> [--selections 파일.json] [--config 설정.json]`, `hwpx_fmt survey <처리기> <입력> [--config 설정.json]`. 처리기 이름: `date`·`twochar`·`overview_lead`·`page_number`·`spacing_reset`(파이썬 함수 이름도 별칭으로 받음).

설정 JSON(`hwpx_fmt/src/config.rs`):

| 키 | 파이썬 원본 | 반영하는 처리기 | 비고 |
|---|---|---|---|
| `page_number` | `표준서식_설정["쪽번호"]` | `page_number` | **문자열 값만**. 숫자 등이면 거부. 속성 대입 순서 = JSON 키 순서(파이썬 dict 순서와 같음) |
| `title_owner_text` | `제목_담당자_글` | (반영 못 함) | 비어 있지 않으면 `twochar`·`overview_lead` 가 거부 |
| `indent_rules` | `표준서식_설정["내어쓰기_규칙"]` | (반영 못 함) | 비어 있지 않으면 `spacing_reset` 이 거부 |

알 수 없는 키·형식 오류도 `미지원 입력:`(종료 코드 4)로 거부한다. 하네스는 파이썬 쪽에 같은 값을 `fn.__globals__`(`표준서식_설정`·`제목_담당자_글`·`활성_항목기호_체계`)로 넣고 시험 뒤 되돌린다. 앱이 실제로 이 값들을 JSON 으로 내려주는 연결 코드는 이 카드 범위 밖이다.

## 남은 한계 (통과했다고 쓰지 않는 것)

1. **자간 초기화는 기본 설정에서만 동등**: 활성 항목기호 체계가 비어 있지 않거나(`marker_scheme_active`) 서식 복사로 `내어쓰기_규칙`이 있으면 보호 구간이 달라지는데 이 부분은 이식하지 않았다(`스키마 canonical`·`복사_내어쓰기_규칙`·`leading_marker`·`서식요소.unify_marker`·`hanging_indent_offset` 필요). 하네스·CLI 는 이 경우를 거부한다. **앱에서 서식 복사나 항목기호 체계 감지가 켜진 문서는 Rust 경로를 쓸 수 없고 파이썬 폴백이 필요하다.** 실제 앱에서 이 설정이 얼마나 자주 켜지는지는 확인하지 못했다(실제 문서 금지).
2. **담당자 칸 글 설정(`제목_담당자_글`)**: 서식 표 판별에 반영하지 못해 두 글자 칸·개요 첫 빈칸이 거부한다(RSXML1 한계 유지, 이제 조용히가 아니라 거부).
3. **유니코드 범주**: Rust `regex` 의 유니코드 표와 파이썬 `unicodedata` 의 유니코드 판이 다를 수 있다. 사례에 쓴 기호(□ㅇ※·원숫자·낫표·따옴표·대시 등)는 같았으나 최근 추가된 희귀 기호는 시험하지 않았다. 판 차이가 나면 `Ps/Pe/Pi/Pf`·`So/Sm/Po` 판정이 달라질 수 있다.
4. **`str.isdigit()`/`int()`**: 글자 모양 번호에 ASCII 가 아닌 숫자 모양 글자(`²`, 아랍 숫자 등)가 있으면 파이썬은 `ValueError` 로 중단하거나 번호로 취급한다. Rust 는 그 경우 `미지원 입력`으로 거부한다(안전 쪽). 구역 파일 이름의 비ASCII 숫자도 같은 이유로 시험하지 않았다.
5. **파이썬 글 보존 검사(`RuntimeError`) 미이식**: 자간 초기화 뒤 구역 글이 달라지면 파이썬은 중단한다. Rust 는 구조상(run 을 둘로 나눌 뿐) 글이 바뀔 수 없어 검사하지 않았다. 로그 문구(`로그()`)도 내지 않는다.
6. **XML 파서 차이**(RSXML1 그대로): UTF-8(BOM 허용)만, DOCTYPE 전부 거부. 이제 구역이 아닌 `Contents/*.xml` 도 같은 파서로 확인하므로 파이썬(expat)이 받는 DOCTYPE·다른 인코딩 선언의 비구역 XML 은 Rust 가 거부한다(안전 쪽). 실제 한/글 HWPX 는 해당 없음.
7. **표본의 한계**: 개요 첫 빈칸은 제목 표+개요 상자 쌍이 든 실제 구조가 fixture 에 없어 합성 사례로만 검증했다(변형 fixture 에서도 대상 0). 쪽 번호·자간 변형 fixture 는 실제 구조에서 일부만 바꿔 만든 것이라 실제 기관 문서의 대형·복잡 표와 항목기호 분포를 대표하지 못한다. 무작위 문단 묶음은 보호 구간 분기를 넓게 건드리지만 모든 조합을 덮지는 않는다.
8. 속도는 1회 측정이며 부하 중 측정이다(위 두 측정값이 서로 다른 이유). Rust 값은 프로세스 기동 포함 전체, 파이썬 값은 모듈 적재 제외라 파이썬에 유리하게 잡혔다.
9. 변형 fixture 가 만드는 쪽 번호 요소는 `<hp:run>` 첫 요소 안의 `<hp:ctrl>` 이어서 실제 HWPX 의 쪽 번호 위치와 다를 수 있다(속성 갱신 논리 검증용).

## 앱 연결 시 남는 일
RSXML1 목록에 더해: 앱 설정(`표준서식_설정` 등)을 `--config` JSON 으로 내리는 코드, 종료 코드 4(미지원 입력) 시 파이썬 처리기로 폴백하는 흐름, 로그 문구 대응, 처리기별 `selections` 가 순차 출력마다 다시 계산되는 계약(RSXML0 설계 참조) 유지.
