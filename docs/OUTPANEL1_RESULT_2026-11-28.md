# OUTPANEL1 결과 — 아웃라이너(앱 안 화면) 패널 접고 펴기 (2026-11-28)

사용자 요청: 좁은 창에서 아웃라이너 메뉴가 가로폭을 많이 차지하므로 접고 펼 수 있게 해 달라.
합성 데이터만 썼다. 설치본·사용자 설정·사용자 데이터·실행 중인 앱은 건드리지 않았다. 푸시하지 않았다.

## 1. 한 일

- 오른쪽 패널(220): 접기 단추. 접으면 36 폭 세로 띠에 펴기 단추가 남고 본문이 그만큼 넓어진다.
- 왼쪽 패널(248): 같은 방식. 접었다 펴도 검색어는 남는다.
- '역링크'·'역참조 (선택 블록)': 제목을 눌러 각각 접고 편다. 개수는 제목에 보이며, 지금 페이지·선택 블록에 대해 실제로 읽은 값이 있을 때만 보인다. 조회를 늘리지 않았다.
- 접힌 상태 저장: 아웃라이너 데이터 폴더의 `outliner_panels.json`. **사용자가 누른 항목만** 저장한다. 읽기·쓰기 실패는 무시한다.
- 좁은 창: 오른쪽 패널의 저장 값이 없고 본문이 420 미만이 되면 접은 채 시작한다. 처음 한 번만 정하며 이 값은 저장하지 않는다.
- '새 창(Win32)으로 열기': 별도 줄의 글자 단추를 제목 줄 끝의 아이콘 단추(도움말 문구 포함)로 바꿨다. 실패 이유는 제목 줄 아래에 보인다.
- 편집 보존: 접기 단추·제목은 포커스를 가져가지도, 칸 바깥 클릭으로 치지도 않는다.

바꾸지 않은 것: 키 처리, `outliner_typeahead.dart`, 엔진 호출, 다른 화면. 오른쪽 패널은 접어도 트리에 남아 같은 시점에 조회한다.

## 2. 요청에 없었지만 필요해서 바꾼 것

- 제목 줄: 폭이 460 미만이면 단추를 제목 아래 줄로 내린다(넘침 방지).
- 블록 줄: 쓸 수 있는 폭이 250 미만이면 줄 끝의 들여쓰기·내어쓰기 **단추를 숨긴다**. Tab·Shift+Tab 은 그대로다. 예: 폭 700 에서 두 패널을 모두 편 경우, 깊이 들여 쓴 줄.
- 오른쪽 패널 내용은 길면 세로 스크롤된다.
- 왼쪽 검색 칸의 안쪽 여백을 줄였다(접기 단추 자리 때문에 안내 문구가 잘렸다).

## 3. 상태

한 항목의 접힘 = 사용자가 누른 값(저장) → 없으면 처음 값.
처음 값은 펼침이고, 오른쪽 패널만 좁은 폭에서 접힘이다. 저장 값을 읽기 전에 누르면 누른 값이 이기고, 저장은 읽기가 끝난 뒤 차례로 쓴다.

## 4. 설계 판단

`OutlinerWorkspace` 에 저장소를 넣지 않으면 저장도 좁은 창 자동 접기도 하지 않는다. 앱에서는 `OutlinerUiGate` 가 파일 저장소를 넣는다.
이유: 기존 위젯 시험은 800 폭(본문 331)에서 저장소 없이 화면을 만들고 '역링크'가 보이기를 기대한다. 이 방식이면 기존 시험을 고치지 않고, 시험이 실제 사용자 폴더를 읽거나 쓰지 않는다.

## 7. 남은 문제·확인하지 않은 것

- 설치본·실제 창, 실제 IME 조합 중 접기, 실제 `outliner_panels.json` 생성·복원은 확인하지 않았다(파일 저장소는 임시 폴더 시험만).
- 폭 700 에서 두 패널을 모두 펴면 본문이 약 230 이라 글이 좁게 줄바꿈된다.
- 저장 값이 '펼침'인데 좁은 창이면, 저장 값을 읽기 전 잠깐 접힌 모습이 보일 수 있다.
- 접기 단추·제목은 포커스를 받지 않으므로 키보드(Tab)로는 누를 수 없다. 기존 실행 취소 단추와 같은 방식이다.
- 기존 동작(이번에 고치지 않음): 확정 전 글이 있는 채로 입력 칸 바깥의 다른 곳을 마우스로 누르면 글이 되돌아갈 수 있다. 위 결함 검출 확인에서 같은 경로를 보았으나 다른 단추·빈 곳 각각은 시험하지 않았다.
- 코드상 추정(미확인): 최근 페이지가 많고 창이 낮으면 왼쪽 패널이 세로로 넘칠 수 있다(기존 배치).
