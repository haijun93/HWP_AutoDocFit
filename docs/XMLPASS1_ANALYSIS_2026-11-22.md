# XMLPASS1 — XML 판정으로 대체 가능한 COM 읽기 분석

작성일: 2026-11-22 · 설계 분석 전용 · 구현은 후속 XMLPASS2

## 결론

한 번에 적용 기준선은 322.8초 중 COM 269.1초(83%), 144,274회다. XML로 확실히 분리 가능한 판정은 항목 내어쓰기의 대상/기준 문자 오프셋, 문단 글 기반 기호·라벨·부연설명 유형, HWPX에 명시된 문자/문단/쪽 속성 조회다. docfit_core/xml_hanging_indent.py는 COM 없이 글과 폭 모델로 내어쓰기 위치 및 여백 쌍을 계산하고, formatter_indent.py의 규칙 판단도 이 계산을 호출한다.

자간 조정의 어절 분리/줄 끝 판정은 한/글 화면 조판에 의존하므로 XML 대체가 입증되지 않았다. “한 줄에 확실히 들어가는 문단” 사전 필터를 검토할 수 있으나, 현 XML 폭 모델이 글꼴 메트릭의 안전한 상계인지 확인되지 않아 현재는 적용 안전성을 보증할 수 없다. COM 서식 쓰기는 본 분석에서 대체량으로 세지 않는다.

## 1. 단계별 COM 읽기와 쓰기 구분

### XML로 결정 가능한 읽기 전용 판정 후보

1. 항목 내어쓰기 대상·기준 오프셋: xml_hanging_indent.py:151-231의 marker_end_offset/hanging_indent_offset가 텍스트로 문자 인덱스를 정하고 formatter_indent.py:41-61, 73-98가 호출한다. 조판 줄 위치와 무관하다.
2. 선행부 폭 및 쌍 계산: prefix_width_hwpunit은 문자 폭 계수·크기·장평·자간을 사용한다(xml_hanging_indent.py:120-149). hanging_indent_pair는 HWPUNIT 여백 쌍을 계산한다(234-260). HWPX 적용기에서 해당 계산을 사용한다(827-997). 단, 모델 계산이 실측 글꼴 폭과 같다고 볼 수 없다.
3. 예시 서식의 여백 쌍 조회: reference HWPX의 paraPr margin과 기호/라벨/문장 키를 이용한다(xml_hanging_indent.py:345-399, 402-439, 462-483). 중복 문장/서식 불일치의 fallback 조건을 유지해야 한다.
4. 문단 텍스트 규칙 판정: 기호·콜론 라벨·부연설명 부모 유형·공백 수·강제 엔터 여부는 XML 문단 텍스트로 계산 가능하다. 예: page_fit.py:4235-4238, formatter_indent.py:731-755. 숨은 글자/컨트롤/셀 경계에서 COM 텍스트와 일치하는지 검증 필요.
5. 명시 속성 조회: HWPX 스타일 참조로 글꼴, 크기, 장평, 자간, 문단 여백/간격, pageBreak를 조회 가능하다. 전체 스타일 상속·글꼴 대체를 반영한 유효값 해석 여부는 확인하지 못했다. 이를 최종 줄/페이지 판정으로 오인하면 안 된다.

## 2. 자간 판정의 보수적 사전 필터

spacing.py:1624-1654, 1737-1753은 줄 끝에서 분리 어절·괄호 등을 판정하고 자간 명령을 실행한다. 바깥 반복도 화면 줄 경계를 이동/조회한다(1755-1819). XML만으로 이 경계가 어디인지 알 수 없다.

전체 문단 폭의 안전한 상한이 본문 사용 가능 폭 이하일 때만 자동 줄바꿈이 없다고 보고 건너뛰는 필터는 이론적으로 가능하다. 입력에는 글자 수 자체가 아니라 문자/run별 폭, 글꼴/크기/장평/자간, 공백·구두점·탭/필드/수식/컨트롤 확장, 좌우 여백·첫 줄/내어쓰기, 쪽·단·셀 가용 폭이 필요하다. 폭 상계는 실제 폭보다 작아서는 안 되고, 가용 폭은 실제보다 커서는 안 된다.

현재 char_width_factor는 전각/반각/괄호 고정 계수(xml_hanging_indent.py:120-129)이고 prefix_width_hwpunit도 그 모델을 쓴다(131-149). 임의 글꼴의 글리프 폭, 글꼴 대체, 양쪽 정렬 공백 확장, 탭·필드·수식·개체를 안전하게 상계하는 근거가 없다. 그러므로 글자 수×평균 폭이나 이 모델만으로 필터를 켜면 안 된다. 후보는 상계가 입증된 단순 문단만 skip하고, 폭 계산 불능·복합 문단·경계 근접은 COM 검사를 계속하는 방식이다. 안전 조건이 없는 조합의 적용률은 0%여도 된다.

오판하면 실제 줄바꿈/어절 분리가 있는 문단을 skip하여 필요한 자간 변경을 놓치고 최종 표시 결과가 달라질 수 있다. 반대로 불필요한 COM 검사는 결과는 보존하고 성능만 덜 개선된다.

### ALLQA 검증

- ALLQA 전체 문서, HWPX 입력, 처리 설정, 한/글 버전을 고정하고 문단 ID별 필터 결정·이유·폭 상한·가용 폭·복합 문단 여부를 기록한다.
- 같은 버전에서 필터 off 기준 결과와 필터 on 결과를 비교한다. 별도 shadow 모드에서 필터가 skip한 모든 문단도 COM 판정을 실행하여 조정 필요 여부를 기록한다.
- 합격은 skip 중 COM 기준 자간/단어 분리 변경 필요 문단 0개, 결과 HWPX의 문단 글·문자 모양(자간/장평 포함)·문단 모양 동일, skip 집합 재현 가능으로 한다.
- 표본 검증만으로 절대 안전성을 증명할 수 없다. 적용 대상인 ALLQA 문서와 글꼴 조합을 전수 대조하고, 포함되지 않은 조합에는 필터를 적용하지 않는다. 이 검증은 Windows 한/글 환경에서 수행한다.

## 3. 후보별 예상 호출량·난이도·위험

기준선은 단계별 전체 COM 호출만 제공하며, 읽기와 쓰기 또는 함수별 귀속을 분리하지 않는다. 따라서 아래는 관련 단계 총량/상한이며 실제 절감량이 아니다.

| 1. XML 텍스트 규칙/대상 선별 후 COM 문단 판정 건너뛰기 | 내어쓰기 6,096 + 최종 재확인 6,098(기준선 19-20행), 부연설명 1,326(35행). 공백·문장부호·라벨 XML은 이미 8회(34행) | 관련 단계 상한 13,520회. 실제 읽기만 제거되는 양은 0~13,520 미확정. 기존 XML 8회는 추가 절감 아님 | 중간. XML과 COM 텍스트의 숨은 글자/표 컨트롤 차이로 대상 누락 위험 |

### 추천 순서

1. 문단 ID별 XML 판정과 현재 COM 판정을 shadow 기록한다(동작 변경 없음).
2. 내어쓰기의 텍스트 규칙/오프셋/reference 쌍을 XML 판정으로 재사용한다. 실제 속성 변경은 COM 쓰기로 남긴다.
3. 부모/기호/라벨, 명시적 쪽 설정처럼 줄 위치 비의존 판정을 확장하고, 표/컨트롤 텍스트 정합성을 확인한다.
4. 자간 필터는 안전 상계가 정의된 단순 문단부터 ALLQA 전체 shadow 검증한다. 불일치 0건 이후에만 적용 설계를 올린다.

## 4. 미확인 사항

- 작업 폴더/상위에서 .git 저장소를 찾지 못해 github/main HEAD를 확인하지 못했다. 분석은 제공된 작업 폴더 파일 기준이다.
- ALLQA 세트 구성, 한/글 버전/글꼴 설치 조합, Windows 비교 실행기는 확인하지 못했다.
- 기준선 COM 통계는 읽기/쓰기/속성 조회를 함수·문단별로 분리하지 않아 후보별 실제 감소량과 시간 절감을 산정할 수 없다.
- docfit_core/hwpx의 모든 스타일 상속, 글꼴 대체, 필드/수식/컨트롤 텍스트 해석 경로를 확인하지 못했다. 구조 검증·캔버스 편집 인프라가 전체 문서 판정 지원을 뜻하지 않는다.
- 폭 모델이 모든 글꼴에서 실제 글리프 advance의 안전한 상계인지는 입증되지 않았다. 자간 필터를 안전하다고 결론내리지 않는다.
- 요청대로 COM 실행·코드 변경·테스트는 하지 않았다.
