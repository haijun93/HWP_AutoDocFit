# UNIFIEDAPP1 — 앱 안 몽땅검색 통합 보기 (2026-11-28)

브랜치 `feature/UNIFIEDAPP1`(`feature/UNIFIED2` 기준, `feature/QMSBUG1` 병합 `16dc8687`). 앱의 몽땅검색 화면에 **통합 보기**(파일명 > 위계 > 본문, 같은 문서는 가장 높은 단에 한 번)를 넣었다. **기본값은 끔**이며 `통합 보기` 단추로 켜고 끈다. 끄면 기존 3탭 그대로다.

설치본·설치된 서비스·사용자 색인·사용자 설정·실행 중인 앱은 바꾸지 않았다. 시험은 합성 자료·임시 설정·격리 파이프만 썼다. 로컬 커밋만 하며 푸시·버전 올림·main 병합은 하지 않았다.

## 구조

```
앱 화면(Flutter) → TimemachineService(Python) → ktm.exe --search-host(JSONL 표준 입출력) → 파일명 서비스 파이프 / 본문 색인(읽기)
```

- 검색·단 배정·커서·0건 안내는 Rust가 한다. UNIFIED2의 `unified::collect`/`Session`을 그대로 쓰고 화면에서 다시 계산하지 않는다.
- 안내 문구는 QMSBUG1의 `notice.rs`를 호출해 만든다(퀵몽땅검색 창과 같은 문구).
- `ktm/src/app_host.rs`(새 파일): `start`/`page`/`cancel`/`close`. 창·설정·색인 쓰기·상주 설치 없음. 표준 입력이 닫히면 끝난다. 본문 색인은 `open_readonly`로 열어 재색인 요청을 보내지 않는다.
- `docfit_app/unified_search_host.py`(새 파일): 첫 검색 때 프로세스를 띄운다. 검색어를 비우면 세션만 놓고, 통합 보기를 끄거나 화면을 닫으면 프로세스를 끝낸다. 옛 `ktm.exe`는 모르는 인자를 받으면 단축키 창을 띄우므로, 실행 파일에 `--search-host`가 없으면 띄우지 않고 '검색 못함'을 알린다.
- 서비스 명령: `unified_view_set`·`unified_start`·`unified_poll`·`unified_page`·`unified_cancel`·`unified_release`·`unified_close`. 설정 `unified_view`(몽땅검색 `timemachine.json`, 기본 false)는 다른 설정 저장에도 유지된다.
- UNIFIED2 문서의 설계에서 달라진 점: 세션 번호 대신 세대 번호 하나를 쓴다. 증분 응답을 밀어 주는 대신 화면이 조회한다(처음 1초 30ms, 이후 200ms, 끝나면 조회 없음). 폴더 집계·자동완성은 화면에서 쓰지 않아 보내지 않는다.

## 화면 동작

- 단 머리글과 단 표시, 전체 개수(파일명·위계·본문), `이어보기`/`이전`(목록에 초점이 있으면 Ctrl+PgDn/PgUp), `취소`(Esc).
- `검색 결과가 없습니다` / `검색을 완료하지 못했습니다` / `파일명 색인을 준비하는 중입니다` / `파일명을 검색하지 못했습니다` / `검색 중…` 구분. 검색 못 한 상태에서는 "0 · 0 · 0" 개수를 적지 않는다. 일부 원천만 실패하면 확인한 결과와 사유를 함께 보인다.
- 문서 열기(더블클릭·단추)·폴더 열기·미리보기는 기존 `open`/`reveal`(조사 폴더 검사 포함)을 경로로 호출한다.
- 기간·종류 칩·적용 확장자·조사 폴더를 반영하고, 바뀌면 다시 찾는다. 검색어가 없으면 기존 기간 타임라인이 보인다.

## 앱에 붙이면서 고친 문제

| 문제 | 조치 |
|---|---|
| 본문 색인의 폴더 조건은 하위 폴더를 포함하지 않아 조사 폴더 아래 문서가 빠짐 | 본문에는 폴더 조건을 넘기지 않고 호스트에서 경로로 거름 |
| 확장자 조건은 색인 메타가 없으면 0건 | 같은 방식으로 경로에서 거름 |
| 연관 검색(`;`)의 파일명 질의는 200자 제한인데 묶음마다 폴더 경로가 붙어 '검색 못함' | 연관 검색은 폴더·확장자 조건 없이 묻고 호스트에서 거름 |
| 전수 조회 결과에는 본문 발췌가 없음 | 보이는 페이지만 발췌를 채움(클라우드 전용 파일 제외) |
| 앱이 열 수 없는 항목(`#IEeEE`, `~$`, 제외 폴더, 점 폴더, 조사 폴더 밖) | 단 배정 전에 제외해 개수와 목록이 일치 |
| 검색어를 비울 때마다 호스트를 끝내 다음 검색이 다시 처음 켜는 비용을 냄(개발 중 발견) | 세션만 해제 |
| 행의 단추가 더블클릭 감지 영역 안이라 0.3초 늦게 반응(개발 중 발견) | 영역 밖으로 이동 |

첫 두 가지와 200자 제한은 퀵몽땅검색 창의 통합 검색(`window.rs`)에도 같은 코드 경로가 있을 수 있다. **코드로만 추정했고 창에서 재현하지 않았으며 이번에는 고치지 않았다.**

## 남은 문제와 한계

- **기본값 끔. 사용자 확인 전이다.**
- **파일명 색인 서비스가 필요하다.** 전수 명령 `names_snapshot`(UNIFIED2)이 있는 새 서비스여야 한다. 설치 서비스는 교체·호출하지 않았다. 옛 서비스나 서비스 없는 PC에서는 '검색 못함'이 된다.
- **파일명 원천이 실패하면 위계·본문도 나오지 않는다**(UNIFIED2 설계: 상위 단 없이 하위 단을 확정하지 않음). 기존 3탭의 본문검색은 따로 동작한다. 서비스가 없는 PC에서는 통합 보기를 끄고 써야 한다.
- 본문은 kfind 색인만 읽는다. 기존 본문검색의 검색 엔진 설정(`legacy`/`shadow`)과 SQLite 대체 경로를 쓰지 않는다.
- 위계 전수 집합이 본문과 같은 현행 의미 때문에, 색인이 정상이면 본문 단은 대개 비고 위계 단에 모인다(UNIFIED2와 같은 별도 결정 사항).
- 화면 기본 기간이 **이번 달**이어서 통합 검색도 그 범위에서 찾는다(기존 본문검색과 같음). 전체에서 찾으려면 기간을 `전체`로 바꿔야 한다.
- 통합 보기에는 정렬 선택, 썸네일, 연관 문서 찾기, 다른 기능으로 보내기, Markdown 내보내기, 폴더 항목이 없다. 필요하면 3탭으로 돌아간다.
- 대량 색인의 전수 조회 시간·메모리, 파일명 응답 8MiB 한도, 조사 폴더가 많을 때의 시간은 확인하지 않았다.
- 배포 CI는 이 소스의 `ktm.exe`를 `resources`에 복사하므로 추가 포장 변경은 없다. 설치본으로는 확인하지 않았다. CI는 `ktm`의 `--lib` 시험만 돌려 새 프로세스 시험(`tests/app_host.rs`)은 CI에서 돌지 않는다.
