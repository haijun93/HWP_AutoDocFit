# RLEV — Rust 본문 색인 경로에서 위계 판정이 빠지는 문제 (2026-11-12)

[Claude ngaytot9 · Opus · low] 설계+구현. 브랜치 `fix/rust-index-levels`.

## 1. 현상과 원인

- PM 실측(배포 v2.2.59): md `# 제목1 / ## 장 / ### 절 / 본문`의 본문검색 경로가 `제목1` 한 단계.
- 재현(klib release 빌드, 같은 md):

| 경로 | 문단별 level(level_rank) | 경로 표시 | 위계 버전 | 재색인 대상 수 |
|---|---|---|---|---|
| Rust(klib index-content) | `# 제목1`=square(4), `## 장`=body(8), `### 절`=body(8) | 제목1 | 1 | 1(계속 남음) |
| Python(index_file) | document_title(0), chapter(1), section(2), body(8) | 제목1 > 장 > 절 | 2 | 0 |

- 원인: `docfit_app/timemachine_service.py` `_content_index_worker`가 txt·md·hwpx·docx·hwp를 klib에 넘기고, klib `index-content`(`klib/src/index_content.rs:71-89`)가 자체 분류기로 level을 정해 바로 기록한다.
- **숨은 상태 기계**: `content_meta.hierarchy_schema_version`이 "위계를 현재 규칙으로 판정했는가"의 표지인데 두 색인기가 다르게 쓴다.
  - Python: 현재 버전 2(`content_search.py:72`), 2 미만이면 다시 색인(`index_file` 캐시 검사, `needs_reindex_count`).
  - Rust: 상수 1을 기록(`index_content.rs:5,96`)하고, 1 이상이면 건너뜀(`index_content.rs:66`).
  - 결과: Rust가 쓴 문서는 영원히 버전 1 → 시작할 때마다 `needs_reindex_count>0`이라 자동 재색인이 돌지만, klib은 "skipped"로 넘겨 **고쳐지지 않는다**(오늘 넣은 규칙 버전 자동 재색인이 Rust 경로에서는 무력).

## 4. 구현 (가)

- `ContentSearchIndex.stale_hierarchy_paths(paths)`: 본문 행은 있으나 위계 버전이 현재보다 낮은 문서.
- `ContentSearchIndex.relevel_file(path)`: Rust가 쓴 문단 행(rowid 유지)에 level·level_rank를 `UPDATE`, `content_table_cells`를 다시 쓰고 위계 버전을 현재로 올린다.
  - txt·md·hwp: Python 추출 기록에도 문단 메타데이터(스타일·개요·표)가 없으므로 저장된 본문으로 바로 판정(재추출 없음).
  - hwpx·docx: Python 추출로 메타데이터를 얻고, 문단 본문 목록이 저장 행과 다르면 Python 전체 색인(`index_file`)으로 대체.
  - 판정 실패 시 Rust 본문 행은 지우지 않고 둔다(버전이 낮아 다음 색인 때 다시 시도).
- `_content_index_worker`: klib 성공 문서 중 위계 버전이 낮은 것만 재판정. 진행 수(seen·indexed)는 Rust 단계에서 이미 셈하므로 두 번 세지 않는다.
- 이미 색인된 사용자 색인: klib이 "skipped"(버전 1)로 넘긴 문서도 버전이 낮으므로 같은 단계에서 재판정된다 → 시작 시 자동 재색인이 실제로 고친다(시험 `test_old_rust_index_is_relevelled_on_next_run`).
- CI: `build-windows-exe.yml` klib 빌드 뒤 `KLIB_EXE`로 `tests.test_rlev_rust_index_levels` 실행 단계 추가.
