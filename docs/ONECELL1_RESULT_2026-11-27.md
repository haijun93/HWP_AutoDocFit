# ONECELL1 — 칸이 하나인 표를 한 번만 처리

작성: 2026-11-27 · 브랜치: `feature/ONECELL1` · 로컬 커밋만, 푸시 없음. 사용자 승인 작업(EFF5 후속 E04).

## 요약

- 「한 번에 적용」에서 한 칸 표가 두 단계(`개요·한 칸 표 자간 조정`, `표/컨트롤 자간·단어 분리 조정`)에서 방문되던 것을 한 번으로 줄였다.
- 합성 문서에서 **한 줄에 「다음 단어 당김」이 두 번 적용되는 현상을 재현**했고, 수정 뒤에는 0줄이다.
- 남은 단어 분리 수는 시험한 문서 모두에서 전후가 같다. 두 번째 방문이 첫 방문의 미해결 단어를 풀어 준 사례는 **관찰되지 않았다.**
- **결과는 달라진다.** 한 칸 표의 압축이 줄고 줄 수가 늘며, 일부 문서는 뒤의 쪽 배치 단계가 본문 줄 간격을 다르게 정한다.

## 변경

- `한칸표_자간조정`(서식 단계)이 끝까지 처리한 영역을 `한칸표_처리영역`에 기록한다.
- 바로 다음 `컨트롤_내부_자간조정` 1차 순회가 그 영역(여전히 한 칸 표일 때만)을 건너뛴다. 기록은 한 번 쓰고 비우며, 문서마다 초기화한다.
- 서식 단계가 건너뛴 영역(쪽 범위 밖·장식 표·세부 작업 꺼짐)과 중간에 멈춘 영역은 기록하지 않는다.
- `서식 적용`(서식 단계만)과 `자간 정리`(컨트롤 단계만)는 전과 같이 한 번 방문한다.

남긴 방문은 앞쪽(서식 단계)이다. 두 단계 사이의 내어쓰기·부연설명·별표 단계는 한 칸 표를 제외한다(코드 확인).

## 실제 한/글 전후 비교 (측정)

- 방식 `all`(기본 설정), 전(`8254bc93` 사본)·후 각 2회. 새 인스턴스(`DispatchEx`)만, COM 잠금 배타 생성, `.full-test.lock`이 있으면 대기, 실행에 강제 종료 시간 제한 없음. 설정·임시 폴더는 격리했고 보안 모듈 설치·레지스트리 쓰기는 호출하지 않았다.

「당김 적용」에는 본문의 당김도 포함한다(전후 같은 건수). 장평은 전후 모두 100%뿐이다(기본 설정은 장평 줄이기 끔). 장평을 켠 설정은 재지 않았다.

### 두 번 당겨진 줄 (pull_a, 14줄 전부)

값은 그 화면줄에 있는 자간(%)의 종류이고, 장평은 모두 100이다. 줄 수는 해당 문단의 전/후다.

| 위치(표·문단·줄) | 당긴 단어(서식 → 컨트롤) | 전 자간 | 후 자간 | 문단 줄 수 |
|---|---|---|---|---|
| 표1 문단2 1줄 | 시 → 개선 | -9, -6, 0 | -3, 0 | 2 / 2 |
| 표1 문단3 1줄 | 총 → 관리. | -10, -7, 0 | -3, 0 | 1 / 2 |
| 표2 문단2 1줄 | 후 → 약. | -5, -4, 0 | -1, 0 | 1 / 2 |
| 표3 문단1 1줄 | 또 → 추진 | -7, -6, 0 | -1, 0 | 2 / 2 |
| 표3 문단2 1줄 | 주민 → 시 | -9, -3, 0 | -6, 0 | 2 / 2 |
| 표4 문단1 1줄 | 관리 → 점검 | -10, -6, 0 | -4, 0 | 2 / 2 |
| 표4 문단2 1줄 | 현 → 현장 | -7, -6, 0 | -1, 0 | 2 / 2 |
| 표4 문단3 1줄 | 더 → 점검. | -9, -7, 0 | -2, 0 | 1 / 2 |
| 표5 문단1 1줄 | 점검 → 계획 | -7, -6, 0 | -1, 0 | 2 / 2 |
| 표5 문단2 1줄 | 검토 → 협력 | -8, -6, 0 | -2, 0 | 2 / 2 |
| 표5 문단3 1줄 | 현장 → 강화 | -9, -6, 0 | -3, 0 | 2 / 2 |
| 표6 문단1 1줄 | 전 → 수 | -9, -7, -3, 0 | -6, -4, 0 | 2 / 2 |
| 표6 문단2 1줄 | 지원 → 더 | -9, -3, 0 | -6, 0 | 2 / 2 |
| 표6 문단3 1줄 | 관리 → 개선 | -10, -6, 0 | -4, 0 | 2 / 2 |

누적 압축은 당김 상한(10%p) 안이었다. 어긋난 것은 「한 줄에 한 번」 규칙이다. 두 줄짜리가 되어야 할 문단이 한 줄로 눌린 곳이 위 표에 3곳 있다.

### 단어 분리 잔존·미해결

| 문서 | 남은 분리(줄 경계) 전→후 | 「미해결」 로그 전→후 | 단어 분리 통계(대상/성공/실패) 전 → 후 |
|---|---|---|---|
| pull_a, pull_b, mixed | 0 → 0 | 0 → 0 | 성공만, 대상 수 동일 |
| split | 0 → 0 | 0 → 0 | 11/11/0 → 9/9/0 |
| split2 | 0 → 0 | 0 → 0 | 12/12/0 → 11/11/0 |
| hard | 10 → 10 | 8 → 4 | 16/8/8 → 12/8/4 |

- hard: 첫 방문에서 못 푼 긴 단어 4개를 수정 전의 두 번째 방문도 **4개 모두 실패**했다. 로그 8 → 4는 같은 단어의 중복 기록이 없어진 것이다. 남은 10곳 중 1곳은 같은 단어 안에서 끊기는 위치가 2글자 다르다.
- split·split2에서 전 코드의 컨트롤 단계만 처리한 분리(예: `관리`, `공동주택관리지원`, `주민 등`)는 수정 뒤 결과에 분리로 남아 있지 않다. 두 번째 당김이 새로 만든 분리를 되풀이로 푼 것으로 판단한다(로그·결과에 근거한 추정).
- 따라서 보존용 추가 방문(당김을 끈 재검사 등)은 **적용하지 않았다.** 보존할 사례가 관찰되지 않았다.

### 한 칸 표 밖의 차이

- 여러 칸 표, 표 안 표의 안쪽 칸, 글상자: 글·글자 모양·문단 모양·줄 위치 차이 0. textbox 문서는 COM 호출 수까지 같다.
- 본문의 글·글자 모양·줄 위치 차이 0.
- **본문 문단 모양은 3개 문서에서 다르다.** 한 칸 표의 줄 수가 달라져 뒤의 `개별 문단 페이지 배치`가 다르게 판단했다.

| 문서 | 다른 본문 문단 | 차이 | 쪽 배치 결과 전 → 후 | 점수 전 → 후 |
|---|---:|---|---|---|
| pull_a | 12 | 줄 간격 160% → 180% | 미해결 1 → 성공 1 | 76.2 → 81.0 |
| pull_b | 12 | 줄 간격 200% → 190% 등 | 성공 → 성공 | 81.0 → 81.0 |
| split2 | 10 | 줄 간격 9개 160% → 180% 등, 1개는 「문단 앞 쪽 나누기」 있음 → 없음 | 성공 → 성공 | 81.0 → 81.0 |

- split 점수 79.0 → 78.6: 단어 분리 「대상」이 11 → 9로 줄어 성공률의 분모가 작아진 영향으로 판단한다(실패 증가 없음). 나머지 문서의 점수는 같다.

## 시험 중 있었던 일

합성 문서를 만들던 별도 인스턴스에서 저장 뒤 문서 닫기가 두 번 「서버에서 예외 오류」로 실패해 한/글 프로세스가 남았다. 창 제목과 생성 시점으로 이 작업이 띄운 것을 확인한 두 프로세스만 종료했다(시간 제한에 의한 종료 아님). 전후 비교 실행에서는 발생하지 않았다.

## 미확인

- 실제 사용자 문서, 다구역, 머리말·각주 안의 표, 쪽 범위 작업의 실제 한/글 실행, 장평 줄이기를 켠 설정, 2회 처리, 문단 세트 방식(알파 설정), 중단.

- 「두 번째 방문이 풀어 주던 분리가 없다」는 위 합성 문서에서의 관찰이며 증명이 아니다. 앞쪽 방문에서 미해결이 남고 뒤의 단계에서 배치가 바뀌는 문서는 다시 시도하지 않는다.
