# OUTKEYS3 결과 — 확정 전 글 보존, 처리 중 Backspace·Delete (2026-11-28)

대상: `flutter_ui/lib/features/outliner/`(앱 안 화면). `outliner_core` 의 키 규칙, 네이티브 창(`outliner_win`)은 바꾸지 않았다.
합성 자료와 가짜 엔진 위젯 시험만 썼다. 설치본·사용자 데이터·실행 중인 앱은 건드리지 않았고 푸시하지 않았다.

## 1. 입력 칸 바깥을 누르면 글이 사라지던 결함 (사실로 확인, 수정)

원인: 칸이 포커스를 잃으면 저장하지 않은 글을 다음 그리기에서 문서 글로 덮었다.

재현(수정 전, `outliner_leave_test.dart` 20건 중 19건 실패, Esc 만 통과): 본문 빈 곳, 제목, 좌우 패널 빈 곳, 도움말 아이콘, 검색 칸, 페이지 목록·최근·오늘의 일지·`[[링크]]` 칩, 새 블록, 다른 블록의 들여쓰기·접기·완료 단추, `[[` 후보 클릭, 새 창 열기, 실행 취소 단추(확정 전 글만 되돌리지 못함).

고친 동작:

- 블록 입력 칸 밖으로 나가면 남은 글을 저장한다.
- 페이지 이동, 새 페이지·이름 바꾸기·삭제·복원, 새 블록, 블록 줄 단추, 블록 검색은 **저장이 끝난 뒤** 한다.
- 저장에 실패하면 이동하지 않고 이유를 보이며 글을 칸에 남긴다. 저장하지 못한 글이 남은 채 다른 블록에서 키 명령을 누르면 그 명령 대신 저장을 다시 시도한다(덮어쓰기 방지).
- 저장 중에 더 친 글은 저장 결과가 덮지 않는다.
- 실행 취소·다시 실행 단추와 `[[` 후보 클릭은 칸을 벗어난 것으로 치지 않는다. 실행 취소는 이전 의도대로 확정 전 글만 되돌린다. Esc 동작은 그대로다.
- 문서 글이 바뀐 칸만 다시 맞춘다. 페이지를 열 때는 모든 칸을 새 문서에 맞춘다.
- OUTPANEL1 의 패널 접기·제목 단추는 그대로다(접고 펼 때 저장하지 않고 글·커서·포커스 유지). 다만 '새 창으로 열기' 단추는 칸을 벗어나는 것으로 바꿨다(화면이 바뀌므로 먼저 저장).

달라지는 점: 칸 바깥을 누르면 이제 저장 명령이 나가고 실행 취소 한 단계가 생긴다.

## 2. 처리 중의 Backspace·Delete

- 처리 중에 친 글 안에서는 이전처럼 바로 지운다.
- 그 밖에서는 Enter·Tab 과 같은 순서 예약에 넣는다(`outliner_typeahead.dart` 의 `eraseInField`).
- 글자 지우기인지 블록 합치기인지는 **앞 명령 결과의 커서 위치**로 정한다. 맨 앞 Backspace·맨 끝 Delete 면 core 의 합치기 명령, 아니면 칸에서 한 글자(이모지·결합 글자 한 덩어리, 빈 괄호 짝) 또는 선택한 글을 지운다. 칸에서 지운 결과는 칸을 벗어나거나 다음 명령 때 저장된다.
- 다른 칸 저장처럼 이 칸을 바꾸지 않는 명령 중에는 칸 안 지우기는 바로 하고, 합쳐야 하는 자리만 예약한다.
- 키를 누르고 있는 반복 입력은 예약하지 않고, **처리 중이 아닐 때도** 블록을 합치지 않는다(이전에는 반복 입력이 여러 블록을 잇달아 합칠 수 있었다). 칸 안 글자의 반복 삭제는 그대로다.

적용하지 않는 경우와 이유:

| 경우 | 이유 |
|---|---|
| 결과가 커서를 주지 않음(실행 취소·다시 실행 중 누른 Backspace·Delete) | 화면이 짐작한 자리에서 지우거나 합치면 의도하지 않은 블록이 바뀐다. 남은 예약도 버리고 알린다 |
| 명령 실패, 결과가 블록 선택, 대상 블록·페이지가 없어짐 | 누른 때의 자리를 더는 알 수 없다 |
| Shift·Ctrl·Alt 조합, 누르고 있는 반복 | 단어 삭제 위치나 반복 횟수를 결과 기준으로 안전하게 정할 수 없다 |

## 3. 바꾼 기존 시험

`outliner_typeahead_test.dart` 의 'character keys are left to the text input while busy' 1건. "친 글이 없을 때의 Backspace 는 받지 않는다"는 기대가 이번 승인 내용과 반대라서, 명령 응답 전에는 칸이 그대로인 확인은 남기고 응답 뒤의 기대값을 `['enter']`·`['ab','kcd']` 에서 `['enter','backspace']`·`['akcd']` 로 바꿨다. 같은 파일의 가짜 엔진에 합치기를 더했다. 다른 기존 시험은 바꾸지 않았다.

## 5. 남은 문제·확인하지 않은 것

- 설치본·실제 키보드·한글 IME 조합 중 Backspace 와 칸 바깥 클릭, 창 전환(Alt+Tab) 때의 저장은 확인하지 않았다.
- 아웃라이너 화면 자체가 닫히거나 앱이 종료될 때의 확정 전 글은 이번에도 저장을 보장하지 않는다.
- 기존 결함(코드로 확인, 고치지 않음): **블록 검색으로 거른 목록에서 Enter·Tab 등 키 명령을 하면 걸러진 목록의 순번을 문서 순번으로 보내** 다른 블록이 바뀔 수 있다. 이번에 추가한 저장 경로는 원래 순번을 보낸다. 우선 수정 권장.
- core 가 합치기를 거절하면(하위 블록 등) 안내가 나오지만, 뒤에 예약한 키가 있으면 안내가 바로 지워질 수 있다.
- 저장(`save`)이 거절된 경우(외부 변경 충돌)는 이번 이동만 막는다. 다시 누르면 이동하며 저장되지 않은 편집은 남지 않는다(이전과 같음).
