# MG2 몽땅검색 단축키 앱(ktm) 2차 기록 (2026-11-14)

브랜치 `feature/mongttang-search-app`. MG1 측정에서 목표에 못 미친 항목을 해결했다. 이전 실행이 Claude 5시간 한도로 끊겨, MG2-R에서 미커밋분을 검토해 마무리했다.

## MG2-5 변경
- 파일명 탭: 서비스 `names_query`(검색어 공유, 탭 바꾸면 자동 재검색). Ctrl+S로 정렬 돌림(관련도→이름→크기→날짜), 결과 줄에 크기·수정 시각, 폴더 결과는 열기=그 폴더·폴더 열기=상위 폴더
- 상태 기계 `Event::Refresh`(같은 검색어 다시 찾기, 앞 세대 결과 무효), Shift+Tab 역방향 탭
- `examples/compare.rs`: 같은 SID 색인에 mmap 직접 읽기 대 `kfind --user` 파이프, 30회 p50/p95·결과 순서 비교, 파일명 질의 지연
- 계측(`KTM_METRICS`)은 메모리에 모았다가 창이 닫힐 때 한 번 파일에 씀. 전에는 단축키 처리 안에서 파일을 열어 써서 측정 표시 시간이 90~130ms로 부풀었음(실사용은 계측이 꺼져 있어 영향 없음)
- 측정 탐침: 파일명 탭에서 파일 이름에 든 낱말("합성문서")로 결과 확인, `KTM_PROBE_SETTLE_MS`(표시 뒤 입력까지 틈)

## 남은 문제
1. 표시 직후 0ms 만에 입력하면 첫 결과가 가끔 377~586ms 늦다(3회 중 2회). 250ms 틈을 두면 3회 모두 8~10ms라 표시 직후 OS 쪽 비동기 작업(IME·TSF 붙이기로 추정) 탓으로 보이며, 원인 확정은 못 했다. 사람 손으로는 틈이 생기지만, 확정하려면 첫 입력 구간을 UI 스레드·일꾼 단계로 나눠 재야 한다
2. 서비스 파이프에서 `status`·`names_status`·`names_build`에 알 수 없는 필드(예: `id`)를 넣으면 서비스가 오류 응답 없이 연결을 끊는다(클라이언트는 "failed to fill whole buffer"). 해석 실패도 `{"ok":false}`로 돌려주도록 kfind 쪽 고칠 것
3. 실제 사용자 색인·드라이브 전체 파일명 색인(서비스 모드)에서의 측정은 아직 안 함(합성 3,000건만)
