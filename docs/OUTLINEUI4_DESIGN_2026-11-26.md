# OUTLINEUI4 구현 기준

- 선행 OUTLINEUI3 `43c40f93`의 커밋·전체 시험 통과 기록을 확인하고 fast-forward 병합했다.
- 대상: outliner_core, outliner_win. 결과는 `OUTLINEUI4_RESULT_2026-11-26.md`에 실제 출력과 함께 기록한다.
- core에 파일 접근 없는 참조 토큰·해결·표시 모델을 둔다. Win32는 같은 표시 조각으로 그리기와 클릭 위치를 계산한다.
- 상태: 참조 Found / Missing / Ambiguous, 확장 Normal / Cycle / Limit. UUID는 그래프 전체에서 유일할 때만 해결하며 임시 숫자 ID는 현재 페이지에서만 해결한다.
- `((id))`는 본문을 인라인 표시한다. `{{embed ((id))}}`, `{{embed [[page]]}}`와 기존 `(((id)))`는 읽기 전용 하위 블록 미리보기다. 조상 경로 순환과 깊이·줄·문자 한도를 적용한다.
- 원문·속성·태그·참조 ID를 표시 과정에서 바꾸지 않는다. 편집 시에는 기존 원문 EDIT를 사용한다.
- 우측에 연결 참조·미연결 언급·선택 블록 속성·태그를 표시한다. 미연결 언급 클릭은 원문 이동만 수행한다. 태그 클릭은 정확한 태그 검색이다.
- 속성 클릭/추가는 명시적 입력 상태로 들어가며 Enter 확정은 메모리 편집·실행 취소 한 단계다. 파일 저장은 기존 명시적 저장/이동 동작을 따른다.
- 검증: 두 Rust 크레이트 전체 cargo test, 관련 Python 시험, 합성 그래프의 보존·오류·순환·클릭·속성 실행 취소 시험. 설치본·설정·서비스·Flutter·사용자 원본·푸시 변경 없음.
