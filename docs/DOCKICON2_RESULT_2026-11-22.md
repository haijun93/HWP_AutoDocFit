# DOCKICON2 결과 (2026-11-22) — 독 그리기 품질을 WinRust 방식으로 보강

공개 저장소(Lemxy/WinRust)의 **방식만** 참고해 독자 구현했다(코드 복사 없음, 새 크레이트 없음, windows-sys 기능 `Win32_Graphics_GdiPlus`만 추가).

## WinRust 방식 3가지와 적용 여부

| # | WinRust 방식 | 우리 적용 | 이유 |
|---|---|---|---|
| ① | 아이콘 글꼴 글리프를 CreateFontW(CLEARTYPE_QUALITY)로 DrawTextW | **적용** (`draw_glyph`: ANTIALIASED→CLEARTYPE_QUALITY) | 글리프는 불투명 배경(알약을 먼저 칠한 메모리 DC) 위에 TRANSPARENT 모드로 그려 ClearType 번짐 문제가 없다. 캡처 확대 비교에서 글리프 둘레 색 번짐(붉은/푸른 가장자리) 픽셀 0개(밝은/어두운 × 100/125/150%). 글리프 단독 효과는 도형 교체와 분리해 측정하지 않았고, 육안으로 전후 차이는 작았다. 시스템 ClearType이 꺼져 있으면 GDI가 알아서 회색조로 그린다. |
| ② | 도형을 GDI+ 안티앨리어싱(SmoothingModeAntiAlias, PixelOffsetModeHalf, GdipAddPathArc 둥근 사각형 경로) | **적용** (`native.rs`의 `Aa`: 알약 배경+테두리, 선택 링, 실행 점) | 확대 시 알약 모서리·링·점의 계단이 사라지고 점이 정원으로 보인다. GdiplusStartup은 첫 사용 때 한 번, GdiplusShutdown은 메시지 루프 종료·캡처 종료 때 호출. 시작/그래픽스 생성 실패 시 기존 GDI(RoundRect/Ellipse)로 폴백. 구분선(수직 1px)은 정수 좌표라 계단이 없어 GDI 유지. |
| ③ | 앱 아이콘을 1024 마스터로 그린 뒤 LANCZOS 축소 | **이미 동일 계열** | `scripts/make_app_icon.py`가 변=1024 마스터를 만들고 Pillow ICO 저장이 각 크기(16~256)를 마스터에서 축소한다(고양이 배치도 LANCZOS). "4배 크게 그린 뒤 축소"와 같은 효과이며 변경 불필요. 별도 보고할 문제 없음(Pillow ICO 축소 필터를 명시 지정하진 않으므로, 작은 크기 선명도에 불만이 있으면 크기별 LANCZOS 명시 저장을 후속 검토). |

④ 아이콘 모양은 DOCKICON1과 동일(글리프 대응표·벡터 폴백 코드 무변경, 대응표 시험 통과).

## 검증 (실측)
- `dock`: `cargo test --release --locked` → `test result: ok. 15 passed; 0 failed`, 이어서 `0 passed; 0 failed` 2줄(다른 대상). 전부 ok.
- 헤드리스 캡처 `--capture-dir`(앱·독 프로세스는 건드리지 않음) 전(main 빌드)·후를 밝은/어두운 × DPI 96·120·144(=100·125·150%) 6쌍 생성, 왼쪽 모서리~첫 아이콘 구간을 3~4배 확대해 나란히 놓고 직접 열어 확인한 것은 **밝은 100%와 어두운 150%** 두 장이다. 두 장 모두 알약 모서리 계단·점찌그러짐이 사라졌다. 나머지 4쌍은 눈으로 열어 보지 않았고 수치만 확인했다(캡처 6장 모두 빈 이미지 아님: 고유 색 148~182개, 두부 글자 없음은 수치 기준으로는 확인 불가이므로 열어본 2장에서만 육안 확인).
- 시험 대상 한계: 실제 창(WM_PAINT, 호환 비트맵) 경로는 같은 `draw_dock`을 쓰지만 이번에 실행해 보지 않았다(실행 중 앱을 건드리지 않는 조건).
