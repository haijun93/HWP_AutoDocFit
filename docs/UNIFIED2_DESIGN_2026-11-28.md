# UNIFIED2 구현 계획

- 결과물: `docs/UNIFIED2_RESULT_2026-11-28.md`, 전후 각 5회 측정 자료, TODO, 로컬 커밋. 기본값 false 및 기존 검색 의미 유지. 설치·자동 실행·사용자 자료·실행 중 앱·푸시 제외.
- 상태: 첫 파일명 발행 → 전역 파일명 수집 → 위계 수집 → 본문 수집 → Ready. 실패 시 Incomplete, 취소 시 발행 중단. 새 질의·숨김 때 세션 폐기. 세대가 다른 응답은 적용 금지.
- 공통 라이브러리 세션은 세 원천의 **전수 응답**으로 최고 단을 한 번 확정한다. 기존 후보 200개 합성 API는 호환 시험용으로 유지하고 실제 통합 경로는 새 API를 사용한다.
- 파일명 첫 화면은 20개만 먼저 요청한다. 전수 조회용 `names_snapshot` 명령은 기존 명령과 분리하며 기존 서비스에서 지원하지 않으면 명시적으로 실패한다. 응답의 total과 반환 수를 검증해 잘린 응답을 전수로 오인하지 않는다.
- 전역 세션은 경로·ID 별칭을 확정하고 각 문서를 파일명 > 위계 > 본문 하나에만 둔다. 페이지마다 20/20/40개까지 표시하고 실제 표시한 수만큼 각 단의 커서를 이동한다. 작은 전체 상한에서도 건너뛰지 않는다. 마지막 페이지 이후 빈 페이지·동일 커서 재발행을 금지한다.
- 위계는 현행 본문 검색의 정렬 방식이다. 전수 집합이 본문과 같으면 본문 단은 빈다. 제목 전용 필터로 의미를 바꾸지 않는다.
- 첫 파일명 스냅샷은 전수 조회보다 먼저 발행한다. 정확도에 필요한 전수 조회 비용과 첫 표시 시간을 별도로 측정한다.
- 세션은 요청 중 일치 메타데이터 O(N)을 보유한다. 상주 캐시는 추가하지 않는다. 응답 크기 제한·시간 초과는 오류이며 조용한 후보 절단을 하지 않는다. 자원 한계는 승격 판단에 반영한다.
- 검증: 기존 시험 유지, 200 및 1,000개를 넘는 합성 일치 집합 전수 대조, 페이지 합집합·순서·최고 단·작은 상한·별칭·취소·부분 실패·4설정 조합, 변경 크레이트 cargo test, 관련 Python Ran/OK. 측정 중 빌드·시험 병행 금지.
- 2단계 앱 화면은 동일 Rust 세션 API를 호출하는 얇은 호스트를 사용한다. 세션/커서/세대/오류 및 종료 계약을 결과 문서에 구체화한다.
