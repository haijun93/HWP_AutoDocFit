# HANG1 결과 — 보고서형 TXT 장시간 처리 원인

## 판정

**13분 이후에도 멈춰 있는 결함은 재현되지 않았다.** 2026-11-24, 같은 보고서형 입력을 일괄 적용으로 처리했을 때 847.5초(14분 7.5초)에 정상 완료했다. SPDMEMO3에서 13분이 지난 시점에 멈춘 것처럼 보였던 현상은, 실제로는 완료까지 약 1분 더 걸리는 처리였다. 15분 상한에는 52.5초 여유를 두고 끝났다.

지연은 `본문 자간·단어 분리 조정` 단계의 대량 COM 호출에 집중됐다. 입력 길이를 약 절반으로 줄이면 이 단계 시간과 호출 수가 거의 절반으로 감소했다. 장 제목·항목 구조에 따른 무한 반복, TXT 변환 정체, 한/글 모달 대화상자는 관찰되지 않았다. 알고리즘 동작은 바꾸지 않았다.

## 측정 조건과 결과

- 기준 브랜치: `feature/HANG1`, `github/main`의 `1284db55`에서 시작.
- Python: 3.15.2. 한/글 COM 잠금을 잡고 문서별로 순차 실행했다. 문서별 외부 타임아웃은 900초이며 이 측정에서는 타임아웃에 도달하지 않았다.
- ALLQA 8문서를 실행하지 않고 해당 문서만 `smoke_engine_pc.py --mode all`로 실행했다. 이는 `allqa_run.py`가 호출하는 같은 엔진 경로이며, 기존 ALLQA 여섯 문서는 재실행하지 않았다.
- 입력은 저장소 원본을 외부 사본으로 복사했다. 원본과 처리 사본 모두 시작/종료 SHA-256이 같았다.

| 입력 | 문단/문자 | 전체 | 본문 자간·단어 분리 | 단계 COM 호출 | 결과 |
|---|---:|---:|---:|---:|---|
| 원본 6장 보고서 | 15 / 9,500 | 847.5초 | 792.1초 | 352,420 (COM 시간 756.2초) | 완료, 4쪽, 글 보존 |
| 앞 3장 절반 입력 | 9 / 4,784 | 420.0초 | 389.6초 | 176,278 (COM 시간 371.7초) | 완료, 3쪽, 글 보존 |

두 번째 절반 입력을 계측 훅 변경 뒤 다시 실행해 TXT 변환 시작·끝 로그도 확인했다. 변환은 약 3.2초였고 모달 창은 나오지 않았다. 총 193개 외부 창 스냅샷에서 대화상자 클래스(`#32770`) 창은 0개였다. 첫 원본 실행에서도 390개 스냅샷 중 0개였다. 관찰된 한/글 창은 작업 문서였고 한/글은 응답 상태였다.

본문 자간 단계는 입력 글자 수가 50.4%로 줄자 COM 호출 수가 50.0%, 단계 시간이 약 49%로 줄었다. 전체 입력 로그에는 자간 조정 156건 뒤 2차 검사를 생략했다고 기록되어 있다. 즉 반복 단계가 계속 되풀이된 것이 아니라, 단일 단계 안에서 많은 COM 작업을 수행한 것이다. 쪽 맞춤은 원본 14.3초(2,755 COM 호출), 절반 입력 2.5초(652회)로 주된 지연 원인이 아니었다.

## 최소 구조 이분 축소

전체 입력과 앞 3장 입력(문자량 약 1/2)을 비교했다. 두 입력 모두 900초 전에 정상 완료했으므로, “멈춤”을 재현하는 실패 입력이 없고 실패 구조의 최소 단위를 이분 탐색으로 좁힐 근거도 없다. 3장 입력에도 제목과 반복 본문이 남아 있었지만 정지하지 않았다. 현재 증거는 특정 장 제목·표·항목 기호보다 입력 글자량에 비례하는 본문 자간 COM 비용을 지지한다.

따라서 최소 정지 구조는 **확인되지 않음**이다. 합성 보고서의 15문단·9,500자는 짧은 문단 수와 달리 긴 반복 본문을 담고 있어 처리시간을 과소평가하기 쉬운 입력이었다. 13분에 사용자가 중단한 관찰과 14분대 정상 완료를 구분해야 한다.

## 구현과 회귀 확인

- `scripts/hang1_repro_pc.py`: 문서별 최대 900초 실행, 엔진 자식 프로세스와 실행 전후 한/글 PID를 구분, 주기별 보이는 한/글 창·대화상자 정보를 JSONL로 남기고 시간 초과 시 해당 실행이 새로 띄운 프로세스만 정리한다.
- `scripts/smoke_engine_pc.py`: 단계 진입·종료·예외를 실행 중 JSONL에 즉시 기록한다.
- `docfit_engine/pipeline.py`: TXT/MD 등 외부 문서 변환도 시작·종료·예외 훅으로 계측한다.
- `tests/fixtures/allqa_report_synthetic.txt`와 `allqa_tables24_synthetic.txt`: SPDMEMO3 커밋 `808767e3`의 바이트 및 SHA-256을 보존했다. HANG1에서는 보고서형 입력만 한/글로 처리했고 표 24개 입력은 COM 측정하지 않았다.
- `tests/test_hang1_repro.py`: 원본 픽스처 지문·구조, 15분 타임아웃 상한, 미완료 단계 판정, timeout 정리 명령 구성을 확인한다(5개 통과).

전체 `python -m unittest discover -s tests`는 **3,583개 실행, OK, 28개 건너뜀(861.718초)**이었다. 종료 시 기존 `tests/__init__.py` 샌드박스 정리 콜백이 잠긴 SQLite 파일 때문에 `PermissionError`를 출력했으나 unittest 결과는 OK였다. 이 정리 경고는 HANG1 회귀시험에서 발생한 것이 아니다.

최종 절반 입력 재현은 900초 제한을 설정한 채 완료했고 타임아웃 경로 자체는 발동하지 않았다. 별도 회귀 단위시험 5개도 통과했다.

## 중단 및 미확인 사항

초기 축소 파일 생성에서 줄 경계를 잘못 잡은 두 실행은 반쪽 입력이 아님을 발견해 각각 약 66초와 21초 후 중단했다. 실행이 새로 띄운 한/글 PID와 Python 작업 프로세스를 종료하고 잠금 파일이 제거된 것을 확인했다. 이 두 실행은 측정치에 포함하지 않았다.

SPDMEMO3의 기존 3회 실행 당시 대기 화면·프로세스 기록은 없어 과거 시점에 실제 대화상자나 특정 루프가 있었는지는 확인할 수 없다. 이번 환경에서는 동일 입력이 약 14분 만에 정상 완료했다. 전체 8건 ALLQA 재실행, 표 24개 입력의 COM 처리, 900초 타임아웃 강제 종료 경로의 COM 실측은 하지 않았다.
