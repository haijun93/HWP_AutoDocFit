### 1.2 kagent·kvf 이식(동작·화면 차이 0)
- kagent `frame.rs` 삭제 → `ui_core::frame`. kvf의 `#[path = "../../kagent/src/frame.rs"]`도 삭제.
- popup: 이중 버퍼·글꼴(그릴 때마다 6개 생성 → 캐시)·색 상수(→`ClipPalette::LIGHT`)·탭 배치·목록 이동·메뉴 만들기·IME 읽기·틀 메시지·창 만들기를 ui-core로. 머리 단추 실행은 `run_head_button` 한 곳(마우스·접근성 공통).
- kvf: 이중 버퍼·글꼴·색·배치(`place`)·목록 이동·메뉴(상자·항목)·IME를 ui-core로.
- `settings_menu::Entry` = `ui_core::menu::Entry`(재노출).
- **새로 생긴 동작**(화면 픽셀은 같음): `WM_DPICHANGED` 다시 배치(popup·kvf 모두 없었음), UIA 접근성(popup: 머리 단추 7·분류 8·찾기 칸·목록 항목, kvf: 머리 단추 4·상자 고르기·영역 탭 5·찾기·항목). Per-Monitor v2 켜기는 `ui_core::dpi::enable_per_monitor_v2`(같은 API 호출).
- **화면 차이 0 확인(그리기 기록 비교)**: 기준선 커밋 8a356bf9에서 popup 10상태·kvf 7상태 픽셀 해시를 뽑고(두 번 실행해 같음), 이식 후 같은 시험이 **17/17 같은 해시**. 시험 `golden_render_matches_before_ui0`(`--ignored`, 이 PC 96 DPI·ClearType 값이라 다른 PC에서는 다를 수 있음).
- 일부러 이식하지 않은 것(픽셀이 바뀌므로 UI1에서): 스크롤 막대 표시, 다크·고대비 팔레트 연결, `LineEdit` 커서 이동·붙여넣기(지금 ←→는 분류 이동에 쓰임).

## 2. 다음 단계 원칙(모든 UI 카드 공통)
- 화면마다 **순수 상태 기계**(상태 이름·전이표·불가능한 전이)를 먼저 적고 시험한다(TEAM_OPERATING_RULES 0절). Win32 쪽은 `event → step → effect` 한 곳(kvf `window.rs` 방식).
- **동등성 표**(계획 7.5): Flutter 화면의 기능·대화상자 목록을 먼저 만들고 Rust에서 1:1로 표시, 빠진 것 0.
- **접근성**: `a11y::unnamed(nodes)` 빈 이름 0, 모든 단추 Invoke·목록/탭 항목 SelectionItem. 내레이터 주요 흐름 1회.
- **테마**: 라이트·다크·고대비 세 가지 그리기 해시를 기록(probe). 다크 AA는 `theme` 시험이 지킨다.
- **배율**: `WM_DPICHANGED` 처리, 100/125/150/200% 배치 시험.
- 화면 스레드에서 막는 호출 0(DB·파일·파이프는 작업 스레드 → `PostMessageW(WM_APP+n)`).
- 프로세스(Q17): kagent(상주) = 몽땅클립보드 빠른 목록·관리창(S18)·업무자료함(S10)·타임머신(S12)·가상 폴더(kvf 합침). 그 밖의 화면은 새 `docfit.exe`(필요할 때 시작, COM 작업자와 함께).
- 측정 1회(창 표시 ms·쉴 때 개인 메모리·exe 크기)를 카드 보고에 남긴다. 측정 중 다른 빌드·시험 금지.
- A안: 중간 관문 없음. 다만 Flutter 쪽 화면 삭제는 UI10(전 화면 이식 후 한 번에).

## 4. 남은 문제
- UIA는 COM 수준 시험과 창 메시지 시험까지 했다. **내레이터·Accessibility Insights로 실기 확인은 하지 않았다**(UI1 카드에서 1회).
- 다크·고대비는 부품(`theme`·`ClipPalette::for_mode`)까지만. popup·kvf 화면 연결은 픽셀이 바뀌므로 UI1.
- `WM_DPICHANGED`는 제안 사각형 적용까지 시험했고, 실제 두 모니터(다른 배율) 사이 끌기는 확인하지 않았다.
- 기준 해시는 이 PC(96 DPI·ClearType) 값이다. 다른 PC에서 `--ignored` 시험은 값이 다를 수 있다.
- kvf 창 첫 표시 때 클라이언트가 창보다 14px 작게 그려지는 기존 동작(생성 시 WM_NCCALCSIZE가 wParam=FALSE로 와서 틀이 남음, 해시 상태 `list`의 586×406)은 화면 차이 0 원칙으로 그대로 두었다. UI2에서 `window::create`(SWP_FRAMECHANGED)로 바꾸면 고쳐진다.
