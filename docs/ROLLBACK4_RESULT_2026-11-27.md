# ROLLBACK4 — 되살린 쪽 나눔을 고려한 문단 배치

작성: 2026-11-27 · 브랜치: `feature/ROLLBACK4`(feature/ROLLBACK3에서 분기) · 로컬 커밋만, 푸시 없음.

## 문제와 수정

문단 페이지 배치가 앞 문단 줄간격을 넓혀(또는 쪽 나눔을 넣어) 묶음을 뒤로 밀 때, 뒤에 있는 원래 쪽 나눔을 보지 않아 그 앞에 짧은 쪽이 새로 생겼다.

| 경로 | 수정 |
|---|---|
| `_묶음_같은쪽_이동`의 줄간격 확대 | 한 단계 넓힐 때마다 다음 강제 쪽 나눔 문단의 쪽을 다시 잰다. 뒤로 밀렸으면(재지 못해도) 확대를 그만두고 ROLLBACK2의 원복·확인(`confirm_line_spacing`)으로 되돌린다 |
| `_묶음_쪽나눔_이동` | 넣은 쪽 나눔 때문에 같은 확인이 실패하면 기존 `_쪽나눔_원복`으로 되돌린다 |

- 두 방법이 모두 안 되면 기존 '실패' 경로를 타서 `[문장 묶음 페이지 분리]`·`[소제목 묶음 쪽 분리]` 등 검수 항목이 남는다. 로그에는 `뒤쪽 쪽 나눔 앞이 넘쳐 … 취소`가 찍힌다.
- 원래 쪽 나눔은 건드리지 않는다. 줄간격 축소(당김) 방향은 바꾸지 않았다.
- 확대를 더 작은 폭으로 제한하지는 않았다. 묶음이 옮겨지지 않은 중간 단계의 확대는 남길 이유가 없어 전부 되돌린다.
- 강제 쪽 나눔 위치: '문단 앞에서 쪽 나눔'은 지금 문서에서, Ctrl+Enter는 저장된 HWPX에서 읽는다(표 위치·문단 수가 같을 때만).
- 상태: `배치_강제쪽나눔`(None=조사 전 / 문단 번호 집합). `세트문장_같은쪽_전체_적용`이 시작할 때 None으로 돌리고, 처음 필요할 때 조사하며, `쪽나눔_설정`이 함께 고친다. 중단된 조사는 저장하지 않는다.
- 뒤에 쪽 나눔이 없으면 추가 확인을 하지 않는다. 위치 조사를 위한 문서 끝 이동과 읽기(문단 수만큼)가 실행마다 한 번 늘어난다. 걸리는 시간은 재지 않았다.

## 실제 한/글 전후 비교(합성 문서)

COM 잠금을 배타 생성하고 DispatchEx 새 인스턴스(창 숨김)만 사용했으며 끝나면 종료했다(15:32~15:47, 최종 코드). 수정 전은 HEAD(ROLLBACK3) 사본, 수정 후는 작업 폴더다. ROLLBACK3과 같은 방식으로, 엔진 함수를 파이프라인의 세로 배치 순서로 불렀고 원본 쪽 수 1을 지정했다. 파이프라인 전체나 EXE를 실행한 것은 아니다. 실행은 하네스의 백그라운드 실행(상한 2시간)이었고 상한에 걸리지 않았다.

### ROLLBACK3 합성 6종

'변경'은 처음 문서와 줄간격·문단 간격이 다른 문단 수, '미해결'은 문단 페이지 배치 첫 회에서 배치하지 못한 묶음 수다.

| 문서(문단 수, 처음 쪽 수, 쪽 나눔) | 최종 쪽 수 전 → 후 | 변경 문단 전 → 후 | 미해결 전 → 후 | 검수 항목 전 → 후 |
|---|---|---|---|---|
| 경계에 1곳(103, 4쪽, 19) | 4 → 4 | 0 → 0 | 0 → 0 | 1 → 1 |
| 묶음 중간 2곳(109, 5쪽, 14·62) | 5 → 5 | 58 → 58 | 4 → 4 | 11 → 11 |
| **뒤쪽 1곳(91, 3쪽, 70)** | **4 → 3** | **67 → 0** | **0 → 2** | 3 → 7 |
| 묶음 중간 1곳(103, 4쪽, 33) | 4 → 4 | 61 → 61 | 2 → 2 | 7 → 7 |
| Ctrl+Enter 19 + 문단 앞 40(103, 4쪽) | 4 → 4 | 33 → 33 | 0 → 0 | 3 → 3 |
| 5줄 넘침(46, 2쪽, 22) | 2 → 2 | 0 → 0 | 0 → 0 | 1 → 1 |

- 추가 문서 Ctrl+Enter만 뒤쪽(91, 3쪽, 70): 최종 4 → **3**쪽, 변경 67 → 0, 미해결 0 → 2, 검수 1 → 3.
- 모든 문서에서 쪽 나눔(문단 앞·Ctrl+Enter)은 전후 모두 저장본에 남았다.
- 수정 후 최종 쪽 수는 위 7개 문서 모두 처음 쪽 수와 같다.
- 뒤쪽 1곳: 쪽별 문단 수 33·33·4·21 → 35·35·21(처음 상태). 늘어난 검수 4건은 `□ 추진 항목 12 개요`의 소제목 묶음 2건·문장 묶음 2건이다(문단 배치를 두 번 해 두 번씩 기록).
- 5개 문서는 `section0.xml`·`header.xml`이 바이트까지 같다. 묶음 중간 1곳은 문단별 실효 문단 모양·글·쪽 위치가 모두 같고, 문단 모양 번호 매김만 30문단에서 다르다(중간 확대 시도가 29회 → 9회로 줄었다).

## 확인하지 않은 것

- 실제 문서, 표·여러 보고서·여러 구역 문서, 다른 한/글 판, 설치본·EXE, 파이프라인 전체 실행, 처리 시간.
- 표 묶음·중제목 경로의 실제 한/글 실행(같은 두 함수를 거치지만 합성 문서에 표가 없다).
- 원복 실패는 이번에 따로 만들지 않았다(원복 함수는 ROLLBACK2의 것을 그대로 쓴다).

## 남은 문제

- HWPX가 아닌 문서(.hwp 등)로 열었거나, 처리 중 문단 수·표 위치가 저장본과 달라지면 Ctrl+Enter 쪽 나눔은 찾지 못해 예전처럼 확대한다. '문단 앞에서 쪽 나눔'은 영향 없다.
- 구역 나눔처럼 쪽 나눔이 아닌 이유로 새 쪽이 시작하는 경계는 보지 않는다.
- 확대로 밀지 못한 묶음은 쪽에 걸친 채 남는다(검수에 기록). 앞 구간에서 일부 문단만 넓히는 식의 다른 배치는 시도하지 않는다.
- 묶음 가운데 원본 쪽 나눔이 있으면 미해결 검수가 남고, 같은 항목이 재확인 때 반복 기록된다(수정 전과 같음).
