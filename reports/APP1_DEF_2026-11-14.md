## APP1-F

- `_search_engine()` 기본 kfind, 명시적 legacy에서는 클라이언트 연결/동기화 호출 0회. 설정 파일에서 kfind/legacy/shadow를 보존한다.
- content_search와 검색어 기반 related_search를 kfind로 연결. 관련 문서(path 기반)·파일명 검색은 기존 경로다.
- 서비스 없음/권한/판 불일치/질의 오류/원문 위치 불일치/세대 변경 시 legacy 자동 대체. 응답 및 content_status에 engine, requested_engine, engine_reason, connection, corpus를 함께 준다.
- 코퍼스 상태: pending → seeding → synced, 실패 → failed, 취소/새 변경 → pending. synced 전에는 legacy. 서비스 세대 변경을 발견하면 다시 seeding한다. legacy 설정일 때 seeding 진입을 막는다.
- index_file/relevel_file/remove_file 뒤 `_kfind_sync` 대기열. 백그라운드 작업 `phase=kfind_seeding`, 기존 취소/종료 관리에 포함. SQLite에서 원문·위계·파일 정보를 읽어 전송하고 kfind_gen/kfind_level_rule을 기록한다. 같은 세대의 변경 대기열은 해당 문서만 전송한다.
- 현재 조사 폴더를 적용한 뒤 정렬/offset/limit. mentions는 top=0의 전체 순위를 문장 수로 정렬. 확장자 그룹 필터 보존. near(~N)는 기존 의미 보존을 위해 legacy로 처리하고 사유 표시.
- shadow는 legacy 결과를 돌려주고 해시·양쪽 수·경로 순서 동일 여부만 1MiB 순환 로그에 기록. E1~E8 정밀 분류는 APP1-J 후속 범위.
- §12의 기본 켬은 `ktm.exe` 단축키 앱이다. 타임라인 감시의 `enabled`와 다른 설정이다. 이 저장소에는 ktm 코드가 없고 isearch는 읽기 전용이므로 ktm 설정은 변경하지 않았다. 타임라인 감시 기본값 변경으로 생긴 기존 시험 4건 실패는 잘못된 적용을 되돌려 해결했다.
