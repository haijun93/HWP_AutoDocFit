## 구현
- 상태 6개: none(없음), connecting(연결 중), connected(연결됨), disconnected(끊김), retry(재시도), refused(거부). TRANSITIONS에 허용 전이를 선언하고 나머지는 거절.
- none→connecting→connected/disconnected/refused, connected→disconnected/refused, disconnected/refused→retry→connecting, 모든 상태→none. 요청 시 최초 5초·후속 30초 재시도. close·재연결 이전 응답은 epoch로 배제.
- status에서 format=3·fold_rule=1·sentence_rule=1·ready 확인 후 질의. Rust Find의 text·id·scope·sources·split·filters, ok/result 봉투, little-endian u32 길이 프레임 사용. 명령마다 별도 연결.
- ingest: JSON 65,536바이트 이하·최대 4,096조각·본문 64MiB. 긴 문단을 같은 p/lv로 분할하여 서비스 merge_paras에서 원문 복구. 조각 실패 시 중단.
- 취소는 별도 연결로 동시 전송. 연결 확인 포함 기본 왕복 한도 2초. Windows CancelSynchronousIo로 동기 대기 중단. pipe busy(231)는 최대 2초 대기. 종료하지 않는 주입 opener의 daemon worker는 최대 16개 제한.
- APP1-F/I 호출자에서 기본 engine=kfind·오류 때 legacy 대체·명시적 legacy 되돌리기를 연결해야 한다. 이 카드는 전송 경계만 구현하며 shadow 전환 대기 없음.
