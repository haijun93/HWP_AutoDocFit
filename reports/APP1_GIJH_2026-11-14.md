## 구현

- G: `LibraryKfindSync`는 상자 파일·메모를 `box:<id>`에, `NotebookKfindSync`는 NBIDX1 공개 출처/문단 API의 사본만 `nb:<id>`·출처 범위에 동기화한다. 조사 폴더 밖 파일·경로 없는 메모도 포함한다. 자료별 키로 타임머신/다른 상자의 삭제와 격리한다.
- 동기화 상태는 pending → seeding → synced, 오류 → failed, 변경 → pending. 세대 변경 시 재전송하고, 이전 앱 세션의 삭제된 자료도 서비스 범위 목록에서 찾아 제거한다. 추출 실패 문서는 기존 kfind 사본부터 제거한다. 검색 오류는 legacy와 사유를 반환한다. legacy 설정에서는 새 엔진을 연결하지 않는다.
- I: 공통 설정 `search_engine=kfind|legacy`, 기본 kfind. 설정 화면·저장 검증·타임머신과 가상 폴더 공급자 연결. `content_status.search_engine_status`에 연결·코퍼스·전환 상태를 묶고 화면에 표시한다.
- J: `tools/app1_equivalence.py`, 시험 전용 Python 기준 구현과 라이선스, 단위 시험, 첫 JSON/Markdown 보고. 격리된 `.test.` 파이프와 빈 시험 서비스만 사용한다. 입력은 임시 사본으로 복제한다.
- H: 기본 가상 폴더 화면은 타임머신 결과를 Dart 경로로 거르는 대신 library 서버의 상자 범위 검색을 요청한다. 서버가 자료 ID를 돌려줘 경로 없는 메모도 표시한다. query와 count의 엔진·세대가 같은 경우에만 count를 채택한다. legacy는 서버에서 자료 ID를 보완하며, 정확한 전체 개수를 제공하지 않으므로 배지는 ‘표시 n개’로 구분한다.

## 재개 중 발견·수정

- 설정 공급자를 주입해도 connector 주입 때문에 kfind 분기를 건너뛰던 조건: 초기 Python 관련 89개 중 오류 4개. 명시적 설정 공급자도 새 분기를 활성화하도록 수정.
- Gemini가 추가한 화면 시험의 필수 `boxId` 누락·위젯 키 오류를 수정. 기존 시험은 삭제하거나 기준을 낮추지 않았다.
- 같은 이름의 메모도 결과의 자료 ID로 열고 강조하도록 보완. 새 시험은 기존 메모 편집기를 여는 흐름에 맞춰 검증한다(첫 시험 작성 때 AlertDialog를 예상한 부분은 시험을 수정했다).
- legacy 응답에 자료 ID가 없어 카드가 사라지는 문제, legacy 선택을 ‘자동 대체’로 표시하는 문제 보완.
- NBIDX1 `original_mtime`은 밀리초, klib 메모 `created_at`은 초임을 각 소스에서 확인해 구분. 날짜 필터용 `ref_date`도 전달.
- 동등성 도구의 첫 실행은 Windows 원문 경로와 정규화된 doc_key를 서로 다른 문서로 비교했다. 경로를 문서 키에 대응시킨 뒤 비교하며, 임시 루트의 원래/소문자 표기를 모두 보고서에서 제거한다. 집합 순회도 정렬해 출력 순서를 고정했다.
- 상자 삭제 후 `box_get`이 실패해 사본이 남지 않도록, `drop_scope`가 서비스의 범위 목록으로 삭제한다. 앱 재시작 뒤 삭제 및 다른 상자 보존을 검증했다.

## 시험 환경과 실패 이력

실제 볼륨 조회 결과 G: FAT32, E: exFAT, C: NTFS. 요청한 E: 작업 트리를 만들었으나 E:에서 NTFS junction 생성은 `Incorrect function`으로 실패했다. 따라서 같은 기능 브랜치의 별도 작업 트리 `C:/HWP_AUTODOCFIT/app1-ntfs`와 NTFS TEMP/TMP를 사용한다. PC 경로를 시험 코드에 넣지 않았다.

전체 시험은 `.full-test.lock`과 `.com-test.lock`을 `CreateNew`로 독점 생성한 뒤 실행한다. 첫 실행은 기존 `SyntaxWarning`을 PowerShell `ErrorAction=Stop`이 종료 오류로 처리해 시험 집계를 얻지 못했다. 다음 실행은 `Start-Process`의 stdout/stderr 파일 리디렉션으로 바꿨다. 시험 기준을 변경하지 않았다.

초기 Rust 시험 서비스 빌드는 GNU `dlltool` PATH 누락, 이어 MSVC의 잘못된 `link.exe` 선택으로 실패했다. 기존 DocFitTools/mingw64/bin을 해당 빌드 프로세스 PATH에 추가해 GNU 빌드를 완료했다. 앱 저장소의 Rust 코드는 변경하지 않았다.
