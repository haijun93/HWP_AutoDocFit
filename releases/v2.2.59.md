# v2.2.59

## 바뀐 점
- **검색 결과에 문서 안 위치(상위 경로)를 보여 줍니다**: 타임머신의 위계검색·본문검색 결과마다 `문서 제목 > 장 > 절 > 항` 경로를 한 줄로 표시합니다. 찾은 문장이 문서의 어느 부분에 있는지 열어 보지 않고 알 수 있습니다.
- **같은 절에서 여러 곳이 걸리면 묶어서 알려 줍니다**: 본문검색 결과에 「절 제목」에서 N곳이라고 표시합니다.
- **제목과 본문에 나뉜 검색어도 찾습니다**: 예를 들어 「관광안내판 해체공사」에서 '관광안내판'은 절 제목에만, '해체공사'는 그 아래 본문에만 있어도 그 본문을 찾아 줍니다. 한 문단에 다 들어 있는 결과가 먼저 나옵니다.
- **한/글 보고서의 제목 표를 문서 제목으로 인식합니다**: 문서 맨 앞 제목 표의 글을 가장 높은 위계로 쳐서, 제목에 검색어가 있는 문서가 위에 나옵니다.
- **위계 판정 보강**: Markdown 제목(`#`~`####`), Word 제목 1~3 스타일, 글머리표 없이 번호만 있는 제목(`제1장`, `Ⅰ.`, `1.`, `가.`이 순서대로 이어질 때)을 장·절·항으로 인식합니다. 텍스트 문서의 `제목1:` 줄도 문서 제목으로 봅니다.
- **업데이트 뒤 첫 실행 때 본문 색인을 배경에서 자동으로 다시 만듭니다.** 다시 만드는 동안에도 예전 색인으로 검색이 되고, 끝나면 새 제목·위계 판정이 반영됩니다.
- **자동 재색인이 화면에 보입니다**: 색인이 배경에서 다시 만들어지는 동안 타임머신 화면에 진행 표시가 켜집니다. 색인이 오류로 끝나면 "완료"가 아니라 실패와 사유로 기록합니다.
- **화면 응답 개선**: 설정·상태를 읽는 화면 요청 18곳이 내부 대기(숨은 창 왕복) 없이 바로 처리됩니다. 같은 요청 묶음에서 내부 왕복이 703회에서 150회로 줄었고, 설정 조회 응답 중앙값이 31.6ms에서 2.3ms가 됐습니다. 응답을 끝없이 기다리던 명령 13곳은 5초 안에 시작하지 못하면 오류로 알려 줍니다.

## 알려진 문제
- 제목과 본문에 나뉜 검색어를 찾는 기능 때문에 위계검색 응답이 약 13% 느려졌습니다(합성 색인 300문서 기준 118ms → 133ms).
- PDF 문서는 제목 정보가 없어 위계를 구분하지 못하고 모두 본문으로 봅니다. HWP(구형) 문서의 위계 판정은 이번에 확인하지 못했습니다.

## 재연 시험
- 자동 시험: Python 전체 시험과 타임머신 화면 시험 통과(CI 결과 참조).
- 합성 문서 180개로 잰 상위 경로 정확도: 100%(이전 0%). 제목 표 규칙을 바꾸기 전에 잰 값입니다(`docs/benchmarks/위계검색_품질_기준선_2026-11-12.md`).
- 실제 화면에서의 표시와 실제 업무 문서 색인으로 한 확인은 하지 않았습니다.
- 화면 응답 개선은 앱 창을 띄우지 않고 내부 창 루프만으로 잰 값이며, 실제 화면에서의 체감은 확인하지 않았습니다.
