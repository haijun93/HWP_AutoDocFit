# v2.2.101

## 바뀐 점
- 내부(기본 동작 불변): **몽땅검색 연관 검색어 `;`**. `2026; 공사 계약`처럼 `;`로 나눈 묶음마다 같은 문장 안에서 모든 낱말이 있는지 찾고, 묶음별 결과를 문서 단위로 교집합합니다. 순위는 최고 위계, 묶음별 일치 문단 수 합, 경로 순입니다. 공통 검색 backend(SQLite·Rust)에서 같은 뜻으로 동작하고 응답에는 묶음별 근거(`group_matches`)가 추가됩니다. 단축키 창(ktm)에서는 설정 `related_queries`를 켜면 질의 칩과 묶음별 색으로 보입니다(기본 꺼짐). `&`는 일반 문자로 처리하고 근접 검색은 아직 없습니다. 합성 1천 문서에서 SQLite와 Rust의 결과 집합·순서·근거가 48개 조합 모두 같았고, 5천 문서 질의 중앙값은 10~26ms였습니다.
  - 파일명 연관 검색은 별도 명령(`names_related`)이라 같은 소스로 빌드한 색인 서비스가 필요합니다. 설치된 서비스는 이전 `kfind.exe`를 계속 실행하므로 적용하려면 관리자 권한으로 서비스를 다시 시작해야 합니다.
  - 새 연관 자료는 색인 판을 올려, 이미 색인된 문서는 다음 색인 요청에서 자동으로 다시 채웁니다.

## 알려진 문제
- v2.2.86~v2.2.100 노트의 '알려진 문제'가 그대로 남아 있습니다.
- 연관 검색어는 합성 문서로만 확인했습니다. 실제 한글 문서·설치본에서의 화면과 순위는 확인하지 못했습니다.
- Rust 검색엔진은 여전히 기본 전환 전 단계입니다(실제 한글 문서·스캔 PDF·설치본 시험 전).

## 재연 시험
